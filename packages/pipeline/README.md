# pipeline(作問パイプライン)

問題を、品質と費用を管理しながら作るための道具です。判断の理由は、`docs/app/adr/` の ADR 0005〜0011 にあります。

問題を作る手順(収集から書き出し、PR を出すときの確認まで)は、[問題を作る手順書](../../docs/question-production.md)にあります。
出典と権利の扱いは、[出典と権利の方針](../../docs/source-policy.md)に従います。

## 境界

- `packages/app` の内部は import しません。共有するのは契約(データの仕様、スキーマと検査、出典に許すドメインの一覧)だけです。
- 公開した問題の正は `data/` です。pipeline は、書き出し(`export`)の段階だけ、作業ツリーの `data/` に追加の分を書きます。ほかの段階は読み取るだけです。取り込みは、その差分を通常の PR で確かめて行います(ADR 0014)。
- 一次情報の本文はコミットしません。台帳には、リンク、取得日、本文のハッシュ、言い換えだけを持ちます。

## 実行方法

ルートから実行します。

```sh
npm run pipeline -- --help
npm run typecheck -w @mokumoku-exams/pipeline
npm test -w @mokumoku-exams/pipeline
```

## コマンドと設定

- コマンドは段階ごとにあります(`collect` `facts` `plan` `draft` `verify` `export`)と、状態を表示する `status` です。解説は `draft` で書きます(ADR 0013)。
  どれも実装済みです。実装していないコマンドを足したときは、「未実装」を標準エラーに出し、終了コード 2(入力の誤り)で終わります(`--help` は 0)。
  - `collect`: 一次情報の収集と台帳。手順は [一次情報の収集と台帳の運用](../../docs/source-collection.md)
  - `collect <資格コード> --candidates` / `--import-candidates`: 出題範囲の項目ごとに、公式の文書を出典の候補として挙げる(依頼 → エージェント `source-scout` → 取り込み)。候補は提案で、計画には自動で入らない。手順は [一次情報の収集と台帳の運用](../../docs/source-collection.md)
  - `facts`: 出典から事実カードを作る。手順は [事実カードの作法と運用手順](../../docs/fact-cards.md)
  - `plan`: 分野の配点から目標の問題数を出し、既存の問題との差を計画にする。手順は [出題計画と下書きの手順](../../docs/drafting.md)
  - `draft`: 計画と事実カードから、選択式と自由記述の問題の下書きを作る(依頼 → エージェント → `--import` → `--check` → 人の確認 `--review`・`--decide`)。依頼は `--domain=<分野のコード>` で 1 分野に絞れる。
    手順は [出題計画と下書きの手順](../../docs/drafting.md)、作り方の決まりは [作問のスタイルガイド](../../docs/question-style.md)
  - `verify`: 下書きを、根拠にした出典の節だけから検証する(依頼 → エージェント `question-verifier` → `--import`)。選択肢ごとの正誤の再導出と、解説の確認。手順は [出題計画と下書きの手順](../../docs/drafting.md) の「検証」
  - `status`: 段階ごとの状態を表示する。依頼待ち・取り込み待ち・通過・保留・不採用・書き出し済みの件数、理由コードごとの件数、再検証の印、計画の項目ごとの未達の理由、役のモデルと定義のハッシュ、依頼待ちの件数 × 役のモデルの見積もり。読むだけで、何も書かない。`pipeline-run` スキルが、止まったときに人に見せる
  - `eval`: 検証役の見落としと誤検出を測る(人が承認した下書きから評価用のデータを作り、検証と同じ形の依頼 → エージェント → `--import`)。指標と目標は [検証役の評価](../../docs/evaluation.md)
  - `score`: 公開している選択式の問題を、書き方の点数票(問題ごと・束)で採点する。読むだけで、何も書かない。出力は問題の ID・項目の ID・点数・割合・字数・件数だけで、本文は出さない。帯は資格ごとに持つ([資格ごとの出題スタイル](../../docs/exam-style/README.md))
  - `reasons`: 不採用と差し戻しの理由を、理由コード・論点・段階ごとに集計し、下書きの指示の改善に使える形で書く(元の記録は変えず、作業用の置き場に集計を書く)。手順は [出題計画と下書きの手順](../../docs/drafting.md) の「理由の集計」
  - `export`: 人が承認し(抜き取りで確認しないと記録したものは、記録で代える)、検証と来歴の検査を通った下書きを、`data/questions.<コード>.json` に追加する。手順は [出題計画と下書きの手順](../../docs/drafting.md) の「書き出し」
- どのコマンドも `--help` と `--dry-run` を受け付けます。`--dry-run` では、書き込みと外部への通信をしません。
- 設定は `pipeline.config.json`(コミットする、環境値を含まない)に書きます。環境値は `packages/pipeline/.env`(gitignore)に書き、
  `.env.example` にはプレースホルダーだけを置きます。環境値は、設定ファイルの値を上書きします。
- 終了コード: 0 成功 / 1 検査の失敗 / 2 入力の誤り / 3 内部の誤り。失敗を報告したときは、0 で終わらせません(止めた出典・確認できない出典、
  本文がない出典、再試行の上限、件数の上限など)。試験ガイドと資格マスタの差分、カバレッジの抜けは、確かめてほしい情報として報告し、0 で終わります。
- 共通部品(`src/shared/`): 依頼 → 取り込みの流れ(依頼の一覧、失敗の回数、`request-stale`、後始末。`request-flow.ts`)、
  資格コードの検査と資格マスタの読み込み(`exam.ts`)、書き出し(`fs.ts`)、項目のパスだけを持つ誤りの基底(`errors.ts`)、
  文字の 2 つ組の類似度(`similarity.ts`)、本文の写しの検出(`copy.ts`。試験ガイド・事実カード・下書きが同じ関数を使う)、エージェントの定義の読み込み(`agents.ts`)。段階ごとに違う検査は、各段階に残します。
- エージェントの定義: 役(`guide-extractor` `fact-extractor` `question-drafter` `question-verifier` `source-scout`)と `.claude/agents/<役>.md` の対応は `src/shared/agents.ts` が持ちます。
  依頼のファイルに、役の名前・モデルの ID・定義のハッシュ(`agent`)を書き、依頼の鍵にハッシュを入れます。ハッシュは、モデルの ID と指示の本文から決め、
  説明文(`description`)の直しでは変わりません。取り込んだ結果(試験ガイドの `guide.agent`、事実カードの `extracted[].agent`、下書きの `agent`)にも同じ記録が残ります。
- ログの作法: 出力は「種類」と「場所(項目名や位置)」だけです。環境値・鍵・本文、入力した引数の文字列は出しません。
  想定外の例外は、クラス名だけを出します。

## 置き場所の決まり

| 場所 | 用途 | コミット |
| --- | --- | --- |
| `src/` | コードとテスト(段階ごとのディレクトリと、共通部品の `shared/`) | する |
| `ledger/` | 出典の台帳(資格ごとの JSON) | する |
| `facts/` | 事実カードの台帳(資格ごとの JSON) | する |
| `plans/` | 収集の計画(資格ごとの JSON) | する |
| `provenance/` | 問題の来歴(資格ごとの JSON。下書きの ID、事実カードの ID、出典の URL・取得日・本文のハッシュ) | する |
| `decisions/` | 人の判断の記録(資格ごとの JSON。対象の ID か出典の URL と本文のハッシュ、判断、理由コード。[人の判断の記録](../../docs/human-decisions.md)) | する |
| `pipeline-work/`(リポジトリ直下) | 取得した本文、段階の成果物 | しない(gitignore。混入はコミット前・push 前の検査が止める) |

`ledger/`、`facts/`、`provenance/`、`decisions/` の JSON は、CLI が書き、読み込むたびにスキーマで検査します。手で整形しないので、整形(Biome)の対象から外しています(`biome.json`)。
