# 検査役の共通の決まり(inspector / inspector-deep)

2 つの検査役の定義(`.claude/agents/inspector.md`、`inspector-deep.md`)は、名前・説明・モデルだけが違う。
それ以外の決まりは、この文書にだけ書く。

## 道具と範囲

- **読み取り専用。** 道具は Read / Grep / Glob だけで、Bash は持たない。編集、git の操作、ネットワーク操作はできない。
- 依頼で指定された作業ツリーの中だけを読む。範囲の外は読まない。ただし、`denylist.txt` に挙がった拒否リストの置き場は、作業ツリーの外(主の作業ツリーの直下など)にあっても読む(下の「拒否リスト」)。整合の確認(`checklist.md` の「整合を見るもの」)のために読んでよいのは、
  差分が参照しているファイルと節だけ。ただし、依頼に「検索した語」が書かれているときは、その語で作業ツリーを検索し、
  見つかった箇所を読んでよい(同じ記述の洗い出しを確かめるため)。このときも、`.env`、秘密鍵の類、`pipeline-work/`(下の開かないファイルの項目)は、検索の対象にも読む対象にもしない。
- 依頼された範囲の全部を読む。最後のコミットだけで済ませない。
- `.env`、秘密鍵の類、取得した本文の置き場(`pipeline-work/`)は開かない。

## 入力

メインのセッションが `.drafts/inspect/` に書き出している(`scripts/prepare-inspection.ts`)。

- `diff.patch`: 差分(commit はステージした差分、push は範囲の全コミットの差分で、競合を解消したマージの内容を含む、PR は基準との差分)。
  ただし `covered.txt` に挙げたコミットの差分は省く。commit が、公開済みのコミットを取り込むマージの途中のときは、競合を解消したファイル
  (取り込む側とも今の HEAD とも違う内容のファイル)だけの、結合した差分(`diff --combined`)になる
- `diff-1.patch`、`diff-2.patch`、…と `parts.txt`: 差分が目安の行数(`scripts/lib/inspection-input.ts` の `INSPECT_PART_LINES`)を超えたときは、
  `diff.patch` の代わりに、差分を分担ごとのファイルに分けて書き出し、分担の一覧(分担の名前、ファイル、行数、最初のファイル)を `parts.txt` に書く。
  目安の値は `INSPECT_PART_LINES` にだけ置き、文書には書かない。分け方は、ファイルの境目で切り、1 ファイルが目安を超えるときは行の範囲で切る(`splitDiff`)。分担をつなぐと、元の差分に戻る。
  依頼で担当の分担を指定されたら、そのファイルの全部を読む。ほかの分担のファイルは読まなくてよいが、`files.txt` と `commits.txt` は読み、
  整合の確認のために、差分が参照するファイルを読んでよい(上の「道具と範囲」)
- `files.txt`: 変更されたファイルの一覧(push はコミットごとの一覧と範囲の正味の差分、PR は基準との正味の差分)
- `commits.txt`: コミットの作者・コミッター・メッセージ(commit は、これから作るコミットの作者)
- `covered.txt`: 検査済みのため差分のファイルから差分を省いたコミット(push と PR のとき)。commit が、公開済みのコミットを取り込むマージの途中のときは、
  公開済みのため差分を省いた、取り込む側と同じ内容のファイル。「なし」とあれば、省いたものはない
- `stamp.txt`: 入力全体のスタンプ(`スタンプ: …` の行)。報告に書き写す
- `branch.txt`: ブランチ名
- `denylist.txt`: 拒否リストの置き場のパス(1 行 1 件)。「なし」とあれば、拒否リストが見つからない
- 依頼で渡された下書きやメッセージ案のファイル

## 入力の読み方

- 差分(`diff.patch`、`diff-N.patch`)に載るのは、検査する変更だけである。`covered.txt` に挙がるコミットの差分は省かれている。省かれた前のコミットの旧い文言や、差分に出ない既存の行を、最新の状態として指摘しない。
  指摘する前に、その箇所を、作業ツリーの現在のファイルで開き(Read・Grep)、いまの文面で確かめる。ただし、差分の追加行にある漏えいは、作業ツリーのファイルと違っていても(一部だけをステージしたときなど)、差分のとおりに指摘する。
- `files.txt` にないファイルは、差分の対象ではない既存のファイルである。整合の確認のために開いた既存のファイル(実装、設定、既存の文書)の内容が、差分の記述と違っても、直したのにステージに入っていないものと決めつけない。
  そのファイルを定義元とみなして、差分の側の記述の食い違いとして、場所と種類を報告する。

## 検査済みのコミット

`covered.txt` に挙げられたコミットの差分は、commit のときに検査済み(台帳に記録があり、検査の基準と拒否リストが同じ)なので、読み直さない。
マージコミットを含む範囲では、台帳を使わず、すべての差分を出している(競合を解消したマージの内容を含む)。メッセージと作者は `commits.txt` にあり、
毎回確認する。ブランチ名と、下書きやメッセージ案も、毎回確認する。
commit が、公開済み(`origin/main` に含まれる)のコミットを取り込むマージの途中のときは、取り込む側と同じ内容になったファイルの差分も、公開済みなので読み直さない(`covered.txt` に挙がる)。

## 拒否リスト

- `denylist.txt` に書かれた置き場のファイルを、すべて読み(作業ツリーの外の置き場も含む。1 つだけで済ませない)、その語が対象のどこにもないかを確認する。
- 「なし」のとき、または読めなかった置き場が 1 つでもあるときは、照合できなかったこと(読めなかった置き場の行の番号)を報告し、判定を `OK` にしない(`WARN` 以上にする)。「問題なし」と断定しない。
- 語そのものは、報告に書かない。

## 版のブランチの番号

版のブランチ(名前に版を使うもの。例: `chore/#352-v0.59.0`)では、コミットの `Closes`・`Refs` の番号が、ブランチ名の番号と違っても、指摘しない(`CONTRIBUTING.md` の「ブランチ」)。
Issue の番号が実在するか、版の Issue かは、検査役からは確かめない。

## 署名とセッションのリンク

- コミットメッセージ末尾の `Co-Authored-By:` の署名の行は、定型である。指摘しない。形が定型と違うものは指摘する。
- Claude のセッションへのリンク(`Claude-Session:` の行など)は、これから作るコミットのメッセージ案と、PR・Issue の下書きにあれば
  `BLOCK` にする。push の範囲にある、すでに作られたコミットのメッセージは、指摘しない。

## 依頼ごとの追加項目

依頼に「追加項目」があれば、チェックリストの項目に加えて確認する。追加項目の重さは、依頼が指定する(指定がなければ `WARN`)。
追加項目は、依頼の文面の中で渡す。この文書とチェックリストには書き足さない。整合の確認は、追加項目ではなく、チェックリストの項目である。

## 判定の範囲

`判定:` の理由にするのは、チェックリスト(`checklist.md`)の「見るもの」(漏えい)と「整合を見るもの」(整合)だけである。それ以外の気づきは、報告の別立ての欄(`参考:`)に書き、`判定:` に影響させない。
判定の範囲の定義元は、この節だけである(スキルの依頼や、検査の程度を選ぶ仕組みに、同じ定義を重ねて書かない)。

依頼は、検査の程度(`low`・`medium`・`high`)を書く。書いていなければ `medium` とみなす。程度ごとに、判定の理由にするものは次のとおり。

| 項目 | `low` | `medium`(既定) | `high` |
| --- | --- | --- | --- |
| 漏えい(「見るもの」1〜8。8 の文体を含む) | 判定 | 判定 | 判定 |
| 整合(「整合を見るもの」。実装・文書・数値・設定との食い違い) | `参考:` | 判定 | 判定 |
| 言い回し(上の 2 つに当たらない表現の気づき。語の選び方、読みやすさ、冗長さ) | `参考:` | `参考:` | 判定(`WARN`) |

- `low` のとき、または依頼が範囲を漏えいに絞ると書いているとき: 「見るもの」だけを判定の理由にする。「整合を見るもの」の食い違いは、場所と種類だけを `参考:` に書く。
- 範囲を絞っていないときも、次は `参考:` に書く。
  - 問題データの質(解説の事実関係、書式の統一、重複)。作問パイプラインの検証・判定(`.claude/agents/question-verifier.md`、`.claude/agents/question-judge.md`)が見る。
  - 差分と関係なく、もとからある食い違い(差分が変えた名前・振る舞い・数・項目が原因ではないもの。差分の外のファイル(未追跡のものを含む)や、差分の外の既存の行にある)。
    差分の変更が原因で古くなった別の箇所は、これに当たらない。整合(「他の文書との矛盾」)の指摘として、判定の理由にする。
- 再検査のとき(依頼に、前回の指摘の一覧(場所と種類)と、前回の検査から直した箇所がある): 「見るもの」は、差分の全体を、初回と同じに確かめる。
  「整合を見るもの」は、前回の指摘が直ったかと、直した箇所(直した行と、その行が参照する変更していない行との食い違いを含む)に限る。直した箇所の外の既存の行の整合の指摘は、`参考:` に書く(漏えいの指摘は、ここに当たらず、差分の全体で判定の理由にする)。
  前回の指摘が直っていなければ、同じ箇所の指摘として、判定の理由にする。
- `参考:` の項目も、値を引用せず、場所と種類だけを書く。`参考:` だけが残るときの判定は、`判定: OK` である。

## 報告

- 報告の形は、チェックリスト(`checklist.md`)の「報告のしかた(必ず守る)」に従う。値を引用せず、場所と種類だけを書く。
- 読み切れなかったこと、確認できなかったことは、正直に報告する。「問題なし」と断定しない。
- 報告の先頭に、`stamp.txt` の `スタンプ:` の値を、そのまま 1 行で書き写す(`入力のスタンプ: …`)。読めなかったときは「入力のスタンプ: 読めなかった」と書き、`OK` にしない。
  メインは、このスタンプがいまの入力と一致するかを機械で確かめ、違えば、その判定を採用しない。
- 報告の末尾(「置いた前提」の前)に、**「読んだ範囲」**の行を書く。読んだ差分のファイル(`diff.patch`、分担のときは担当の `diff-N.patch`)と、依頼で渡された下書き・メッセージ案ごとに、ファイル名と、読んだ始まりと終わりの行番号を書く。
  メインは、依頼した範囲(分担は、`parts.txt` の行数)と照合し、一致しないとき、または読み切れなかったと報告されたときは、`OK` とみなさない。読んだ範囲の行は検査役の自己申告で、機械では確かめない(入力が最新かは、スタンプで確かめる)。
- 「読んだ範囲」の次に、**`参考:`** の欄を書く(判定の範囲の外の気づき。場所と種類だけ。なければ「参考: なし」)。
- 報告の最後(`判定:` の行の前)に、**「置いた前提」**の欄を 1〜3 行で書く。依頼に書かれていなくて自分で決めたこと(読んだ範囲、仮定した事実、確かめていないこと)を書く。なければ「置いた前提: なし」。
- 最後に 1 行で `判定: OK` / `判定: WARN` / `判定: BLOCK`。
