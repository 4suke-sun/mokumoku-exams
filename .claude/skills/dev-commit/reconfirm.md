# 再確認の条件(dev-commit / dev-push / dev-pr 共通)

検査や承認のあとに、対象が変わったら、そのまま進めずにやり直す。

| 操作 | 控えるもの(控える時点) | やり直す条件 | やり直しの起点 |
| --- | --- | --- | --- |
| commit | ステージした差分のハッシュ(`git diff --cached \| shasum -a 256`)と、メッセージ案のハッシュ(`shasum -a 256 .drafts/commit-msg.txt`)。検査役に依頼する前 | 検査で止められて直したとき。検査のあとに差分かメッセージ案が変わったとき | 機械的な検査 |
| push | push する範囲の末尾のコミット(`git rev-parse HEAD`)と、範囲のコミット数(`git rev-list --count <範囲>`)。承認の時点 | 検査で止められて直したとき。承認のあとに範囲が変わったとき(コミットが増えた、作り直した) | 範囲と作者情報の確認 |
| PR・Issue | 下書きのハッシュ(`shasum -a 256 <下書きファイル>`)。PR は、範囲の末尾のコミット(`git rev-parse HEAD`)とコミット数(`git rev-list --count origin/main..HEAD`)も。承認の時点 | 投稿の直前のハッシュが、承認のときと一致しないとき。下書きを直したとき。PR は、承認のあとに範囲が変わったとき(この場合、push も行わない) | 機械的な検査 |

- 控えた値は、進める直前(commit・push・投稿の直前)にもう一度取り、一致することを確かめる。一致しなければ、進まずにやり直す。
- 例外: commit のメッセージ末尾に、定型の署名の行(`Co-Authored-By:`)を足すだけのときは、再検査を要しない。
