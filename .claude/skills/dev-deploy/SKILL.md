# /dev-deploy — 版のデプロイの手順を進める

手順の本体は `scripts/deploy.ts` にある。このスキルは、**人の明示の指示の確認**と、**スクリプトの呼び出し**、**承認を待つ関門**だけを担う。
段階の中身は、このスキルに書き写さない。

このスキルは、モデルが自分の判断では起動しない(`disable-model-invocation: true`)。デプロイは環境を変えるので、人が `/dev-deploy` と打ったときだけ動く。
指示は、その版の分に限る。次の版には持ち越さない。

## 守ること

- `cdkd deploy`(`npm run deploy`)は、モデルが実行しない。確認の問いが出うるので、人が自分の端末で実行する(`docs/app/lessons/0004-mask-diff-output.md`)。
  デプロイの出力は、`mask` に通さずに記録しない。人の報告と、終了コードだけを使う。
- 差分・合成の出力は、必ず `npm run -s mask` を通した形で読む(スクリプトが通す)。伏せていない出力を、会話・記録・コミットに出さない。
- 素の `cdk` と混在させない。`v1.0.0` までのデプロイは `cdkd` だけ(`CLAUDE.md`)。
- 失敗したときは止めて、原因を直し、同じコマンドを再実行する。戻すときは、前の版のタグを指定して、同じ手順で再デプロイする(自動のロールバックはしない)。

## Step 1. デプロイの前まで(何も変えない)

```sh
node scripts/deploy.ts <版>
```

前提の確認(版のタグのコミットで、変更がなく、`.env` がある。AWS の認証が使える)→ 要否の判定(前の版のタグとの差分のパス)→ 静的な確認
(`docs/pre-deploy-checklist.md` の、機械で確かめられる項目)→ 差分(伏せた出力の要約)→ 関門 の順に行い、段階ごとの結果を表で出す。
要らないときは「デプロイは不要」と出して終わる。`data/release-notes.json` だけが影響する版は、人が省くと選べる(次の版のデプロイでまとめて出る)。
失敗したら、その段階を人に報告して止まる。

## Step 2. 関門(人の承認を待つ)

差分の要約(変更のあるスタック、リソースの種類と件数、IAM・公開の設定・削除の有無)を、人に見せる。要約が「解釈できなかった」ときは、
`.drafts/deploy/diff.masked.txt`(伏せた全文)を読んで、人に見せる。承認は、人自身の発言に限る。承認がなければ、先へ進まない。

## Step 3. デプロイ(人が実行する)

承認のあと、次のコマンドを人に示して待つ(モデルは実行しない)。

```sh
npm run deploy -w @mokumoku-exams/infra -- --all
```

人が実行を終えて、結果(成功か失敗か)を報告したら、先へ進む。失敗したら、原因を人と確かめ、Step 1 からやり直す。

## Step 4. デプロイのあと

```sh
node scripts/deploy.ts <版> --after
```

人が確かめる項目の一覧(`docs/post-deploy-smoke.md` の「3. 確認する流れ」)を出して止まる。人が確かめて、結果を報告する。
**この確認が通るまで、公開へ進まない**(`docs/post-deploy-smoke.md`)。結果は、項目ごとに、成功 / 失敗 / 未確認で、場所と種類だけを書く(値を書かない)。
