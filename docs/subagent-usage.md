# 定義を持たないサブエージェントの用途

定義を持たないサブエージェント(`general-purpose`)は、メインのセッションと同じモデルで動きます。
用途ごとに、入力・出力・読む範囲・書く範囲・呼び出す手順と、近い既存の定義を一覧にします。どの用途を、どの定義に回すかは、#520 の「決めること」で決めます。
この一覧は、用途の洗い出しです。新しい定義は、まだ足していません。

件数は、#520 の本文の内訳(エージェントごとの費用の集計、`npm run agent-cost`)です。

## 洗い出しで分かったこと

- どの用途も、手順の文書は「サブエージェントで」「別のサブエージェントの検証役で」のように書き、どの定義を使うかを書いていない。そのため、定義のない `general-purpose` で起動される。
- バッチでの生成・保留の再判定・生成物の検証の 3 つは、作問パイプラインの依頼(`pipeline-run` が渡す依頼のファイル)の形を持たない。近い既存の定義(`question-drafter`・`question-verifier`・`question-judge`)は、依頼のファイルの場所だけを受け取る前提なので、そのままでは使えない。
- 保留の再判定と生成物の検証は、書く範囲がない(報告だけ)。定義を足すなら、道具を Read・Grep・Glob に絞れる。
