# デプロイ後の画面確認

デプロイした直後に、ブラウザで確かめる流れと、結果の報告のしかたです。**この確認が通るまで、公開へ進みません。**
単体テストと E2E は、開発サーバーや差し替えた認証で動きます。本番のビルドでしか起きない不具合(例: [lessons/0006](./app/lessons/0006-reload-after-sign-in.md))や、
CloudFront・Lambda を通した経路でしか起きない不具合は、デプロイしてから画面で確かめます。

## 1. ほかの確認との関係

| 確認 | 内容 | 通すとき |
| --- | --- | --- |
| [デプロイ前のチェックリスト](./pre-deploy-checklist.md) | コードと設定を、静的に確かめる(環境変数、認証の設定、部品の処理の有無、`cdkd` の引数) | デプロイの前 |
| **この文書** | デプロイ後の実機の挙動を、軽く確かめる | デプロイの直後 |
| [公開前のチェックリスト](./pre-release-checklist.md) | 公開前の最終確認。「5. 動作確認」が、配信のドメインでの確認の正 | 公開の前 |

- この確認は、公開前の確認の**前段**です。公開前の確認が正で、この確認の結果は、公開前の確認の代わりになりません。
- 公開前の確認と重なる手順(配信のドメインでの `/login` と API の `401`、ログイン → 出題 → 結果の流れ、Function URL への直接のアクセス)は、この文書に書き写さず、
  公開前のチェックリストの「5. 動作確認」の手順で確かめます。
- 設定値の確認(認証の設定、合言葉など)は、デプロイ前のチェックリストを参照します。

## 2. 準備

- 確認するのは、デプロイした環境です。環境は 1 つで、`STACK_PREFIX` はリソース名の接頭辞であり、環境という概念は定義していません([インフラの構築とデプロイ](./app/infra.md)、`packages/infra/lib/config.ts`)。
- この文書の「公開」は、リポジトリと配信を公開することです([公開前のチェックリスト](./pre-release-checklist.md))。
- 環境の URL は、デプロイの出力(`DistributionDomainName`。独自ドメインを使うときはそのドメイン)で得ます。文書には書きません。
- 確認に使う利用者は、招待された確認用のアカウントです。パスワードは、記録にも報告にも書きません。

## 3. 確認する流れ

| 項目 | 確認の方法 | 期待する結果 |
| --- | --- | --- |
| サインイン | サインイン、サインアウト、再度のサインインをする | どれも通る |
| 主要なボタン | ホーム、問題を解く、結果、復習、アカウントの各画面で、主要なボタンとリンクを 1 つずつ押す(ボタンの有無の静的な確認は[デプロイ前のチェックリスト](./pre-deploy-checklist.md)) | 期待する画面や表示になる |
| 同じ配信元での API | ブラウザの開発者ツールで、画面と同じ配信元の `/api/` のパスの応答を見る | 想定どおりのステータス(2xx)で応答し、本文にトークンが出ていない。未ログインの `401` は、公開前の確認の手順で確かめる |
| Cookie | サインイン後の Cookie(`mokumoku_id`・`mokumoku_access`・`mokumoku_refresh`)を、開発者ツールで見る | `HttpOnly`・`SameSite=Lax`・`Secure` で付いている([認証の仕組み](./app/auth.md)) |
| 画面スタイル | リッチ / シンプルとライト / ダークを切り替えて、主要な画面を見る | 表示が崩れていない |
| 静的ファイルと CSP | 開発者ツールで、`/icons/` の画像と `/sw.js` の応答のヘッダーを見る。主要な画面を開き、コンソールを見る | 画像とアイコンは `max-age=86400`、`/sw.js` は `no-cache` で返る。応答に `Content-Security-Policy-Report-Only` があり、コンソールに CSP の違反が出ていない(出たら、場所と種類を記録する) |
| 失敗の記録 | API の失敗を 1 度起こせる環境なら起こし、CloudWatch のアプリの 5xx のメトリクスを見る | メトリクスが増える(アプリの 1 行の JSON が、そのままログに残っている) |

公開前の確認と重なる手順(未サインインで保護された画面を開くと、サインイン画面へ移ること)は、上の表に入れていません。「1. ほかの確認との関係」のとおり、公開前のチェックリストの「5. 動作確認」で確かめます。

## 4. 結果の報告

- 項目ごとに、成功 / 失敗 / 未確認を、表で記録します。失敗には、画面の場所と、再現の手順を書きます。
- **値は引用しません。** URL・ID・トークン・メールアドレスは書かず、場所と種類だけにします。
- スクリーンショットは、環境の値(URL、ID)が写っていないことを確かめてから添えます。

## 5. 公開へ進む条件

- すべて成功していること。
- または、失敗の項目に対応する Issue があり、人が、その状態で進めてよいと許可していること。

人が確かめる手順なので、E2E に移せる項目は、ここに候補として残します。

- サインイン、サインアウト、再度のサインイン(E2E では、差し替えた認証で確かめている)
- 主要な画面の主要なボタンの動作
