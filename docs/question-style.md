# 作問のスタイルガイド

作問パイプラインの下書きの段階で、設問文・選択肢・誤答・自由記述の採点基準を、どう作るかの決まりです。
決まりの多くは、機械で検査できる規則(`packages/pipeline/src/draft/style.ts` と `distractors.ts`)になっていて、下書きを取り込むときに適用されます。
この文書の規則の名前は、検査の報告に出る名前と同じです。手順は[出題計画と下書きの手順](./drafting.md)、データの形は[問題データの仕様](./data-spec.md)にあります。

## 1. 規則の重さ

- **止める**(`block`): 違反した下書きは、不採用になります。理由コードは `style:<規則の名前>` です。
- **警告**(`warn`): 違反しても通ります。下書きの記録に、規則の名前と場所が残り、レビューで見ます。

報告は、規則の名前と場所(`questionText`、`choices.2.text` など)だけです。設問文や選択肢の本文は出しません。

## 2. 設問文

| 規則 | 重さ | 内容 |
| --- | --- | --- |
| `stem-question-form` | 止める | 問いの形(「〜か。」「〜してください。」など)で終える |
| `multi-select-count` | 止める | 複数選択の設問文には、選ぶ数(「2 つ選択」など)を書く |
| `multi-select-count-mismatch` | 止める | 複数選択の設問文に書いた数は、正答の数と一致させる |
| `stem-negation` | 警告 | 否定を含む設問は避ける。使うなら否定の語を 1 つだけにし、強調する |
| `stem-double-negation` | 止める | 設問文に否定の表現を 2 つ以上入れない(二重否定) |

## 3. 選択肢

| 規則 | 重さ | 内容 |
| --- | --- | --- |
| `choice-count` | 警告 | 選択肢は 4 つ以上にする |
| `choice-length-balance` | 警告 | 選択肢の長さをそろえる(最も長いものが 30 文字以上のとき、最も短いものの 3 倍を超えない) |
| `correct-length-bias` | 警告 | 正答だけが長い(短い)といった偏りを作らない |
| `choice-similar-pair` | 警告 | ほぼ同じ文言の選択肢を並べない。紛らわしさは、内容の違いで作る |
| `choice-catch-all` | 止める | 「すべて正しい」「いずれでもない」のような、選択肢をまとめる選択肢を置かない |

## 4. 誤答

誤答(正答でない選択肢)には、1 つずつ設計を付けます(下書きの `distractors`)。

| 項目 | 内容 |
| --- | --- |
| `key` | 誤答の選択肢の `key` |
| `type` | 誤答の型。`similar-service`(似た別のサービス)、`scope-difference`(適用範囲や条件の違い)、`misconception`(よくある誤解)、`numeric-difference`(数値や上限の違い)、`condition-reversal`(条件の逆) |
| `reason` | 誤りである理由。10 文字以上で具体的に書く |
| `basis` | 誤りの根拠。事実カードの主張(`factId`。依頼にあるものだけ)か、適用範囲の違い(`scope`。型が `scope-difference` のときだけ) |

誤答の検査は、モデルを呼ばずに行います。理由コードは `distractor:<コード>` か、保留の `ambiguous:<コード>` です。

| コード | 結果 | 内容 |
| --- | --- | --- |
| `distractor-missing` | 止める | 誤答に設計がない |
| `distractor-unknown-key` | 止める | 正答の選択肢や、存在しない選択肢に設計がある |
| `distractor-duplicate` | 止める | 同じ選択肢に設計が重複している |
| `distractor-reason-short` | 止める | 理由が短すぎる |
| `distractor-basis-not-in-request` | 止める | 根拠の事実カードが、依頼にない |
| `distractor-basis-scope-type` | 止める | 適用範囲の違いを根拠にできるのは、`scope-difference` の型だけ |
| `distractor-forbidden-text` | 止める | 理由や適用範囲の言い表しに、URL や環境固有の値がある |
| `distractor-type-bias` | 警告 | 誤答が 3 つ以上で、型が 1 種類に偏っている |
| `similar-to-correct` | 保留 | 誤答が正答とほぼ同じ文言(15 文字以上の選択肢だけ比べる) |
| `supported-by-fact` | 保留 | 誤答の語(数値とラテン文字の語)が、根拠の主張にそのまま含まれる |

保留は、**設問文の条件のもとで誤答が正しくなりうる(正答が複数になる)候補**です。機械の検査は候補を出すだけで、白黒はつけません。
候補は、モデルによる検査(検証の段階)で確かめるまで、先へ進めません。

## 5. 自由記述の採点基準

形は[問題データの仕様](./data-spec.md)の「自由記述」に従います。データの検査規則(配点と合格点の関係、観点名の重複、キーワードの長さなど)に合わない採点基準は、
形の誤りとして、取り込みを止めます。次の規則は、データの検査規則に加える、作り方の決まりです。

| 規則 | 重さ | 内容 |
| --- | --- | --- |
| `rubric-criteria-count` | 警告 | 観点は 2 つ以上にする。1 つだけでは、部分的な理解を測れない |
| `rubric-keyword-short` | 警告 | キーワードは 2 文字以上にする。1 文字では、無関係な回答にも当たる |
| `rubric-keyword-shared` | 警告 | 同じキーワードを、複数の観点に入れない |
| `rubric-pass-ratio` | 警告 | 合格点は、配点の合計の 5 割以上 9 割以下にする |

観点とキーワードは、根拠の事実カードの主張だけを根拠にします。選択肢と誤答の規則は、自由記述には適用しません。

## 6. 禁止事項と、そのほかの決まり

| 規則 | 重さ | 内容 |
| --- | --- | --- |
| `no-url` | 止める | 設問文・選択肢・解説・観点名・キーワードに URL を書かない。出典は来歴に記録する |
| `no-env-value` | 止める | 環境固有の値(12 桁のアカウント ID、ARN、アクセスキー、メールアドレス、ローカルのパス)を書かない |
| `overclaim-term` | 警告 | 「必ず」「絶対」「常に」など、断定しすぎる語を使わない |
| `explanation-length` | 警告 | 総合解説は、正答の理由が分かる長さ(30 文字以上)で書く |

加えて、次の決まりがあります(規則ではなく、取り込みの関門です)。

- 設問文と正答は、依頼の事実カードの主張だけを根拠にします。主張にないことは書きません。
- 公式の文書の本文を、思い出して書き写しません。自分の言葉で書きます。
- 下書きの種別と難易度は、依頼のとおりにします。種別が違う下書きは、不採用になります(`kind-mismatch`)。

## 7. 規則を足す・変えるとき

1. `packages/pipeline/src/draft/style.ts`(または `distractors.ts`)に規則を足し、通る例と落ちる例のテストを書きます。
2. この文書の表に、同じ名前の行を足します。表の名前と実装の名前が食い違うと、テストが失敗します。
3. 規則の集合を変えたら、`STYLE_VERSION` を上げます。依頼の鍵が変わり、規則が変わったあとの依頼は、取り込み済みの入力とは別に扱われます。
