# Databricks Certified Data Engineer Associate(DBX-DEA-2605)の書き方

[Databricks の資格に共通の書き方](./dbx-common.md)に加わる、この資格の値と言い回しです。採点は [点数票](./scorecard.md) です。

## 1. 要点

**状況の問と、1 文の知識の問が混ざります。状況の問が多数を占めます。** 択一が大半で、選択肢は製品名・語句・文が混在します。

| 項目 | 目安 |
| --- | --- |
| 設問文の文字数(複数選択の表記を除く) | 30〜320(満点)、20〜420(部分点) |
| 状況の文(問いより前の文)の数 | 0〜5(知識の問は 0) |
| 設問文の段落 | 状況の問は、状況の段落と問いの段落を分ける(機械では見ない) |
| 状況つきの設問の割合(束) | 50% 以上 80% 以下(状況の文が 1 文以上あるもの) |
| 最長の選択肢の文字数 | 100 以内(満点)、150 以内(部分点) |
| 選択肢の最長÷最短 | 3.5 倍以内(満点)、5 倍以内(部分点) |
| 選択肢どうしの類似度(バイグラムの Dice) | 0.9 未満 |
| 複数選択の割合(束) | 15% 以下(複数選択がない束も通す) |
| 設問文の中央値(束) | 100〜190 字。90 パーセンタイルは 340 字以下 |
| 選択肢の形(束) | 製品名・語句・文の混在。文 50% 以下 |
| 設問文の先頭 8 文字が同じものの割合(束) | 40% 以下 |

## 2. 設問の構成

```text
[状況の問]  状況の段落(主体・現状 → 課題 → 要件。2〜5 文)+ 問いの段落(1 文)
[知識の問]  機能や仕様を直接問う 1 文(30〜90 字)
```

- 状況の問は、役割の語(「データエンジニア」「ジュニアデータエンジニア」)から書き出してよい。
- 知識の問は、製品名や機能名を主語にして、「〜の説明として正しいものはどれですか」「〜に使うのはどれですか」の形で問います。
- 状況は、現状の構成(使っている機能の組み合わせ)から始め、課題や追加の要件に進みます。要件は 2〜3 つまでにします。
- 問いは「最も適切なソリューションはどれですか」「推奨されるオプションはどれですか」「〜すべきですか」が主です。

## 3. 選択肢

| 項目 | 決まり |
| --- | --- |
| 数 | 単一 4。複数選択は 5(2 つが正答)で、まれに使う |
| 長さ | 最長÷最短は 3.5 倍以内。文で書く問は、1〜2 文(100 字以内) |
| 並行 | 方式を選ぶ設問は、選択肢どうしが書き出しや構成を共有し、1 点だけ違う |

## 4. 作問の指示に落とすとき

1. 設問は、状況の問と知識の問を混ぜる。状況の問は **状況の段落+問いの段落**(空行で分ける)。
2. 選択肢は、1 問の中で形をそろえる。最長の選択肢は 100 字以内にする。複数選択は、必ず「(2 つ選択)」と書く。
3. 誤答は、同じ層の別の機能・方式で、1 点だけずらして作る。事実カードの主張で誤りを示せるものにする。
4. 状況の要件・制約は、事実カードで根拠を示せるものだけにする。
5. 難易度との対応は拘束しない。この資格は全体が Associate の難しさなので、`easy` も状況つきで書くのが自然。
6. 問いは「です・ます」で書く。

## 5. 範囲の注意

- 分野は 7 つです(プラットフォーム、取り込み、変換とモデリング、Lakeflow Jobs、CI/CD、障害対応・監視・最適化、ガバナンス)。配点の重みは、資格マスタの分野の重みに従います。
- 設問は、機能の選び分け(コンピュートの種類、取り込み方式、デプロイ方法、トリガーの種類)と、操作や設定の意味を問います。
