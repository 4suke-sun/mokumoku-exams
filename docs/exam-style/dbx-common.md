# Databricks の資格に共通の書き方

Databricks の資格の問題に共通する、文章の構成の特徴です。資格ごとの値は、[Data Engineer Associate](./dbx-dea.md) にあります。
採点は [点数票](./scorecard.md) です。

## 1. 設問の構成

設問は、次の 2 つの部品でできています。

1. **状況**(任意): 誰が(ある企業・データエンジニア・チーム)、何をしようとしているか、どんな要件があるかを書きます。
2. **問い**(必須): 状況の要件を満たすものを、1 文で問います。

| 部品 | 決まり |
| --- | --- |
| 状況 | 1 文目で主体と目的・現状を書き、次の文以降で要件・制約を示す(「〜する必要があります」「〜したいと考えています」)。文の数は資格別 |
| 問い | 状況とは別の 1 文。末尾は問いの形(です・ます)で終える。状況つきの設問は、状況と別の段落にする |
| 主体 | 状況の書き出しは「あるデータエンジニア(チーム、企業)は」が主。ほかに「あなたは」。製品の機能を直接問う設問は、製品名や機能名を主語にしてよい |
| 1 文 1 要件 | 要件・制約は、1 文に 1 つ。並べるときは文を分ける |
| 根拠 | 正答を決める要件・制約は、出典と事実カードで根拠を示せるものにする |

設問には、2 つの型があります。**状況の問**(状況の段落+問いの段落)と、**知識の問**(機能や仕様を直接問う 1 文)です。資格によって、2 つの割合が違います。

## 2. 問いの形

- 末尾は「どれですか」「何ですか」「〜すべきですか」「〜でしょうか」か、「〜を選択してください」で終えます。句点の有無は問いません。
- 「どれか。」のように、「です・ます」を含まない末尾は避けます(点数票で減点します)。
- 複数選択は、必ず選ぶ数(「(2 つ選択)」)を書き、正答の数と一致させます。
- 否定の設問(〜でないもの、〜サポートされていないもの)は使いません。

## 3. 選択肢

| 項目 | 決まり |
| --- | --- |
| 数 | 単一選択は 4。複数選択は 5(2 つが主) |
| 形 | 製品名・機能名・コマンドの語、語句、文が混在してよい。1 問の中では、形と句点の有無をそろえる |
| 内容 | 機能名や方式を選ぶ設問は、同じ層の別の機能(例: 同じ用途の別のコンピュート、別の取り込み方式)を並べる |
| 並べ方 | 正答の位置と長さに偏りを作らない。正答だけが際立って長い(短い)形にしない |
| 誤答 | 正答と同じ分類のものから選び、1 点だけずらす(方式・範囲・条件・順序)。分類の違うものは混ぜない。事実カードの主張で誤りを示せるものにする |
| 一括り | 「すべて正しい」「いずれでもない」は置かない |

## 4. 表記

- 製品名・機能名・設定名は、英語の表記のまま書きます(例: Delta Lake、Unity Catalog、Auto Loader)。旧称と新称が両方使われているものは、事実カードの主張に合わせます。
- コードやコマンドの断片は、設問文の中で段落を分けて示します。選択肢にコードブロックは置きません。

## 5. 要件と制約の言い回し

- 要件は「〜する必要があります」「〜したいと考えています」「〜が求められています」で示します。
- 数値(データ量・頻度・件数)は、答えを分けるときだけ書きます。
- 長くするために、根拠のない要件を足しません。
