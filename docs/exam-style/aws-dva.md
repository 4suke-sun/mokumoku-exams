# AWS Certified Developer - Associate(AWS-DVA-C02)の書き方

[AWS の資格に共通の書き方](./aws-common.md)に加わる、この資格の値と言い回しです。採点は [点数票](./scorecard.md) です。

## 1. 要点

**設問は長く、選択肢は「やり方を述べる文」で、選択肢どうしが並行します。** Cloud Practitioner の値は流用できません。

| 項目 | 目安 |
| --- | --- |
| 設問文の文字数(複数選択の表記を除く) | 150〜360(満点)、110〜450(部分点) |
| 状況の文(問いより前の文)の数 | 2〜6 |
| 設問文の段落 | 状況の段落と、問いの段落を分ける。問いの段落は 100 字以内 |
| 状況つきの設問の割合(束) | 90% 以上(状況の文が 2 文以上あるもの) |
| 最長の選択肢の文字数 | 150 以内(満点)、220 以内(部分点) |
| 選択肢の最長÷最短 | 3 倍以内(満点)、4.5 倍以内(部分点) |
| 選択肢どうしの類似度(バイグラムの Dice) | 0.97 未満 |
| 複数選択の割合(束) | 60% 以下(複数選択がない束も通す) |
| 設問文の中央値(束) | 180〜290 字。90 パーセンタイルは 370 字以下 |
| 選択肢の形(束) | 文が 80% 以上 |
| 設問文の先頭 8 文字が同じものの割合(束) | 45% 以下 |

## 2. 設問の構成

```text
[状況の段落]  主体・目的・現状の構成 → 追加の事情 → 要件・制約(2〜6 文)
[問いの段落]  要件を満たす〜は何でしょうか。/〜を選択してください。(1 文)
```

- 主体は「ある企業は」が主です。ほかに「ある開発者は」「あるデベロッパーが」「あなたは」「ある会社は」。開発者を主役にした状況を書いてよい。
- 状況は、**現状の構成**(使っているサービスの組み合わせ)から始め、困りごとや追加の要件に進みます。サービス名は 1 〜数個にとどめ、並べすぎません。
- 要件は「〜する必要があります」「〜が求められています」で示します。問いの文に「この要件を満たす」を入れる形を使ってよい。コストや運用の最小化(「最も」「最小限」)を求める設問を混ぜてもよい。
- 数値(台数・容量・期間・金額)は、答えを分けるときだけです。
- コードや設定の断片を設問に含めるのは、まれです。
- 否定の設問は使いません。
- 問いの末尾は、「〜してください」「〜は何でしょうか」「〜はどれでしょうか」が主です。複数選択は「(2 つ選択)」が主です。

## 3. 選択肢

| 項目 | 決まり |
| --- | --- |
| 数 | 単一 4、複数 5(2 つが正答) |
| 形 | **文**。「〜する。」で終える(句点あり)。1 問の中でそろえる |
| 内容 | **手順や設定のやり方**(「A を作成し、B を設定する」)。2 文以上の選択肢や、「〜して、〜する」の連なりを使ってよい |
| 並行 | 選択肢どうしは書き出しや構成を共有し、**1 つの要素だけ**違う。紛らわしさは、部品の入れ替え(サービス・API・設定値)で作る |
| 長さ | 最長÷最短は 3 倍以内。そろえる |
| 偏り | 正答の位置と長さに偏りを作らない |

## 4. 作問の指示に落とすとき

1. 設問文は **状況の段落+問いの段落**(空行で分ける)。状況 2〜6 文、150〜360 字。
2. 選択肢は文にして句点で終える。最長の選択肢は 150 字以内にする。
3. 誤答は、正答の部品を 1 つ入れ替えて作る(似たサービス、別の API、逆の設定値)。事実カードの主張で誤りを示せるものにする。
4. 状況の要件・制約は、事実カードで根拠を示せるものだけにする。長くするために、根拠のない要件を足さない。
5. 難易度との対応は拘束しない。この資格は全体が Associate の難しさなので、`easy` も状況つきで書くのが自然。
6. 問いは「です・ます」で書く。選択肢の「〜する。」は常体のままにする。

## 5. 範囲の注意

- 設問は、サービスの選択よりも、**サービスの使い方(API・設定・コード・デプロイ・認証)の選択**を問います。
- 解説は長めで、手順や設定の箇条書き(構成の詳細)を伴うことがあります。
