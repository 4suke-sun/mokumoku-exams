# 資格ごとの出題スタイル

問題文・設問・選択肢の**書き方**(文章の構成)を、資格ごとの出題スタイルに合わせるための指針です。合わせるのは、書き方と出題の重みづけ(論点の分布など)だけで、問題の内容(事実の正誤)ではありません。
問題の内容の根拠は、これまでどおり、許可したドメインの出典と事実カードだけです。

指針は 2 層です。

| 層 | 文書 | 内容 |
| --- | --- | --- |
| ベンダー共通 | [aws-common.md](./aws-common.md)、[dbx-common.md](./dbx-common.md) | ベンダーの資格に共通の構成・問いの形・選択肢・要件の言い回し |
| 資格別 | [aws-clf.md](./aws-clf.md)、[aws-dva.md](./aws-dva.md)、[aws-aib.md](./aws-aib.md)、[aws-soa.md](./aws-soa.md)、[dbx-dea.md](./dbx-dea.md) | 資格ごとの長さの目安・設問の型・選択肢の形・判定の基準 |

作問役は、依頼の `styleGuides` に挙がった文書(ベンダー共通、資格別、ベンダーの用語の辞書)を読んで書きます。採点の仕組みは [scorecard.md](./scorecard.md) です(`npm run pipeline -- score <資格コード>`)。
文書の資格別の値と、点数票の帯(`packages/pipeline/src/scorecard/profiles.ts`)は、同じ値を持ちます。主な値の食い違いは、テストが見つけます。

## 決まり

- 指針に置くのは、長さや構成といった、書き方の特徴の記述と、出題の重みづけ(論点の分布、誤答の作られ方の傾向)の抽象的な記述だけです。重みづけは、複数の所感や公式の例題に共通するものを蒸留したもので、問題の内容の根拠にはしません([出典と権利の方針](../source-policy.md)の「出題の傾向の蒸留」)。
- 問題の文章は、すべて新たに書きます。既存の文章の写しや、語順をなぞった言い換えは作りません([作問のスタイルガイド](../question-style.md)の 6 節は公式の文書の書き写し、[出典と権利の方針](../source-policy.md)の 2 節と 5 節は語順をなぞる言い換えの禁止)。
- 状況の要件や制約は、事実カードの主張で根拠を示せるものだけにします。長くするために、根拠のない要件を足しません(状況を成り立たせる架空の設定の数値は、資格別の指針が許すときだけ、根拠を求めません。事実の主張の数値には、必ず根拠を示します)。
- 語尾は「です・ます」(「〜でしょうか」「〜ですか」「〜してください」)にそろえます。
- 設問文の状況の文と解説の文は、主語を書きます。省いてよい範囲と、試験の言い回しとの優先は、[作問のスタイルガイド](../question-style.md)の「主語の書き方」にあります。

## 資格を足すとき

[資格を追加する手順](../adding-an-exam.md)の手順 8(書き方の指針と点数票の帯を足す)に従い、次の 2 つを足します。

1. 資格別の指針の文書(`aws-<略称>.md` のように、ベンダー共通の文書と同じ形)。公開している問題を判定する資格は、文書に「判定の基準」の節も置きます(`judge` は、節がないと入力の誤りで止まります)。ベンダーが新しいときは、ベンダー共通の文書も足します。
2. 点数票の帯(`profiles.ts` のベンダー共通の帯と資格別の帯)。足したら `npm run pipeline -- score <資格コード>` で、公開している問題を採点し、帯が極端でないことを確かめます。

## 用語の辞書

ベンダーごとに、訳語と略語の決まりを、辞書の文書(`<ベンダー>-terms.md`。[AWS](./aws-terms.md)、[Databricks](./dbx-terms.md))の表に置きます。表の形は、`packages/pipeline/src/shared/terms.ts` が決めています(形が違うと、取り込みが「用語の辞書の誤り」で止まります)。

| 表(見出し) | 内容 | 使われ方 |
| --- | --- | --- |
| 使う訳語と使わない訳語 | 使う語、使わない語、対象外の語(使わない語を含む別の意味の語)、条件 | 作問役・書き直し役の指針。判定の基準に、使う語と使わない語の対を足す。取り込みの規則 `avoid-term` が、使わない語を止める |
| 略語と正式名称 | 初出に正式名称を補う略語と正式名称の対 | 作問役・書き直し役の指針。取り込みの規則 `abbr-first-use` が、初出に補っていないものを止める |
| 補わない略語 | よく使われるので、補わない略語 | 作問役・書き直し役の指針(検査はしない) |

- 辞書の文書がないベンダーは、検査も受け渡しもしません。辞書にない語と略語も、検査しません。
- 辞書は、作問役と書き直し役が指針として読む文書です(依頼の `styleGuides` に載ります)。作問役の定義の「出題スタイル」の項に、辞書を読むことを書きました。
- 表の「条件」の列は、人が読む注記です。取り込みの規則 `avoid-term` には効かず、使わない語を、場所によらず止めます。判定の基準には、使う語と使わない語の対の注記として載ります(判定役が、条件を読んで判断します)。使わない語を含む別の意味の語は、「対象外の語」に足します(例: 「表示」)。使わない語が一般の文でも使われる語のときは、対象外の語を先に足します。
- 判定の基準に足すのは、使う語と使わない語の対(条件を注記として含む)だけです(略語の補い方は、取り込みの規則が止めるため)。対が変わると、判定の基準のハッシュが変わり、判定をやり直します。
  判定役の評価(`judge-eval`)の基準には、足しません(資格別の文書の節だけ)。
- 試験ガイドの対象サービスの一覧(台帳。範囲の判断に使う)と、辞書の略語と正式名称の対は、別に持ちます。前者は範囲の判断、後者は初出の書き方のためで、読む場所が違います。
- 表記ゆれと誤字の検査(別の仕組み。#412)とは、対象が違います。辞書は、資格の用語の訳語と略語(使う・使わない・補う・補わない)と、作問への受け渡しです。
- 辞書の中身を変えたときは、変えた表の語が、作問の取り込みで検査されます。公開済みの問題は、検査しません(直す作業は、別の変更で行います)。

## 判定の基準

公開している問題を、基準に照らして判定します。基準は二層で、**機械の観点**は点数票([scorecard.md](./scorecard.md))、**LLM の観点**は判定役(`question-judge`。[ADR 0021](../app/adr/0021-pipeline-judge-role.md))が、資格別の文書の「判定の基準」の節に照らして判断します。点数の閾値(問題 1 問が 80 点、束が 70 点)は、判定のために変えません。
台帳に試験ガイドの対象サービス・対象外サービスの一覧があるときは、その一覧を、判定の基準の本文の末尾に足して判定役に渡します(J5 の範囲の判断に使う。[ADR 0024](../app/adr/0024-scope-check-by-exam-guide-service-lists.md))。一覧が変わると、判定の基準のハッシュが変わり、判定をやり直します。

```sh
npm run pipeline -- judge <資格コード>            # 判定の依頼を書く
npm run pipeline -- judge <資格コード> --import   # 判定役の出力を検査し、判定の結果を書く
```

### 判定

| 判定 | 意味 | 次の扱い |
| --- | --- | --- |
| `publish` | 基準を満たす。理由コードはない | 公開のまま |
| `rewritable` | 内容(論点)は生かせるが、書き方が基準を満たさない。書き直して公開に戻せる | 非公開へ移す対象、かつ書き直しの対象にする(移す作業は `unpublish`、書き直しは `draft --rewrite`、公開へ戻す作業は `restore`) |
| `unpublish` | 設問が成り立たない、または試験の範囲外で、同じ内容の書き直しでは直らない | 非公開へ移す対象にする(書き直しの対象にしない。移す作業は `unpublish`) |

### 理由コード(`judge:<コード>`)

| コード | 観点 | 意味 | 許す判定 |
| --- | --- | --- | --- |
| `type-mismatch` | J1 | 設問の型が、その資格の型から外れる | `rewritable` |
| `situation-unnatural` | J2 | 状況が不自然、または要件が答えを分けていない | `rewritable` |
| `choices-weak` | J3 | 誤答が紛らわしくない、または選択肢の構成がそろっていない | `rewritable` |
| `explanation-inconsistent` | J4 | 解説が、設問・正解・選択肢と食い違う | `rewritable` |
| `not-unique` | J5 | 正答が 1 つに決まらない(複数選択は個数も) | `unpublish` |
| `out-of-scope` | J5 | 試験の範囲外の論点を問う | `unpublish` |

- 判定が `publish` のときは、理由コードを持たない。`rewritable` のときは、上の `rewritable` のコードだけを持つ。`unpublish` のときは、`not-unique` か `out-of-scope` を 1 つ以上持つ(`rewritable` のコードを併せて持ってよい)。
- 解説が**出典と合うか**は、判定役の観点に入れません。出典の節を読んで確かめるのは、検証役(`question-verifier`)の仕事です(公開済みの問題の来歴は一部にしかなく、節を取り出せないため)。判定役の J4 は、設問・正解・解説のあいだの食い違いだけを見ます。
- 判定の結果は、作業用の置き場(`pipeline-work/judge/<資格コード>/results.json`)に、問題の ID、判定、理由コード、指摘の場所、機械の観点の点数と減点の項目、判定に使った内容と基準と判定役の定義のハッシュだけで書きます。問題の本文は持ちません。コミットしません。

### 使う時機

最初は、定期の採点として手元で `judge` を実行し、結果を人が読みます(非公開へ移すのは、結果を読んだ PR で行う)。取り込み(下書きを公開データに入れる)の時点では、判定で止めません。点数票の新しい項目と同じく、効果が確かめられるまで、取り込みを止めません。
判定役の見落としと誤検出は、`npm run pipeline -- judge-eval <資格コード>` で測ります([判定役の評価](../evaluation.md))。
