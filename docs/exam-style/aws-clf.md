# AWS Certified Cloud Practitioner(AWS-CLF-C02)の書き方

[AWS の資格に共通の書き方](./aws-common.md)に加わる、この資格の値と言い回しです。採点は [点数票](./scorecard.md) です。

## 1. 要点

**設問は短く、選択肢はサービス名が中心です。** 設問を長くすると、かえってこの資格の出題スタイルから離れます。長さは、次の表の範囲にとどめます。

| 項目 | 目安 |
| --- | --- |
| 設問文の文字数(複数選択の表記を除く) | 35〜125(満点)、25〜160(部分点) |
| 状況の文(問いより前の文)の数 | 0〜2 |
| 状況つきの設問の割合(束) | 80% 以下(状況の文が 1 文以上あるもの。設問が 1 文だけの束も通す) |
| 最長の選択肢の文字数 | 40 以内(満点)、60 以内(部分点)。サービス名(括弧つきの略称を含む正式名)の選択肢は数えない |
| 選択肢の最長÷最短 | 4 倍以内(満点)、6 倍以内(部分点)。サービス名の選択肢は数えない |
| 選択肢どうしの類似度(バイグラムの Dice) | 0.85 未満 |
| 複数選択の割合(束) | 60% 以下(複数選択がない束も通す) |
| 設問文の中央値(束) | 55〜100 字。90 パーセンタイルは 135 字以下 |
| 選択肢の形の割合(束) | 名称 30〜70%、語句 45% 以下、文 30% 以下 |
| 設問文の先頭 8 文字が同じものの割合(束) | 25% 以下 |

## 2. 難易度との対応(参考)

難易度とのおおまかな対応です。守る義務はありません。

| 難易度 | 書き方の傾向 |
| --- | --- |
| `easy` | 状況なし(または 1 文)。設問文は 35〜80 字。選択肢は名称が中心。単一選択が主 |
| `medium` / `hard` | 状況 1〜2 文と問い 1 文。設問文は 60〜125 字。概念を照合する設問では、文の選択肢を使ってよい。複数選択を 25〜35% まで |

## 3. 設問の型

| 型 | 特徴 |
| --- | --- |
| 状況型 | 「ある企業」「あなた」が目的と要件をもち、要件を満たすサービスや方法を問う。状況は 1〜2 文で、要件は「〜する必要があります」。1 文 1 要件。選択肢は名称が中心 |
| 概念照合型 | 「〜として正しい説明はどれか」「〜の特徴を選択」。サービス名や概念が主語。選択肢は文の形が増える。形(名称/語句/文)と句点を、1 問の中でそろえる |

## 4. 言い回し

| 位置 | 言い回し |
| --- | --- |
| 書き出し(状況型) | ある企業は〜/あなたは〜/あなたの会社は〜/A 社は〜 |
| 目的 | 〜したいと考えています/〜を予定しています/〜することになりました |
| 要件 | 〜する必要があります/この要件を満たす〜 |
| 問い(サービスを問う) | どの AWS サービスを使用すればよいでしょうか/どの AWS サービスまたは機能を〜 |
| 問い(概念を問う) | 〜として正しいものはどれでしょうか/〜を選択してください |
| 問い(複数) | 末尾に(2 つ選択)または(3 つ選択) |

## 5. 範囲の注意

- 設問は、サービスの細かい設定や数値ではなく、**サービスの役割の使い分け・責任の範囲・料金とサポートの考え方・設計原則の理解**を問います。
- 数値で答えが決まる設問は少なくします。数値を使うなら、答えを分けるときだけです。
- 誤答は、同じ分野の別のサービス(似た名前・隣り合う役割)から選びます。

## 6. 判定の基準

公開している問題を、**公開 / 非公開 / 書き直しで復帰できる**のどれにするかを決める基準です。判定と理由コードの共通の決まりは、[README](./README.md) の「判定の基準」にあります。基準は二層で、機械の観点は点数票が測り、LLM の観点は判定役(`question-judge`)が、次の文章に照らして判断します。

### 機械の観点

点数票の項目(A1〜A10、B1〜B7、S1〜S5)と、「1. 要点」の表の帯のとおりです。値は表にだけ置き、ここには重ねて書きません(食い違いを防ぐため)。合格点は、問題 1 問が 80 点、束が 70 点で、変えません。問題 1 問ごとの項目(A と B)で不合格になる問題(合格点に届かない、または止める項目に違反する問題)は、判定の依頼に「候補」として載ります(判定役は全件を判定します。束の項目 S は、候補には使いません)。

### LLM の観点

| ID | 観点 | この資格で見ること | 外れの例 |
| --- | --- | --- | --- |
| J1 | 設問の型 | 状況型(状況は短く、1 文 1 要件、選択肢は名称が中心)か、概念照合型(概念やサービスを主語に「正しいもの」を問う)のどちらかに収まる | サービスの細かい設定や数値で答えが決まる。状況が長く、要件が複数ある |
| J2 | 状況の自然さ | 「ある企業」の目的と要件が自然で、要件が答えを分けている | 要件が答えと関係ない。根拠のない数値や制約を足している |
| J3 | 選択肢の質 | 誤答が、同じ分野の別のサービス(似た名前・隣り合う役割)で、正答だけが要件を満たす | 誤答が別の分野で、一目で誤りと分かる。正答だけ形や長さが違う |
| J4 | 解説の整合 | 総合解説と選択肢ごとの解説が、設問と正解に食い違わず、誤答の理由が、その選択肢が誤りである理由になっている(出典との照合は検証役の仕事) | 解説が別の選択肢を正解として述べている。誤答の理由が設問に合わない |
| J5 | 一意性と範囲 | 正答(複数選択は個数も)が 1 つに決まり、役割の使い分け・責任の範囲・料金とサポート・設計原則の範囲に収まる | 条件次第で別の選択肢も正しくなる。試験の範囲外の論点を問う |
