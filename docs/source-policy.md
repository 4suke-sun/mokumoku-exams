# 出典と権利の方針

問題の根拠にする一次情報(試験ガイド、公式ドキュメントなど)の扱いを定めます。作問パイプライン(`packages/pipeline`)と、
問題データの出典(`references`)の両方に適用します。判断の理由は [ADR 0006](./app/adr/0006-source-ledger-and-rights.md) にあります。

## 1. 持つもの・持たないもの

リポジトリにコミットするのは、次のものだけです。

| 持つもの | 内容 |
| --- | --- |
| URL | `https://` の URL。許可したドメインのものだけ |
| 題 | 公式ページの `<title>`。短い文字列(URL を含めず、200 文字以内)。問題の出典の題に使う |
| 取得日 | 出典を確かめた日 |
| 本文のハッシュ | 出典の内容が変わったことを検出するための値 |
| 対象 | 資格・版・リージョン |
| 根拠にした主張の言い換え | 自分の言葉で書いた短い文(上限は「2. 言い換えと引用」) |
| 試験ガイドの対象サービスの一覧 | サービスの名前だけ(1 件 80 文字以内、300 件まで)。名前という事実の一覧で、引用として扱わない(「2. 言い換えと引用」) |
| 状態 | 有効、要確認、廃止など |

次のものは、コミットしません。

- 出典の本文(全文でも一部でも、長い写しは持たない)
- 取得した HTML・PDF・スクリーンショットなどの生データ(作業用の置き場 `pipeline-work/` に置く。gitignore 済み)
- 非公式の問題集、受験体験記、有料講座の内容
- 出題の所感(受験者が書いた、どう聞かれたかの記述)そのもの。問題の本文・選択肢・正答の写しや、固有の問題の再現を含む

本文らしい長い文章が、台帳などのデータ形式のファイルに入ったときは、コミット前・push 前の検査が止めます。

### 出題の傾向の蒸留

作問の採点(出題スタイルの指針、点数票の帯、判定の基準)を実際の出題に近づけるため、出題の所感を材料にしてよい場合があります。
持ってよいのは、**複数の所感や公式の例題に共通する出題のされ方を蒸留した指針**だけです。

- 置いてよい: 設問の型、状況の有無と長さ、選択肢の形、論点の分布(どの論点を多く出すかの重み)、誤答の作られ方の傾向を、抽象的な言葉で書いたもの。
  これらは書き方と出題の重みづけにだけ使う。問題の内容(事実の正誤)の根拠にはせず、根拠は、これまでどおり出典と事実カードだけにする。
  1 つの所感だけでは指針を変えず、複数で共通するものだけを反映する。
- 置かない: 所感そのもの、問題の本文・選択肢・正答、固有の問題の再現(長い写しを含む)。所感と材料は、手元(`.drafts/` など gitignore 済みの置き場)だけに置く。
- 指針の確からしさは、公式の例題と試験ガイドが先で、所感は補強にとどめる。公式と食い違うときは、公式を優先する。

## 2. 言い換えと引用

- 根拠は、**自分の言葉で言い換えて**書きます。出典の文の語順や言い回しをなぞりません。
- 言い換え 1 件の長さは、日本語で **200 文字以内**、英語で **35 語以内**にします。
- 直接の引用は、サービス名・機能名・API 名・設定値・数値の**表記を正しく示す必要があるときだけ**にします。
  1 件 **30 文字以内**(英語は 10 語以内)、1 つの出典あたり合計 **100 文字以内**です。引用符で示します。
- 設問文・選択肢・解説は、出典の文をそのまま使いません。事実を、問題の形に作り直します。
- 試験ガイドの対象サービスの一覧は、サービスの名前だけを並べた事実の一覧として持ちます。名前は言い換えられない固有の表記なので、
  引用として扱わず、引用の上限(1 件・出典あたりの合計)の対象にしません。名前のほかの文(説明、分類の見出しなど)は持ちません
  (台帳のスキーマが、名前の長さと文字を絞ります)。判断の理由は [ADR 0018](./app/adr/0018-exam-guide-service-list-and-targets.md) にあります。

上限の検査: 本文らしい長い文章(1 行 240 文字・英語 40 語を超えるものなど)は、コミット前・push 前の検査が止めます。
言い換えと引用の個別の上限は、出典の台帳のスキーマ(`packages/pipeline/src/collect/ledger.ts`)が機械検査します。
事実カードの台帳(`packages/pipeline/facts/`)には、アンカーの引用を残しません(引用は、取り込むときの照合にだけ使います。[事実カード](./fact-cards.md)、ADR 0017)。
抽出の出力は、作業用の置き場(gitignore 済み)にだけ置き、取り込みが終わると消します。この間の引用は、上の合計の上限の対象にしません(コミットにも公開にも残らないため)。

## 3. 出典にしてよいもの

出典にするのは、**許可したドメインの `https` の URL だけ**です。許可の一覧は
`packages/data-schema/src/exam-data/schema.ts` の `ALLOWED_REFERENCE_HOSTS` にあります([問題データの仕様](./data-spec.md) の「3.1 出典」)。

出典として使う前に、次を確かめます。**確かめられないものは、先へ進めません**。

1. 公式か。資格のベンダーなどが出している情報である。
2. 対象の資格・版・リージョンに該当するか。
3. 廃止・更新の兆候がないか(古い版の注記、移行の案内など)。
4. 日付が新しいか。更新日が分かるものは、取得日と合わせて記録する。
5. リンクが生きているか。

作問パイプラインは、この 5 つを機械検査します(合格・不合格・確認不能の 3 値。確認不能も先へ進めません)。
判定の基準と理由コードは、[一次情報の収集と台帳の運用](./source-collection.md)にあります。

## 4. 許可するドメインを追加する手順

資格を足すときなど、新しいドメインが必要になったときの手順です。判断するのは、リポジトリの管理者です。

1. 管理者が、そのドメインが**ベンダーなどの公式のもの**であることを確かめる(運営者の表示、公式サイトからのリンクなど)。
2. ホスト名を**完全一致**で決める。サブドメインは、別に足さない限り許さない。
3. `ALLOWED_REFERENCE_HOSTS` に足し、同じファイルの `REFERENCE_HOST_VENDORS` に、そのホストを出典にしてよい資格のベンダーを足す。
   [問題データの仕様](./data-spec.md) の「3.1 出典」の表にも足す([資格を追加する手順](./adding-an-exam.md))。
   データの検査と作問パイプラインの収集は、どちらもこの 1 か所を参照するので、ほかに足す場所はない。
4. `npm run validate:data` と `npm test` を通す。
5. 変更は、通常の PR で出す。レビューで、公式であることの確認結果を示す。

## 5. 禁止事項

- 出典の本文の長い写し(要約に見せかけた、語順をなぞる言い換えも含む)
- 非公式の問題集・ダンプ・有料講座の内容の転載や、それを根拠にした問題(「1. 持つもの・持たないもの」の「出題の傾向の蒸留」で許す、抽象的な指針は対象外)
- 許可していないドメインの URL を、出典として載せること
- 出典の URL を、設問文や解説の本文に書くこと(`references` にだけ書く)
- 取得した生データを、コミットすること
