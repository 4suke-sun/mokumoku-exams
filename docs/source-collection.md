# 一次情報の収集と台帳の運用

作問パイプラインの最初の段階(収集)の手順です。公式の一次情報を取得し、出典の台帳に記録し、根拠に使えるかを検査します。
出典の扱いの決まりは[出典と権利の方針](./source-policy.md)、判断の理由は ADR 0006・0007・0009 にあります。

## 1. 置き場所

| 場所 | 内容 | コミット |
| --- | --- | --- |
| `packages/pipeline/plans/<コード>.json` | 収集の計画(資格ごとに 1 つ) | する |
| `packages/pipeline/ledger/<コード>.json` | 出典の台帳(資格ごとに 1 つ) | する |
| `pipeline-work/cache/` | 取得した本文(本文のハッシュがファイル名) | しない |
| `pipeline-work/collect/<コード>/report.json` | 最後の実行の報告 | しない |
| `pipeline-work/guide/` | 試験ガイドの抽出の依頼と結果 | しない |
| `pipeline-work/candidates/<コード>/` | 出典の候補の依頼(`requests/`)、エージェントの出力(`out/`)、失敗の回数(`state.json`)、候補の一覧(`candidates.json`) | しない |

`<コード>` は、試験コードを英小文字にしたものです(例: `AWS-AIB-C01` なら `aws-aib-c01`)。
置き場所は `packages/pipeline/pipeline.config.json` で決まり、作業用の置き場は環境値 `PIPELINE_WORK_DIR` で変えられます。

**本文は、作業用の置き場(`pipeline-work/`)だけに置きます。** 台帳には、URL、取得日、本文のハッシュ、検査の結果、短い言い換えだけが入ります。
`pipeline-work/` は gitignore 済みで、その中のファイルや、台帳に入った本文らしい長い文章は、コミット前・push 前の検査が止めます。

## 2. 資格を新しく足すときの収集の手順

1. **許可ドメインを確かめる。** 収集する URL のホストが `ALLOWED_REFERENCE_HOSTS` にあり、`REFERENCE_HOST_VENDORS` で
   その資格のベンダーに対応していることを確かめます。なければ、[出典と権利の方針](./source-policy.md)の「4. 許可するドメインを追加する手順」で足します。
2. **計画ファイルを作る。** `packages/pipeline/plans/<コード>.json` に、次の形で書きます。

   ```json
   {
     "examCode": "EX-SMP-XX",
     "sources": [
       { "url": "https://docs.example.com/certification/guide.html", "kind": "exam-guide" },
       { "url": "https://docs.example.com/service/overview.html", "kind": "official-doc" }
     ],
     "guidePages": ["https://docs.example.com/certification/guide-domain1.html"],
     "scope": { "prefixes": ["https://docs.example.com/certification/", "https://docs.example.com/service/"], "maxDepth": 1 },
     "exclude": ["https://docs.example.com/service/archive/"],
     "regions": ["us-east-1"]
   }
   ```

   | 項目 | 意味 |
   | --- | --- |
   | `sources` | 収集を始める URL と種別(`exam-guide`・`official-doc`・`standard`)。試験ガイドは 1 つまで |
   | `guidePages` | 任意。試験ガイドの続きのページ(分野ごとの出題範囲など)。深さにかかわらず取得し、試験ガイドの抽出の材料に含める。`sources` の URL(試験ガイドを含む)と重ねない |
   | `scope.prefixes` | リンクをたどってよい URL の接頭辞。`sources` の URL も、どれかの接頭辞の中にあること |
   | `scope.maxDepth` | `sources` からリンクをたどる深さ(0〜3)。0 はたどらない |
   | `exclude` | たどらない URL の接頭辞。`sources` の URL と重ねない |
   | `regions` | 任意。対象のリージョン。台帳の出典に `target.region` があるとき、この中にないものを不合格にする |

   台帳の出典の種別は、収集のたびに計画から付けます。試験ガイド、`guidePages`、試験ガイドのページからリンクをたどって見つけた付属のページは `exam-guide`、
   それ以外(`official-doc`・`standard` として書いた URL と、そこからたどったページ)は、計画の種別か `official-doc` です。
   `exam-guide` の出典は、分野・配点・出題範囲・対象サービスの一覧の材料(台帳の `guide`)で、事実カードの抽出の対象にしません([事実カード](./fact-cards.md))。
   技術の事実の根拠には、サービスの文書を `official-doc` として `sources` に足します。

3. **計画を検査する。** 通信も書き込みもしません。

   ```sh
   npm run pipeline -- collect <試験コード> --dry-run
   ```

4. **収集する。**

   ```sh
   npm run pipeline -- collect <試験コード>
   ```

   計画の順に、取得、キャッシュへの保存、台帳の更新、検査を行います。1 回に取得する URL の数は、設定の `maxItemsPerRun` までです。
   上限に達したら「件数の上限」を出して止まるので、もう一度実行すると、続きから進みます(同じ日に取得済みのものは取り直しません)。

5. **試験ガイドを取り込む。** 試験ガイドが検査に合格すると、`pipeline-work/guide/<コード>.request.json` に抽出の依頼が書かれます。
   依頼には、試験ガイドの本文と、計画の `guidePages` の本文の場所が入ります(`guidePages` が 1 つでも検査に合格していなければ、
   依頼を出さず「試験ガイドの抽出の保留」を出します)。試験ガイドか `guidePages` のどれかの本文が、前に取り込んだときから変わると、依頼し直します。エージェントの定義(`.claude/agents/guide-extractor.md` の本文かモデル)が、取り込んだときから変わったときも、依頼し直します。
   依頼のファイルには、役の名前・モデルの ID・定義のハッシュ(`agent`)が書かれ、取り込んだ台帳の `guide.agent` にも同じ記録が残ります(指示の本文は残しません。記録のない古い取り込みは、同じ定義とみなします)。
   依頼のあとに定義が変わったときは、`--import-guide` は抽出を取り込まず、`試験ガイドの取り込みの停止: guide request-stale` で依頼と抽出を捨てます(`collect` を実行すると、依頼が作り直されます)。
   Claude Code で、エージェント `guide-extractor` に、その依頼のファイルを渡して抽出させます。抽出が書かれたら、取り込みます。

   ```sh
   npm run pipeline -- collect <試験コード> --import-guide
   ```

   CLI が、抽出の形、配点の合計(100%)、分野の番号の抜け、`guidePages` をすべて材料にしていること、本文の写しでないことを検査してから、
   台帳に取り込みます。
   試験ガイドは、分野・配点・出題範囲のほかに、試験の本番の値(出題数 `questionCount`、採点対象の問題数 `scoredQuestionCount`、試験時間 `timeMinutes`(分)、
   合格点 `passingScore`、満点 `totalScore`)も、ガイドが示すときだけ抽出します(示さない項目は、補わず、持たない)。取り込みは、これらの値の形だけを検査します
   (どれも正の整数。外れる値は `extract-invalid` で止まる。さらに、合格点は満点以下、採点対象の数は総数以下で、外れると `exam-values-invalid` で止まる)。数値は本文の写しではないので、写しの検査の対象にしません。
   台帳の `guide.exam` には、数値だけを持ちます。
   対象サービスの一覧(`services`)も、ガイドが示すときだけ、サービスの名前だけを抽出します(`guidePages` の対象サービスのページなど。対象外のサービスは入れない)。
   取り込みは、名前が重ならないこと(外れると `service-duplicate`)と、名前が試験ガイドか続きのページの本文に、空白をそろえてそのまま出ること(外れると `service-not-in-source`)を確かめます。
   名前は固有の表記なので、本文の写しの検査の対象にしません。名前の長さと文字は、形の検査で絞ります(外れると `extract-invalid`)。一覧が空なら、台帳に `guide.services` を持ちません。
   一覧は、出題計画の対象サービスの目標に使います([下書き](./drafting.md) の「2. 出題計画」)。

   取り込みのあと、資格マスタ(`data/exams.json`)との差分を `試験ガイドの差分` として報告します。差分を見たら、人がマスタを直すかを判断し、通常の PR で直します。
   **マスタは書き換えません。** 差分があっても、終了コードは 0 です(報告だけ)。

   | 報告 | 意味 |
   | --- | --- |
   | `マスタにない分野 <分野のコード>` / `ガイドにない分野 <分野のコード>` | 分野の有無の差分 |
   | `配点のずれ <分野のコード> ガイド <割合> マスタ <割合>` | 配点の差分(許容は 0.005) |
   | `出題数のずれ ガイド <値> マスタ <値>`、`試験時間のずれ …`、`合格点のずれ …`、`満点のずれ …` | ガイドとマスタの両方に値があり、食い違う |
   | `マスタにない項目 <項目> ガイド <値>` | ガイドが示す値を、マスタが持たない(準備中の資格など)。公開にするときに足す値の目安になる |

   本番の値の突き合わせは、ガイドが示した項目だけを対象にします。出題数は、ガイドの総数(`questionCount`)をマスタの `officialQuestionCount` と突き合わせます
   (本番モードは、受験者が実際に解く問題の数に合わせるため)。ガイドが採点対象の問題数を分けて示すときは、`情報` として値を報告するだけで、突き合わせません。

   **出典の候補を挙げる(任意)。** 試験ガイドが書くのは出題範囲(分野ごとの項目)で、問題の根拠にできる個々の事実ではありません。サービスや機能の公式の文書が台帳になければ、その項目の事実カードもできません。
   `facts <試験コード> --coverage` の「カバレッジの抜け」は、どの文書を足せば埋まるかを示さないので、出題範囲の項目ごとに、公式の文書を候補として挙げさせます。

   ```sh
   npm run pipeline -- collect <試験コード> --candidates          # 依頼を書く
   npm run pipeline -- collect <試験コード> --import-candidates   # エージェントが挙げた候補を検査して取り込む
   ```

   - 前提は、試験ガイドが台帳に取り込み済みであること(上の「試験ガイドを取り込む」)と、収集の計画があることです。
   - 依頼(`pipeline-work/candidates/<コード>/requests/<鍵>.json`)には、試験ガイドの出題範囲の項目(分野のコードと項目の番号と言い換えた文)、計画の今の `sources`、
     その資格のベンダーに許した出典のホスト、項目ごとの候補の数の上限(設定の `candidates.maxPerItem`)を載せます。**取得した本文は載せません。**
   - エージェント `source-scout`(モデルは [ADR 0016](./app/adr/0016-pipeline-source-scout-role.md) の表)に、依頼のファイルを渡します。エージェントは、自分の知識で文書の URL を挙げ、選んだ理由を短い言い換えで添えます。
     読むのは依頼のファイルだけ、書くのは出力先の 1 ファイルだけで、外部へ通信しません。存在が確かな文書だけを挙げる決まりです。
   - 取り込みは、候補の URL を検査します。**https で形が正しく、このベンダーに許したホストで、計画の `sources` になく、同じ項目の中で重複しないもの**だけが残ります。
     落とした候補は、理由コード(`not-https`・`malformed`・`userinfo`・`port`・`query`・`host-not-allowed`・`already-in-plan`・`duplicate` など)の件数だけを `候補の不採用` として報告します(URL は出しません)。
     依頼にない項目、同じ項目の重複、項目ごとの上限の超過、形の違う出力は、`output-invalid`(設定の `candidates.maxAttempts` まで出し直す)で取り込みません。
   - 結果は、`pipeline-work/candidates/<コード>/candidates.json`(コミットしない)に、項目ごとの候補の一覧として書きます。報告は、`候補: <分野のコード> 項目 <番号> 候補 <件数> 件`、候補のない項目(`候補のない項目: <分野のコード> 項目 <番号>`。`facts --coverage` と同じ書式)、落とした候補の件数(`候補の不採用`)、合計の `情報` の行で、項目の文や本文、URL は出しません。
   - **候補は提案にとどまり、計画には自動で入りません。** 人が一覧を見て、使う URL を計画の `sources` と `scope.prefixes` に足します。足したあとの `collect` が、既存の 5 つの検査(公式か、対象か、廃止の兆候、日付、リンク)を、候補だった URL にも適用します。
     エージェントが挙げた URL は、存在しないものが混ざりうるので、取得して初めて分かります(取得できなければ、取得の失敗として報告され、その出典は使われません)。
   - 依頼の鍵は、出題範囲の項目、計画の `sources`、許可したホストの一覧、項目ごとの上限(`candidates.maxPerItem`)、依頼の版、エージェントの定義のハッシュから決まります。
     どれかが変わると鍵が変わり、古い依頼の出力は取り込まず(`request-stale`)、依頼を作り直します。

6. **台帳をコミットする。** 台帳と計画と、人の判断の記録(`packages/pipeline/decisions/`。書いたときだけ)だけをコミットします(`/dev-commit`)。`pipeline-work/` の中身はコミットしません。

## 3. 取得の決まり

- https で、許可したドメインの URL だけを取得します。リダイレクトのたびに、行き先を確かめ直します。
- 同じホストへは、1 本ずつ、2 秒の間隔を空けて取得します。全体の同時の取得は 4 本までです(設定の `fetch`)。
- robots.txt に従います。取得の主体は、User-Agent の製品名 `mokumoku-exams-pipeline` で示します。robots.txt が取得できない(5xx・通信の失敗)ときは、
  そのホストからは取得しません。
- 本文の大きさ、タイムアウト、リダイレクトの回数に、上限があります(設定の `fetch`)。

## 4. 出典の検査

取得のたびに、出典ごとに 5 つの検査を行い、結果(合格 `pass`・不合格 `fail`・確認不能 `unknown`)と理由コードを台帳に書きます。
**状態が `active` の出典だけが、先の段階の根拠に使えます。** 確認不能も、不合格と同じく止めます。

| 検査 | 合格の条件 |
| --- | --- |
| `official`(公式か) | URL(リダイレクトの後も)が許可ドメインにあり、`REFERENCE_HOST_VENDORS` でそのホストが資格のベンダーに対応している |
| `target`(対象か) | 資格が計画の資格と同じで、版が資格マスタの `edition` と同じ。出典に `target.region` があり、計画に `regions` があれば、その中のリージョン |
| `deprecation`(廃止の兆候) | ページ全体の廃止・アーカイブ・試験の退役を示す言い回しがなく、410 でない。ページの中の機能の非推奨の記述には反応しない |
| `freshness`(日付) | 出典が示す更新日(meta・time 要素・Last-Modified)が 365 日以内(設定の `checks.freshnessDays`)。更新日を示さない出典は、取得日で代えて合格 |
| `liveness`(リンク) | 取得できた |

状態は、検査の結果から次のように決まります。

| 状態 | 条件 |
| --- | --- |
| `active` | すべて合格 |
| `deprecated` | `deprecation` が不合格 |
| `unreachable` | `liveness` が合格でない |
| `needs-review` | ほかの不合格・確認不能 |

日付が古い(`stale`)だけで不合格の出典は、[人の判断の記録](./human-decisions.md)に同じ本文のハッシュで受け入れ(`accept`)があれば、`active` にします。
検査の記録は不合格のまま残し、受け入れたことは判断の記録が持ちます。本文が変わると、受け入れは効かなくなります。

## 5. 出典の本文が変わったときの再検証

- 取得した本文のハッシュが、台帳の前回のハッシュと違うと、「出典の変化」として報告します(URL、前回と今回の取得日、状態だけ)。
- 変わった出典を根拠にしている事実カードに、「再検証が必要」の印を付けます(台帳の `recheck.facts`)。
  事実カードは、事実カードの台帳(`packages/pipeline/facts/<コード>.json`)の根拠の出典から、不採用でないカードを洗い出します。
- 来歴(`packages/pipeline/provenance/<コード>.json`)をたどり、印の付いた事実カードを根拠にした下書き・問題の件数を報告します(「再検証の印」)。
  下書き・問題には印を持たせません。来歴の検査(`draft <試験コード> --check`)が、来歴と台帳の今の状態を比べて、検査のたびに止めます。
- 取得できなかった出典は、「変化」ではなく「確認できない出典」として別に報告し、終了コード 1 で終わります。印は付けませんが、出典の状態が
  `active` でなくなるので、その出典を根拠にした事実カード・下書き・問題は、次に取得できて `active` に戻るまで、先の段階へ進めません(印が残り続けることはありません)。
- 先の段階は、次のものを止めます([出題計画と下書きの手順](./drafting.md))。
  - 下書きの依頼: 印のある事実カードと、根拠の出典が `active` でないか本文が変わった事実カードを、根拠の候補にしません。
  - 下書きの取り込み: 依頼のあとに、根拠の事実カードが上の状態になった出力は取り込まず、依頼を作り直します(`request-stale`)。
  - 来歴の検査: 原因ごとの理由コードで失敗にします。書き出しは、この検査を通ったものだけを対象にします。

  | 理由コード | 原因 |
  | --- | --- |
  | `recheck-fact` | 根拠の事実カードに、再検証の印がある |
  | `recheck-question` | 書き出した問題に、再検証の印がある(台帳の `recheck.questions`) |
  | `source-changed` | 根拠の出典の本文が、来歴を作ったときから変わった |
  | `source-check-<検査の名前>` | 根拠の出典が `active` でない。合格しなかった検査ごと(`official`・`target`・`deprecation`・`freshness`・`liveness`) |
  | `source-<状態>` | 根拠の出典が `active` でなく、合格しなかった検査の記録がない |
  | `source-not-in-ledger` | 根拠の出典が台帳にない |

- 再検証は、変わった出典を読み直し、事実カードと問題を確かめ直すことです。事実カードは、その出典の抽出をやり直して取り込むと、
  古いカードが新しい抽出に置き換わり、印が外れます([事実カードの作法と運用手順](./fact-cards.md)の「5. 出典が変わったとき」)。
  下書き・問題は、根拠の事実カードの印が外れ、出典が `active` で、来歴の本文のハッシュが台帳と一致すれば、来歴の検査を通ります(人の操作は要りません)。
  出典の本文が変わった下書きは、新しい事実カードを根拠に、下書きを作り直します。

## 6. 止まったときの対処

報告は、種類と場所(項目のパス、URL)と理由コードだけを出します。本文は出しません。

### 計画の誤り(`計画の誤り: <場所> <理由コード>`)

| 理由コード | 原因 | 直し方 |
| --- | --- | --- |
| `plan-not-found` | 計画ファイルがない | `packages/pipeline/plans/<コード>.json` を作る |
| `invalid-json` / `schema` | JSON の形・項目の誤り | 「2. 資格を新しく足すときの収集の手順」の形に合わせる |
| `exam-code-mismatch` | 中の `examCode` が、指定した資格と違う | ファイル名と `examCode` を合わせる |
| `not-https` / `malformed` / `userinfo` / `port` / `query` / `fragment` | URL の形が出典に使えない | `https://` の、ユーザー情報・既定以外のポート・クエリ文字列・フラグメントのない URL にする(クエリを持つページは、計画の候補にもリダイレクト先にもできない) |
| `host-not-allowed` | 許可ドメインにない | 許可ドメインの追加の手順を経るか、URL を外す |
| `out-of-scope` | 収集を始める URL・`guidePages` が、どの接頭辞の中にもない | `scope.prefixes` を足すか、URL を直す |
| `excluded-listed` | 収集を始める URL・`guidePages` が、除外に当たる | 一覧か除外の一方を直す |
| `duplicate` | 同じ URL・接頭辞の重複。`guidePages` と `sources`(試験ガイドを含む)の重複 | 重複を消す |
| `multiple-exam-guides` | 試験ガイドが 2 つ以上 | 1 つにする |
| `no-exam-guide` | `guidePages` があるのに、試験ガイドがない | 試験ガイドを `sources` に足すか、`guidePages` を外す |

### 取得の失敗(`取得: <URL> <状態> <理由コード>`)

| 理由コード | 原因 | 直し方 |
| --- | --- | --- |
| `not-allowed` | リダイレクト先が許可外・https でない | 計画の URL を、リダイレクト後の公式の URL に直す |
| `robots-disallowed` | robots.txt が禁止している | 取得しない。計画から外すか、別の公式の資料にする |
| `robots-unreachable` | robots.txt が取得できない | 時間をおいて再実行する |
| `timeout` / `network-error` | 応答がない・通信の失敗 | 時間をおいて再実行する |
| `too-large` | 本文が大きさの上限を超えた | 対象を絞る(上限は、必要なときだけ設定で上げる) |
| `too-many-redirects` | リダイレクトが多すぎる | 最終の URL を計画に書く |
| `http-error` | 4xx・5xx | 404・410 はリンク切れ。URL を直すか外す。5xx は再実行する |

### 出典の検査(`出典の検査: <URL> <検査> <結果> <理由コード>`)

| 理由コード | 原因 | 直し方 |
| --- | --- | --- |
| `host-not-allowed` / `vendor-mismatch` | 公式と確かめられない | 資格のベンダーの公式の資料にする。対応表に足すなら、許可ドメインの追加の手順で |
| `exam-not-in-master` | 資格マスタにない | 資格マスタに資格を足す |
| `exam-mismatch` / `edition-mismatch` / `edition-unknown` | 版が合わない・マスタに版がない | 資格マスタの `edition` を確かめる。版が変わったなら、計画と資料を新しい版に合わせる |
| `region-mismatch` | 対象外のリージョン | 計画の `regions` か、資料を直す |
| `deprecation-signal` / `gone` | 廃止・アーカイブ・退役の兆候 | 後継の資料に差し替える |
| `stale` | 更新日が古い | 新しい資料に差し替える。古くても正しいと人が確かめたものは、[人の判断の記録](./human-decisions.md)に本文のハッシュつきで `accept` を書く(本文が変わるまで、根拠に使える) |
| `future-date` / `invalid-date` | 更新日が読めない | 資料を確かめる |
| `no-body` | 本文が取れず検査できない | 取得の失敗を先に直す |
| `dead-link` / `redirect-not-allowed` | リンク切れ・許可外へのリダイレクト | URL を直すか外す |

### 試験ガイドの取り込みの停止(`試験ガイドの取り込みの停止: <理由コード>`)

| 理由コード | 原因 | 直し方 |
| --- | --- | --- |
| `extract-not-found` / `extract-invalid` | 抽出のファイルがない・形が違う | エージェントに抽出をやり直させる |
| `exam-mismatch` / `source-not-in-ledger` | 依頼と違う資格・出典の抽出 | 依頼のファイルを渡し直す |
| `source-not-active` | 試験ガイドか `guidePages` が検査に合格していない | 出典の検査の失敗を先に直す |
| `page-mismatch` | 抽出の `pages` が、計画の `guidePages` と合わない | 依頼を出し直して(収集をやり直す)、抽出をやり直させる |
| `source-hash-mismatch` / `body-not-cached` | 抽出のもとの本文が、台帳の最新と違う・キャッシュにない | 収集をやり直してから、抽出をやり直させる |
| `domain-numbering` | 分野の番号に抜けや重複がある | 抽出をやり直させる |
| `weight-sum-mismatch` | 配点の合計が 100% にならない | 試験ガイドを確かめ、抽出をやり直させる |
| `exam-values-invalid` | 合格点が満点を超える、採点対象の問題数が総数を超える | 試験ガイドを確かめ、抽出をやり直させる |
| `verbatim-copy` | 言い換えが本文の写しになっている | 自分の言葉で言い換えるよう、抽出をやり直させる |
| `service-duplicate` | 対象サービスの一覧に、同じ名前が重なっている | 抽出をやり直させる |
| `service-not-in-source` | 対象サービスの名前が、試験ガイドと続きのページの本文に、そのまま出ない | 名前を本文の表記のまま書くよう、抽出をやり直させる(言い換えた名前、分類の見出し、対象外のサービスを入れない) |
| `guide request-invalid` | 依頼のファイルが壊れている | 依頼のファイルを消し、`collect` を実行して依頼を作り直す |
| `guide request-stale` | 依頼のあとに(または`agent` の記録がない古い依頼のとき)定義が変わった | `collect` を実行して依頼を作り直し、抽出をやり直させる |

### 出典の候補の取り込みの停止(`候補の取り込みの停止: <鍵> <理由コード>`)

| 理由コード | 原因 | 直し方 |
| --- | --- | --- |
| `output-invalid` | 出力の形が違う、依頼にない項目、同じ項目の重複、項目ごとの上限の超過 | 理由を伝えて、同じエージェントに書き直させる(出力は消える。`candidates.maxAttempts` まで) |
| `request-mismatch` | 出力の資格や鍵が依頼と違う | 依頼のファイルを渡し直して、書き直させる |
| `request-invalid` | 依頼のファイルが壊れている | 依頼のファイルを消して、`collect <試験コード> --candidates` で作り直す |
| `request-stale` | 依頼のあとに、計画・試験ガイド・エージェントの定義などが変わった | `--candidates` で依頼を作り直す(失敗の回数には数えない) |
| `再試行の上限: candidates max-attempts` | 同じ依頼の出し直しが上限に達した | 原因(エージェントの指示、依頼の内容)を直す |

`候補の出力なし: <鍵>` は、出力がまだ書かれていないだけです(エージェントの完了を待つ)。

### そのほか

| 表示 | 原因 | 直し方 |
| --- | --- | --- |
| `件数の上限` | 1 回の取得の数が `maxItemsPerRun` に達した | もう一度実行する(続きから進む) |
| `台帳の誤り: <場所>` | 台帳がスキーマに合わない | 場所の項目を直す。言い換え・引用の長さの上限は[出典と権利の方針](./source-policy.md)の「2」 |
| `資格マスタの誤り` | `data/exams.json` が読めない | `npm run validate:data` で確かめる |

| 2 | 入力の誤り(資格コードの形、資格マスタにない資格) |
