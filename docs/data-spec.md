# 問題データの仕様

資格マスタ(`exams.json`)と問題データ(`questions.<コード>.json`)の形を定めます。アプリの実装には依存せず、
**この仕様に従っていれば、表示・採点・分野別の分析ができる**ことを目標にします。

スキーマの正本は `scripts/lib/exam-data/schema.ts`(Zod)で、この文書は、その意味を説明します。
検査は `npm run validate:data` で行います(CI でも実行します)。

## 1. ファイル

データは `data/` に置きます。

| ファイル | 役割 | 必須 |
| --- | --- | --- |
| `exams.json` | 資格マスタ | 必須 |
| `questions.<コード>.json` | 資格ごとの問題。`<コード>` は資格コードの英小文字 | 公開中の資格に必須 |
| `help.json` | 使い方ページの内容(「10. 使い方ページのデータ」) | 必須 |
| `curriculum.<コード>.json` | 学習モードの単元と本文(「11. カリキュラムのデータ」)。ない資格は、学習モードを使えない | 任意 |

次の付随ファイルは、それぞれの機能の Issue で、形を定めます。この文書の対象外です。

| ファイル | 役割 |
| --- | --- |
| `summary.<コード>.json` | 直前チェック用の要約 |
| `freeform.<コード>.json` | 自由記述の問題と、判定の観点 |

## 2. 資格マスタ `exams.json`

```jsonc
{
  "exams": [
    {
      "examCode": "SAMPLE",           // 英大文字で始まる英大文字と数字(2〜16 文字)。一意
      "status": "published",          // "published"(公開中)| "coming-soon"(近日公開)
      "vendor": "Example",            // 提供元。一覧のグループ分けに使う
      "edition": "S01",               // 試験の版
      "name": "サンプル資格",
      "shortName": "サンプル",
      "category": "Foundational",     // 自由な文字列(区分)
      "passingScore": 70,             // 合格点
      "totalScore": 100,              // 満点(合格点 ≤ 満点)
      "officialQuestionCount": 5,     // 本番モードの出題数
      "officialTimeMinutes": 10,      // 本番モードの制限時間(分)
      "domains": [
        { "code": "domain1", "name": "基礎の用語", "weight": 0.6 },
        { "code": "domain2", "name": "考え方", "weight": 0.4 }
      ]
    },
    {
      "examCode": "SAMPLE2",
      "status": "coming-soon",
      "vendor": "Example",
      "name": "サンプル資格 2",
      "shortName": "サンプル 2",
      "note": "近日公開予定です。"        // 任意。一覧に添える文言
    }
  ]
}
```

- **公開中**(`published`)の資格は、上の項目がすべて必要です。問題データのファイルも必要です。
- **近日公開**(`coming-soon`)の資格は、`examCode`・`vendor`・`name`・`shortName` と、任意の `note` だけを持ちます。
  一覧に表示するだけで、問題データは持ちません。
- 分野は `domain1`〜`domainN` のコードで表します。**表示名はマスタ側にだけ**置きます(問題側に名前を書くと、
  表記のゆれで集計が崩れるためです)。分野の数は、資格ごとに異なります。
- `weight` は公式の配点を小数にした値で、合計は 1(許容誤差 0.005)です。

## 3. 問題 `questions.<コード>.json`

```jsonc
{
  "examCode": "SAMPLE",
  "questions": [
    {
      "questionId": "SAMPLE-0001",     // <資格コード>-<4 桁の連番>。一意。削除しても再利用しない
      "examCode": "SAMPLE",
      "domain": "domain1",             // マスタの分野のコード
      "questionType": "single",        // "single"(択一)| "multiple"(複数選択)
      "difficulty": "easy",            // 任意: "easy" | "medium" | "hard"
      "questionText": "設問文",
      "choices": [
        { "key": "A", "text": "選択肢", "explanation": "選択肢ごとの解説(任意)" },
        { "key": "B", "text": "選択肢" }
      ],
      "correctAnswers": ["B"],         // 常に配列。択一でも 1 要素の配列
      "explanation": "総合解説",
      "supplement": "補足(任意)",
      "references": [{ "title": "参考資料", "url": "https://example.com/" }],  // 任意
      "tags": ["任意のタグ"]            // 任意
    }
  ]
}
```

| 必須 | 任意 |
| --- | --- |
| `questionId`、`examCode`、`domain`、`questionType`、`questionText`、`choices`(各 `key`・`text`)、`correctAnswers`、`explanation` | `difficulty`、`choices[].explanation`、`supplement`、`references`、`tags` |

- 選択肢は 2〜10 個です。
- 項目の名前の綴りを誤ると(未知の項目)、検査が失敗します。

## 4. 機械検査する規則

`npm run validate:data` が、次を検査します。報告は、ファイル名・項目の位置・問題の ID と、規則の種類だけです(設問文や選択肢の本文は出しません)。

**1 つの問題の中**

1. `choices[].key` は、`A` から連番で、重複しない。
2. `correctAnswers` は空でなく、重複せず、すべて `choices[].key` の中にある。
3. `questionType` は正解の数と一致する(1 つなら `single`、2 つ以上なら `multiple`)。
4. 同じ文言の選択肢がない(空白と全角・半角の違いをならして比べる)。
5. `references[].url` は、`http://` か `https://` で始まる。

**1 つのファイルの中**

6. `questionId` は重複しない。接頭辞は、ファイルの資格コードと一致する。
7. 同じ設問文の問題がない(空白と全角・半角の違いをならして比べる)。
8. 各問題の `examCode` は、ファイルの `examCode` と一致する。

**ファイルをまたぐ**

9. 各問題の `domain` は、資格マスタの分野のコードにある。
10. 公開中の資格には、問題データのファイルがある。問題データは、資格マスタにある公開中の資格のものだけ。
11. 問題数は、本番モードの出題数(`officialQuestionCount`)以上。
12. ファイル名のコードと、ファイルの `examCode` が一致する。

**資格マスタ**

13. `examCode` は重複しない。
14. 合格点は満点以下。分野のコードは重複せず、重みの合計は 1(許容誤差 0.005)。

## 5. 採点の考え方

- 演習の得点は、**正答数 ÷ 出題数 × 100(%)** で、全資格に共通です。分野の重みは、採点には使いません
  (出題に含まれない分野が 0 点になり、全問正解でも満点にならないため)。
- 合格ラインは、`passingScore / totalScore` を割合にして比べます(700/1000 も 70/100 も 70%)。
- 分野の重みは、ダッシュボードの合格予測にだけ使います。

## 6. 文字の書き方

設問文・選択肢・解説は、次の限定した記法だけが解釈されます。これ以外の Markdown の記法や HTML は、書いても文字がそのまま表示されます。

| 書き方 | 表示 | 使える場所 |
| --- | --- | --- |
| 空行 | 段落の区切り(段落の中の改行は、そのまま改行になる) | すべて |
| `**太字**` | 太字 | すべて |
| `` `コード` `` | 文中のコード | すべて |
| 行頭の `- ` | 箇条書き | 設問文・解説・補足・使い方の本文 |
| 行頭の `## ` | 小見出し | 設問文・解説・補足・使い方の本文 |
| 行頭が ``` の行で囲んだ範囲 | コードのブロック(中の記法は解釈しない) | 設問文・解説・補足・使い方の本文 |

カリキュラムの節の本文(「11. カリキュラムのデータ」)は、使い方の本文と同じく、上の表のすべての記法が使えます。

選択肢の本文と、選択肢ごとの解説(`explanation`)は、1 つの流れの中に入れるため、`**太字**`・`` `コード` ``・改行だけが使えます。

## 7. ID の運用

- `questionId` は永続です。問題を削除しても、番号を詰めません(受験履歴・ブックマーク・復習が ID を参照するため)。
- 資格の試験の版が変わったら、`edition` を更新します。分野の再配置が必要なら、新しい資格コードで扱います。分野の重みだけの変更は、マスタの更新で済みます。

## 8. 自由記述

自由記述は、選択肢のない、**学習者向けのモード**です。本番モードの出題には含めません。
問題と、判定の観点の形は、別の Issue で定めます(`freeform.<コード>.json`)。

## 9. サンプルデータ

`data/` の `SAMPLE`(公開中)と `SAMPLE2`(近日公開)は、動作確認用の架空の資格です。実在の試験の問題は含みません。
`SAMPLE` のカリキュラム(`curriculum.sample.json`)も、動作確認用の架空の教材です。
実データを追加するときは、そのつど、扱いを決めます。

## 10. 使い方ページのデータ `help.json`

使い方ページの内容です。スキーマの正本は `scripts/lib/help-data/schema.ts` で、`npm run validate:data` が検査します。

```json
{
  "sections": [
    {
      "id": "start",
      "title": "はじめに",
      "body": "本文(「6. 文字の書き方」の記法が使えます)",
      "links": [{ "label": "資格を選ぶ", "href": "/exams" }]
    }
  ]
}
```

| 項目 | 型 | 必須 | 規則 |
| --- | --- | --- | --- |
| `sections` | 配列 | 必須 | 1〜30 件。表示は、この順 |
| `sections[].id` | 文字列 | 必須 | 英小文字・数字・ハイフンで、英字から始まる 32 文字以内。重複不可。目次のリンク(`#id`)になる |
| `sections[].title` | 文字列 | 必須 | 空白だけは不可。80 文字以内 |
| `sections[].body` | 文字列 | 必須 | 空白だけは不可。4000 文字以内 |
| `sections[].links` | 配列 | 任意 | 10 件まで。`label`(60 文字以内)と `href` を持つ |

リンク先(`href`)は、次のどちらかです。

- アプリ内のパス(`/` で始まる)。画面ができているページ(ナビゲーションで「近日公開」でないもの)か、公開中の資格のページ(`/exams/<資格コード>`)だけを指せます。ないページへのリンクは、検査で失敗します。
- `https://` で始まる URL。外部サイトは、新しいタブで開きます。`http://` や `javascript:` は使えません。

## 11. カリキュラムのデータ `curriculum.<コード>.json`

学習モードで読む単元と、単元ごとに解く問題です。`<コード>` は資格コードの英小文字です。
スキーマの正本は `scripts/lib/curriculum-data/schema.ts` で、`npm run validate:data` が検査します。

```json
{
  "examCode": "SAMPLE",
  "units": [
    {
      "id": "basics",
      "title": "基礎の用語",
      "order": 1,
      "sections": [
        { "id": "intro", "title": "はじめに", "body": "本文(「6. 文字の書き方」の記法が使えます)" }
      ],
      "questionIds": ["SAMPLE-0001", "SAMPLE-0002"]
    }
  ]
}
```

| 項目 | 型 | 必須 | 規則 |
| --- | --- | --- | --- |
| `examCode` | 文字列 | 必須 | ファイル名のコードと一致する、公開中の資格のコード |
| `units` | 配列 | 必須 | 1〜100 件。表示は `order` の小さい順 |
| `units[].id` | 文字列 | 必須 | 英小文字・数字・ハイフンで、英字から始まる 32 文字以内。ファイルの中で重複不可。画面の URL(`/exams/<資格コード>/study/<id>`)になる |
| `units[].title` | 文字列 | 必須 | 空白だけは不可。80 文字以内 |
| `units[].order` | 整数 | 必須 | 1 以上。ファイルの中で重複不可 |
| `units[].sections` | 配列 | 必須 | 1〜50 件。表示は、この順 |
| `units[].sections[].id` | 文字列 | 必須 | `units[].id` と同じ形。単元の中で重複不可 |
| `units[].sections[].title` | 文字列 | 必須 | 空白だけは不可。80 文字以内 |
| `units[].sections[].body` | 文字列 | 必須 | 空白だけは不可。10000 文字以内 |
| `units[].sections[].diagram` | オブジェクト | 任意 | 節の図解。本文のあとに描く。形は下の「図解」 |
| `units[].questionIds` | 配列 | 必須 | 1〜500 件。「この単元の問題を解く」で、この順に出題する。単元の中で重複不可 |

- `questionIds` の各 ID は、同じ資格の問題データ(`questions.<コード>.json`)にある問題です。ない問題や、別の資格の問題を指すと、検査が失敗します。
- 1 つの問題を、複数の単元に関連づけてかまいません。
- 項目の名前の綴りを誤ると(未知の項目)、検査が失敗します。
- 近日公開の資格や、資格マスタにない資格のカリキュラムは置けません。

### 図解 `diagram`

箱(ノード)と矢印(辺)の図です。座標は書きません。画面が、矢印の向きに沿って箱を上から下へ段に並べ、
矢印のラベルを、ほかのラベルや箱と重ならない位置に置きます。

```json
{
  "title": "物事を進める流れ",
  "nodes": [
    { "id": "goal", "label": "目的を決める" },
    { "id": "do", "label": "進める" }
  ],
  "edges": [{ "from": "goal", "to": "do", "label": "次に" }]
}
```

| 項目 | 型 | 必須 | 規則 |
| --- | --- | --- | --- |
| `title` | 文字列 | 必須 | 空白だけは不可。80 文字以内。図の下に出し、読み上げでは図の名前になる |
| `nodes` | 配列 | 必須 | 2〜20 件。同じ段の中では、おおむねこの順に左から並べる |
| `nodes[].id` | 文字列 | 必須 | `units[].id` と同じ形。図の中で重複不可 |
| `nodes[].label` | 文字列 | 必須 | 空白だけは不可。20 文字以内。箱の中の文字 |
| `edges` | 配列 | 必須 | 1〜40 件。`from` の箱から `to` の箱への矢印 |
| `edges[].from` / `edges[].to` | 文字列 | 必須 | `nodes[].id` のどれか。同じ箱どうしは不可 |
| `edges[].label` | 文字列 | 任意 | 空白だけは不可。12 文字以内。矢印に添える文字 |

- 同じ向きの矢印(`from` と `to` の組)は、図の中で重複できません。逆向きの矢印を足すと、一周して戻る形になるため置けません。
- 矢印をたどって元の箱に戻れる形(閉路)は、段に並べられないため、検査が失敗します。
- 読み上げでは、図の名前に続けて、矢印ごとに「「元の箱」から「先の箱」へ(ラベル)」を読みます。
- 段を 2 つ以上飛ばす矢印は、間の段の箱の上を通ることがあります。図が込み入るときは、図を分けます。
