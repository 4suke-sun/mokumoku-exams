# 問題データの仕様

資格マスタ(`exams.json`)と問題データ(`questions.<コード>.json`)の形を定めます。アプリの実装には依存せず、
**この仕様に従っていれば、表示・採点・分野別の分析ができる**ことを目標にします。

スキーマの正本は `packages/data-schema/src/exam-data/schema.ts`(Zod)で、この文書は、その意味を説明します。
検査は `npm run validate:data` で行います(CI でも実行します)。
資格を追加する順番とファイルの置き場所は、[資格を追加する手順](./adding-an-exam.md) にまとめています。

## 1. ファイル

データは `data/` に置きます。

| ファイル | 役割 | 必須 |
| --- | --- | --- |
| `exams.json` | 資格マスタ | 必須 |
| `questions.<コード>.json` | 資格ごとの問題。`<コード>` は資格コードの英小文字 | 公開中の資格に必須 |
| `help.json` | 使い方ページの内容(「10. 使い方ページのデータ」) | 必須 |
| `curriculum.<コード>.json` | 学習モードの単元と本文(「11. カリキュラムのデータ」)。ない資格は、学習モードを使えない | 任意 |
| `summary.<コード>.json` | 直前チェックの要約カード(「12. 要約カードのデータ」)。ない資格は、要約カードの入口を出さない | 任意 |
| `unpublished.<コード>.json` | 非公開にした問題(「13. 非公開の問題」)。アプリは読まず、配信に含まれない | 任意 |

## 2. 資格マスタ `exams.json`

```jsonc
{
  "exams": [
    {
      "examCode": "EX-SMP-XX",        // 試験コード `<ベンダー略称>-<試験略称>-<版>`(下の「試験コード」)。一意
      "idPrefix": "SAMPLE",           // 公開中は必須。問題 ID の接頭辞(問題 ID は `<接頭辞>-<4 桁の連番>`)。資格どうしで重複しない
      "retiredQuestionIds": [],       // 任意(公開中だけ)。削除した問題の ID。再び使わない
      "previousCodes": ["SAMPLE"],    // 任意。以前の試験コード(旧コードの URL を転送し、保存済みの記録を移すために使う)
      "status": "published",          // "published"(公開中)| "coming-soon"(近日公開)
      "vendor": "Example",            // 提供元。一覧のグループ分けに使う
      "edition": "S01",               // 試験の版
      "name": "サンプル資格",
      "shortName": "サンプル",
      "level": "Foundational",        // 任意。レベル(下の一覧)。一覧で、ベンダーの中をこの順に並べる
      "abbr": "SMP",                  // 任意。一覧のタイルに出す短い表記(英数字 1〜4 文字)
      "category": "Sample",           // 自由な文字列(区分。資格の領域。レベルとは別)
      "passingScore": 70,             // 合格点
      "totalScore": 100,              // 満点(合格点 ≤ 満点)
      "officialQuestionCount": 5,     // 本番モードの出題数(選択式のすべての問題から、ランダムにこの数を選ぶ。自由記述は出題しない)
      "officialTimeMinutes": 10,      // 本番モードの制限時間(分)。過ぎると、そこまでの回答で採点する
      "domains": [
        { "code": "domain1", "name": "基礎の用語", "weight": 0.6 },
        { "code": "domain2", "name": "考え方", "weight": 0.4 }
      ],
      "info": {                       // 任意。情報ページに出す項目(下の「資格の情報」)
        "checkedAt": "2026-10-12",    // 公式の情報を確認した日(info を持つなら必須)
        "format": "択一選択式と複数選択式",
        "languages": ["日本語"]
      }
    },
    {
      "examCode": "EX-SM2-XX",
      "previousCodes": ["SAMPLE2"],
      "status": "coming-soon",
      "vendor": "Example",
      "name": "サンプル資格 2",
      "shortName": "サンプル 2",
      "level": "Associate",
      "abbr": "SM2",
      "note": "近日公開予定です。",       // 任意。一覧に添える文言
      "edition": "S02",                  // 任意。作問パイプラインに通すときに持たせる(下の説明)
      "officialQuestionCount": 65,       // 任意。同上
      "idPrefix": "SAMPLE2",             // 任意。同上
      "domains": [                       // 任意。同上
        { "code": "domain1", "name": "分野 1", "weight": 0.6 },
        { "code": "domain2", "name": "分野 2", "weight": 0.4 }
      ]
    }
  ]
}
```

### 試験コード

試験コード(`examCode`)は、`<ベンダー略称>-<試験略称>-<版>` の形で、すべて大文字と数字です(正規表現: `^[A-Z][A-Z0-9]{1,5}-[A-Z][A-Z0-9]{1,9}-[A-Z0-9]{2,4}$`)。
例: AWS Certified AI Business Strategist は `AWS-AIB-C01` です。

- **ベンダー略称**: `data/vendors.json` の、資格のベンダー(`vendor`)に対応する略称です。コードの先頭は、この略称と一致します
  (`npm run validate:data` が検査します)。略称は、ベンダーをまたいでコードが衝突しないように使います。
- **試験略称**: 試験を表す短い表記です(例: `AIB`)。ベンダーが違えば、同じ略称でもかまいません(例: `AWS-DEA-C01` と `EX-DEA-XX`)。
- **版**: 公式の呼び名に合わせます(例: `C01`)。公式に版の呼び名がない試験は `XX` にします。
- 大文字だけにします(`Aws` のように、混在させません)。
- URL・ファイル名・DynamoDB のキー・端末の保存のキーに使います。ファイル名は、コードを英小文字にしたものです(`questions.aws-aib-c01.json`)。

`data/vendors.json` は、ベンダーの名前と略称の一覧です。名前と略称は、それぞれ重複しません。

```jsonc
{ "vendors": [{ "name": "AWS", "abbr": "AWS" }, { "name": "Example", "abbr": "EX" }] }
```

### 問題 ID の接頭辞と、以前のコード

- 問題 ID は `<接頭辞>-<4 桁の連番>` です。接頭辞(`idPrefix`)は、試験コードとは別に、資格マスタに明示します。
  試験の略称が同じ試験(ベンダー違いの `DEA` など)でも、接頭辞を変えれば、問題 ID は衝突しません。接頭辞は、資格どうしで重複させません。
  問題 ID は、保存済みの記録(回答・ブックマーク・復習・解答回数)の中にも入っているので、試験コードを変えても、変えません。
- 試験コードを変えたときは、以前のコードを `previousCodes` に残します。旧コードの URL(`/exams/<旧コード>/…`、`/admin/preview/<旧コード>`)は、
  新しいコードの URL へ、問い合わせを引き継いで、永続的に(308)転送します。保存済みの記録は、次の手順で移します。
  - 端末(localStorage): ページを開いたときに、旧コードのキーの記録を新しいコードのキーへ、1 回だけ移します。
  - アカウント(DynamoDB): `scripts/migrate-exam-codes.ts` で移します(既定は件数の確認だけ。`--apply` で実行)。
    旧コードの SK の項目を、新しいコードの SK の項目に写し(項目の中の `examCode` も新しくします)、旧い項目を消します。何度実行しても同じ結果になります。

- **公開中**(`published`)の資格は、上の項目がすべて必要です(`idPrefix` を含みます)。問題データのファイルも必要です。
- **近日公開**(`coming-soon`)の資格は、`examCode`・`vendor`・`name`・`shortName` と、任意の `level`・`abbr`・`note` を持ちます。
  一覧に表示するだけで、問題データ・`info`・カリキュラム・要約カードは持ちません。
  問題を作る前に作問パイプラインへ通すために、任意の項目として `edition`・`domains`・`officialQuestionCount`・`idPrefix` も持てます(形は公開中の資格と同じです。
  どれも任意で、一部だけでもかまいません)。`domains` を持つときは、公開中と同じく、分野のコードが重複せず、重みの合計が 1(許容誤差 0.005)であることを検査します。
  `idPrefix` は、公開中の資格と準備中の資格をまたいで、重複を検査します。アプリの一覧は、これらの項目を使わず、準備中の資格の表示は変わりません。
  作問パイプラインは、分野(`domains`)と本番の出題数(`officialQuestionCount`)を持つ資格を、公開中でなくても、出題計画・下書き・検証に受け付けます。持たない資格は、足りない項目を示して止まります。
- 分野は `domain1`〜`domainN` のコードで表します。**表示名はマスタ側にだけ**置きます(問題側に名前を書くと、
  表記のゆれで集計が崩れるためです)。分野の数は、資格ごとに異なります。
- `weight` は公式の配点を小数にした値で、合計は 1(許容誤差 0.005)です。

### 2.1 レベル・略称・区分

- `level`(任意)は、資格のレベル(段階)です。値は `Foundational`・`Associate`・`Professional`・`Expert`・`Specialty` のいずれかで、
  資格の一覧では、ベンダーの中を、この順に並べます。公式にレベルの区分がない資格は、持ちません(一覧の最後に並びます)。
- `abbr`(任意)は、一覧のタイルに出す短い表記です。英数字 1〜4 文字です。持たないときは、試験コードの試験略称の部分(4 文字まで)を使います。
- `category`(公開中は必須)は、資格の領域を表す自由な文字列です(例: `Business`)。レベルとは別の項目で、並びには使いません。

### 2.2 資格の情報 `info`

公開中の資格だけが持てる、情報ページ(`/exams/<コード>/info`)に出す項目です。**すべて任意**で、持たない項目は、画面に出しません(空欄にしない)。
値は、ベンダーの公式の情報だけに基づけます。公式に載っていない項目は、推測で書かず、持ちません。

| 項目 | 型 | 必須 | 規則 |
| --- | --- | --- | --- |
| `info.checkedAt` | 文字列 | `info` を持つなら必須 | 公式の情報を確認した日。`YYYY-MM-DD` で、実在する日付。画面に「確認した日」として出す |
| `info.format` | 文字列 | 任意 | 出題形式。空白だけは不可。80 文字以内 |
| `info.languages` | 配列 | 任意 | 受験できる言語。1〜10 件の文字列で、各 20 文字以内 |
| `info.fee` | オブジェクト | 任意 | 受験料。`amount`(正の数)と `currency`(大文字 3 文字の通貨コード)が必須。`note`(任意、80 文字以内)に、価格の補足を書く |
| `info.validityYears` | 整数 | 任意 | 認定の有効期間(年)。1〜10 |
| `info.lastExamDate` | 文字列 | 任意 | この版の試験を受験できる最終日。`YYYY-MM-DD` で、実在する日付。公式に告知されている資格だけが持つ。出題を選ぶ画面にお知らせを、情報ページに「受験できる最終日」を出す |
| `info.guideUrl` | 文字列 | 任意 | 公式の試験ガイドの URL。出典と同じく、許したドメインの `https` の URL だけ(「3.1 出典」)。ユーザー情報・既定以外のポート・クエリ文字列(`?…`)・フラグメント(`#…`)付きは不可 |

- 試験の問題数・制限時間・合格点・分野と配点は、`officialQuestionCount`・`officialTimeMinutes`・`passingScore`・`totalScore`・`domains` を使います(`info` では重ねて持たない)。
- 文字の項目に、URL は書けません(URL は `guideUrl` だけ)。
- 近日公開の資格は、`info` を持てません。

## 3. 問題 `questions.<コード>.json`

```jsonc
{
  "examCode": "EX-SMP-XX",
  "questions": [
    {
      "questionId": "SAMPLE-0001",     // <問題 ID の接頭辞(idPrefix)>-<4 桁の連番>。一意。削除しても再利用しない
      "examCode": "EX-SMP-XX",
      "domain": "domain1",             // マスタの分野のコード
      "questionType": "single",        // "single"(択一)| "multiple"(複数選択)| "free-text"(自由記述。「8. 自由記述」)
      "difficulty": "easy",            // 任意: "easy" | "medium" | "hard"
      "questionText": "設問文",
      "choices": [
        { "key": "A", "text": "選択肢", "explanation": "選択肢ごとの解説(任意)" },
        { "key": "B", "text": "選択肢" }
      ],
      "correctAnswers": ["B"],         // 常に配列。択一でも 1 要素の配列
      "explanation": "総合解説",
      "supplement": "補足(任意)",
      "references": [{ "title": "出典の題(任意)", "url": "https://docs.aws.amazon.com/" }],  // 任意。公式ドキュメントだけ(「3.1 出典」)
      "tags": ["任意のタグ"]            // 任意
    }
  ]
}
```

| 必須 | 任意 |
| --- | --- |
| `questionId`、`examCode`、`domain`、`questionType`、`questionText`、`choices`(各 `key`・`text`)、`correctAnswers`、`explanation` | `difficulty`、`choices[].explanation`、`supplement`、`references`(「3.1 出典」)、`tags` |

- 選択肢は 2〜10 個です。
- 学習モードの教科書は、節の本文を、書き方の決まりで、パートのカードに分けて出します(専用の項目は持ちません)。
  - 単元の最初の節の、最初の段落が「この単元で学ぶこと」です(最初のブロックが段落のときだけ)。
  - 見出し `## 押さえどころ` から、節の終わりまでが「ここがポイント」です(見出しの行は出しません)。
  - それ以外が本文です。単元の `summary` は「この単元の要点」(✓)、節の `diagram` は図、`references` は出典のカードになります。
- 分野のコードが、資格マスタの分野の一覧にないと、検査が失敗します(単元の `domain` と `domains[].code` の両方)。
- 学習モードは、分野の一覧 → 単元の一覧(要約) → 教科書 → 問題の順にたどります。単元が 1 つだけの分野は、単元の一覧を飛ばします。
- 項目の名前の綴りを誤ると(未知の項目)、検査が失敗します。
- 自由記述の問題は、`choices` と `correctAnswers` の代わりに `rubric`(採点基準)を持ちます(「8. 自由記述」)。
- 選択肢をシャッフルして出題すると、画面の記号は、並べた順に上から A, B, C, … と振り直します(正誤の判定と保存は、`key` のままです)。
  解説(`explanation`、`choices[].explanation`、`supplement`)の中で、選択肢を記号で指す箇所(「選択肢B」「正解がBである理由」など)は、
  画面の記号に置き換えて表示します。置き換えるのは、前後が英数字につながらない、選択肢の `key` と同じ大文字 1 文字です。
  選択肢ではないものを、前後に英数字のない大文字 1 文字で書かないでください(「AI」「S3」のように英数字につながる語は、置き換えません)。

### 3.1 出典 `references`

問題の根拠にした資料です。結果の画面と直前チェックで、解説のあとにリンクとして出します(新しいタブで開きます)。
**出典は、資格のベンダーなどの公式ドキュメントだけ**にします。ほかの学習サイトや講座のサービスなどは書きません。

| 項目 | 型 | 必須 | 規則 |
| --- | --- | --- | --- |
| `references` | 配列 | 任意 | 1〜10 件。同じ `url` は重ねない |
| `references[].title` | 文字列 | 任意 | 資料の題。空白だけは不可。200 文字以内。URL を含めない。ないときは、画面に URL のホスト名を出す。作問パイプラインの書き出しは、台帳に題がある出典に、その公式ページの題を入れる(台帳に題がない出典は、題なしで書き出す。ADR 0020) |
| `references[].url` | 文字列 | 必須 | 2000 文字以内。`https://` で始まり、ユーザー情報(`user@` など)・既定以外のポート(`:443` 以外)・クエリ文字列(`?…`)・フラグメント(`#…`)を持たず、ホスト名が「許すドメイン」の一覧にある。クエリとフラグメントは、署名や利用者を識別する値を運びうるので許さない(空の `?` や `#` も不可) |

**許すドメイン**は、`packages/data-schema/src/exam-data/schema.ts` の `ALLOWED_REFERENCE_HOSTS` の 1 か所で定めます。ホスト名の完全一致で比べます(サブドメインも、別に足さない限り許しません)。

| ホスト名 | 内容 | 出典にしてよい資格のベンダー |
| --- | --- | --- |
| `docs.aws.amazon.com` | AWS の公式ドキュメント | AWS |
| `aws.amazon.com` | AWS の公式サイト | AWS |
| `www.nist.gov` | NIST の公式サイト | AWS |
| `docs.databricks.com` | Databricks の公式ドキュメント | Databricks |
| `www.databricks.com` | Databricks の公式サイト | Databricks |

ホストごとに、そのホストを出典にしてよい資格のベンダーを、同じファイルの `REFERENCE_HOST_VENDORS` で定めます。
作問パイプラインは、出典が公式かどうかを、この対応で判定します。ベンダーの名前は `data/vendors.json` にあるものだけで、
`npm run validate:data` が確かめます。

資格を足すときに、その資格のベンダーの公式ドキュメントのドメインを、一覧に足します([資格を追加する手順](./adding-an-exam.md))。
出典の扱い(持つもの・持たないもの、言い換えと引用の上限、ドメインを足す手順)は、[出典と権利の方針](./source-policy.md)にあります。
出典の URL は `references` にだけ書き、設問文や解説などの本文には書きません(「4. 機械検査する規則」の 20)。

## 4. 機械検査する規則

`npm run validate:data` が、次を検査します。報告は、ファイル名・項目の位置・問題の ID と、規則の種類だけです(設問文や選択肢の本文は出しません)。正解の偏りは、ファイルと種類に、21 は記号・問題の数・期待値に対する倍率を、22 は問題の数と割合を添えます。

**1 つの問題の中**

1. `choices[].key` は、`A` から連番で、重複しない。
2. `correctAnswers` は空でなく、重複せず、すべて `choices[].key` の中にある。
3. `questionType` は正解の数と一致する(1 つなら `single`、2 つ以上なら `multiple`)。
4. 同じ文言の選択肢がない(空白と全角・半角の違いをならして比べる)。
5. `references[].url` は、`https://` で始まり、ユーザー情報・既定以外のポート・クエリ文字列・フラグメントを持たず、ホスト名が許すドメインの一覧にある(「3.1 出典」)。`references` は 1〜10 件で、同じ URL は重ねない。
6. 自由記述の `rubric.criteria` は 1 つ以上。各観点の `keywords` も 1 つ以上。
7. 自由記述の `rubric.passingPoints` は、配点(`criteria[].points`)の合計以下。
8. 自由記述の観点名(`criteria[].name`)は重複しない(空白と全角・半角の違いをならして比べる)。結果の画面で、観点名を観点の識別に使うためです。
9. 自由記述の観点名は 40 文字以内、キーワードは 1 つ 40 文字以内。
10. 自由記述のキーワードは、全角・半角、大文字・小文字の違いをならし、空白を除いても空にならない(判定と同じならし方。空になるキーワードは、どの回答にも含まれないため)。

1〜4 は、択一・複数選択の問題だけの規則です。自由記述の問題は、選択肢と正解を持てず、6〜10 と `rubric` の形(「8. 自由記述」)を検査します。

**1 つのファイルの中**

11. `questionId` は重複しない。接頭辞は、資格マスタの `idPrefix` と一致する。資格マスタの `retiredQuestionIds`(退役した ID)を使わない。退役した ID の接頭辞も `idPrefix` と一致する。
12. 同じ設問文の問題がない(空白と全角・半角の違いをならして比べる)。
13. 各問題の `examCode` は、ファイルの `examCode` と一致する。

**ファイルをまたぐ**

14. 各問題の `domain` は、資格マスタの分野のコードにある。
15. 公開中の資格には、問題データのファイルがある。問題データは、資格マスタにある公開中の資格のものだけ。
16. 選択式(択一・複数選択)の問題数は、本番モードの出題数(`officialQuestionCount`)以上(自由記述は数えない)。
17. ファイル名のコードと、ファイルの `examCode` が一致する。

**非公開の問題(`unpublished.<コード>.json`。「13. 非公開の問題」)**

U1. 非公開の問題の ID は、退役した ID と重ならず、公開の問題の ID とも重ならず、非公開の中でも重複しない。接頭辞は `idPrefix` と一致する。
U2. 非公開の問題の `domain` は、資格マスタの分野のコードにある。ファイル名のコードと `examCode` が一致し、資格は公開中のものである。
U3. 公開の問題の数(規則 16)は、非公開の問題を数えない。

**資格マスタ**

18. `examCode` は重複しない。
19. 合格点は満点以下。分野のコードは重複せず、重みの合計は 1(許容誤差 0.005)。

**本文**

20. 本文に、URL(`http://`・`https://`・`www.` を含む文字列。大文字・小文字は区別しない)を書かない。対象は、問題の設問文・選択肢・選択肢ごとの解説・総合解説・補足・自由記述の観点名・出典の題・タグ(`tags`)と、資格マスタの文字の項目(提供元、資格名、略称、版、区分、分野名、近日公開の文言)、カリキュラムの題・本文・要約・図の文字(「11. カリキュラムのデータ」)。出典の URL は、問題と節の `references` にだけ置く(「3.1 出典」)。

**正解の偏り(ファイルごと)**

問題を読まなくても、記号の位置や選択肢の長さで正解を選べないかを数えます。種類(択一・複数選択)ごとに 20 問以上あるファイルだけを検査します(少ないと、分布がぶれるため)。

21. 正解の記号の分布に偏りがない(失敗)。記号ごとに、正解になった数と、偏りがないときの期待値を比べる。
    期待値は、問題ごとの「正解の数 ÷ 選択肢の数」を、その問題の選択肢の記号それぞれについて足したもの。
    ずれが、標準偏差(問題ごとの p(1 − p) の和の平方根)の 3 倍を超え、かつ期待値の 40% を超えると、偏りとする。
22. 択一で、最長の選択肢が正解である問題の割合が 40% 以下(警告。止めはしない)。分母は択一の問題数。
    分子は、選択肢の `text` の文字数が最大の選択肢がただ 1 つあり、それが正解である問題(最長が同じ文字数で並ぶ問題は数えない)。
    選択肢の長さは、並べ替えでは変わらないので、選択肢の文面を手直しして直す。

## 5. 採点の考え方

- 演習の得点は、**正答数 ÷ 出題数 × 100(%)** で、全資格に共通です。自由記述の問題は、判定で合格点以上なら 1 問の正解として数えます。分野の重みは、採点には使いません
  (出題に含まれない分野が 0 点になり、全問正解でも満点にならないため)。
- 合格ラインは、`passingScore / totalScore` を割合にして比べます(700/1000 も 70/100 も 70%)。
- 分野の重みは、合格予測と、優先して復習したい分野の並びにだけ使います。
  - 合格予測は、直近の結果(10 回分まで)の問題を分野ごとに数えた正答率を、分野の重みで平均します。重みの合計が 1 でないときは、合計で割って合わせます。
  - 出題のない分野は、直近の結果の全体の正答率で代わりにします。重みがすべて 0 のときは、全体の正答率にします。
  - 優先して復習したい分野は、取りこぼし(重み × (100 − 正答率))の大きい順に、上位 3 件を出します。同じなら、正答率の低い順です。

## 6. 文字の書き方

設問文・選択肢・解説は、次の限定した記法だけが解釈されます。これ以外の Markdown の記法や HTML は、書いても文字がそのまま表示されます。

| 書き方 | 表示 | 使える場所 |
| --- | --- | --- |
| 空行 | 段落の区切り(段落の中の改行は、そのまま改行になる)。設問文は、状況の段落と問いの段落を空行で分けられる | すべて |
| `**太字**` | 太字 | すべて |
| `==強調==` | 橙の太い下線で強調(太字とは別。見落としたくない語に使う) | カリキュラムの本文・要約 |
| `` `コード` `` | 文中のコード | すべて |
| 行頭の `- ` | 箇条書き | 設問文・解説・補足・使い方の本文 |
| 行頭の `## ` | 小見出し | 設問文・解説・補足・使い方の本文 |
| 行頭が ``` の行で囲んだ範囲 | コードのブロック(中の記法は解釈しない) | 設問文・解説・補足・使い方の本文 |

カリキュラムの節の本文(「11. カリキュラムのデータ」)は、使い方の本文と同じく、上の表のすべての記法が使えます。`==強調==` は、カリキュラムの本文と要約だけで使えます(問題・解説・使い方では、そのまま文字として表示されます)。

選択肢の本文と、選択肢ごとの解説(`explanation`)は、1 つの流れの中に入れるため、`**太字**`・`` `コード` ``・改行だけが使えます。

### 6.1 解説の見出し

解説(`explanation`)は、見出しで区切って、見出しごとの色とアイコンのカードで表示します(`packages/app/src/lib/explanation.ts`)。見出しの名前の一覧は、データの契約(`packages/data-schema/src/exam-data/explanation.ts`)にあり、アプリと作問パイプライン(下書きの解説の検査)が同じ一覧を読みます。

- 見出しは、次のどちらかです。
  - 行頭の `## ` の行。
  - 段落(前後を空行で区切った部分)が、ちょうど次の表の見出しの名前だけのもの。末尾のコロン(`:` か `：`)の有無は問いません。
- 最初の見出しの前の段落は、「問われている要件」のカードにします。見出しのない解説は、全体が 1 枚のカードになります。
- `## ` の見出しで、表にない名前は、その名前の普通のカードにします。本文は欠けずに表示されます。
- 表記ゆれは、データを直さず、表の別名で吸収します。新しい見出しの名前を使うときは、この表と、データの契約の一覧と、テストに足します。

| 種類 | 見出しの名前(別名) | 表示 |
| --- | --- | --- |
| 問われている要件 | 問われている要件(要件) | 見出しの前の段落も、このカード |
| 正解の決め手 | 正解の決め手(正解の理由、理由) | |
| 前提知識 | 前提知識 | 句点で終わらない短い 1 行の段落(40 文字まで)は、用語の題として太字にする |
| 解くための考え方 | 解くための考え方(考え方) | |
| まとめ | まとめ | |
| 他の選択肢が誤りである理由 | 他の選択肢が誤りである理由(他の選択肢が誤りの理由、誤りの選択肢) | 選択肢の本文の段落と、次の理由の段落を組にして、選択肢ごとの小カードにする |

「他の選択肢が誤りである理由」の節では、選択肢の本文と同じ段落(空白と読点・句点の違いは問わない)を、その選択肢として扱います。
組にできない段落は、普通の段落のまま表示します。作問パイプラインは、組にできない段落のある下書きを、取り込みで止めます(規則 `explanation-wrong-pairs`。[作問のスタイルガイド](./question-style.md))。組の判定は、アプリと作問パイプラインが、データの契約の同じ関数を使います。今のデータでは、見出しの名前は「前提知識」と「他の選択肢が誤りである理由：」と `## 理由` を使っています。

補足(`supplement`)は、解説のあとに「さらに詳しく」の折りたたみで表示します。

## 7. ID の運用

- `questionId` は永続です。問題を削除しても、番号を詰めません(受験履歴・ブックマーク・復習が ID を参照するため)。
- 問題を削除したら、その ID を、資格マスタのその資格の `retiredQuestionIds` に足します。退役した ID を問題が使うと、データの検査が失敗します。
  CI(`npm run check:retired-ids`)は、main から削除した問題の ID が `retiredQuestionIds` にないと失敗にします。
- 問題を非公開にしたときは、削除ではなく、非公開のファイルへ移します(「13. 非公開の問題」)。非公開の ID は、退役した ID とは別で、公開に戻せます。
  CI(`npm run check:retired-ids`)は、公開と非公開のあいだの移動を削除とみなしません。非公開のファイルから消した ID は、削除として、`retiredQuestionIds` に求めます。
- 作問パイプラインの書き出し(`export`)は、今の問題・非公開の問題・退役した ID・書き出し済みの ID を含めた最大の番号の次から採番します(ADR 0020、0022)。
- 資格の試験の版が変わったら、`edition` を更新します。分野の再配置が必要なら、新しい資格コードで扱います。分野の重みだけの変更は、マスタの更新で済みます。

## 8. 自由記述

自由記述は、選択肢のない、文章で答える問題です(`questionType: "free-text"`)。択一・複数選択の問題と同じファイルに置き、
通常出題では、出題の条件の「自由記述の問題を含める」を選んだときだけ一緒に出題します(既定は含めない)。本番モードと 5 問のセクションの出題には含めません。

```jsonc
{
  "questionId": "SAMPLE-0006",
  "examCode": "EX-SMP-XX",
  "domain": "domain1",
  "questionType": "free-text",
  "questionText": "設問文",
  "rubric": {
    "criteria": [
      { "name": "観点の名前", "keywords": ["キーワード", "言い換え"], "points": 50 },
      { "name": "別の観点", "keywords": ["キーワード"], "points": 50 }
    ],
    "passingPoints": 60
  },
  "explanation": "総合解説(解答の例を含めてよい)"
}
```

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `rubric.criteria` | 配列 | 観点の一覧。1 つ以上 |
| `rubric.criteria[].name` | 文字列 | 観点の名前。結果の画面に表示する。40 文字以内。重複不可 |
| `rubric.criteria[].keywords` | 文字列の配列 | 回答がどれか 1 つを含めば、観点を満たす。1 つ以上。1 つ 40 文字以内 |
| `rubric.criteria[].points` | 正の整数 | 観点を満たしたときの配点 |
| `rubric.passingPoints` | 正の整数 | 合格点。満たした観点の配点の合計が、これ以上なら正解。配点の合計以下 |

`difficulty`・`supplement`・`references`・`tags` は、選択式の問題と同じく任意です。`choices` と `correctAnswers` は持てません。

**判定**(`packages/app/src/lib/free-text.ts` の `judgeFreeText`)

- 回答とキーワードは、全角・半角、大文字・小文字の違いをならし、空白を除いてから、含むかどうかを比べます。
- 外部のサービス(AI など)は使いません。画面の採点と、サーバーの採点し直し(復習プールと、問題ごとの解答回数・直近の正誤)で、同じ関数を使います。
- 結果の画面には、観点ごとの判定と点数、得点と合格点を表示します。

## 9. サンプルデータ

`data/` の `EX-SMP-XX`(公開中)と `EX-SM2-XX`(近日公開)は、動作確認用の架空の資格です。実在の試験の問題は含みません。
`EX-SMP-XX` のカリキュラム(`curriculum.ex-smp-xx.json`)も、動作確認用の架空の教材です。架空の資格なので、出典(`references`)は付けません。テストと動作確認に使うため、実在の資格を加えても残します。
画面には、開発・テスト・E2E のときだけ出し、本番のビルドでは出しません(ベンダーが `Example` の資格を、`packages/app/src/lib/exam-data.ts` の `visibleExams` で外します)。

実在の資格(`AWS-AIB-C01` など)の問題とカリキュラムは、同じ形で、資格ごとのファイル(`questions.<コード>.json`、`curriculum.<コード>.json`)に置きます。
資格ごとの扱いは、加えるときに、そのつど決めます。どの資格でも、本文に URL は書きません(「4. 機械検査する規則」の 20)。

## 10. 使い方ページのデータ `help.json`

使い方ページの内容です。スキーマの正本は `packages/data-schema/src/help-data/schema.ts` で、`npm run validate:data` が検査します。

```json
{
  "updatedAt": "2026-10-12",
  "sections": [
    {
      "id": "start",
      "title": "はじめに",
      "body": "本文(「6. 文字の書き方」の記法が使えます)",
      "links": [{ "label": "資格を選ぶ", "href": "/exams" }],
      "items": [{ "id": "start-first", "title": "最初にすること", "body": "本文" }]
    }
  ]
}
```

| 項目 | 型 | 必須 | 規則 |
| --- | --- | --- | --- |
| `updatedAt` | 文字列 | 任意 | 最終更新日。`YYYY-MM-DD` の実在する日付。ページの題の下に出す |
| `sections` | 配列 | 必須 | 1〜30 件。表示は、この順 |
| `sections[].id` | 文字列 | 必須 | 英小文字・数字・ハイフンで、英字から始まる 32 文字以内。節と項目のすべての ID の中で重複不可。目次のリンク(`#id`)になる |
| `sections[].title` | 文字列 | 必須 | 空白だけは不可。80 文字以内 |
| `sections[].body` | 文字列 | 必須 | 空白だけは不可。4000 文字以内 |
| `sections[].links` | 配列 | 任意 | 10 件まで。`label`(60 文字以内)と `href` を持つ |
| `sections[].items` | 配列 | 任意 | 節の中の項目。20 件まで。目次の 2 段目になる(よくある質問の 1 問など) |
| `sections[].items[].id` | 文字列 | 必須 | `sections[].id` と同じ規則。節と項目のすべての ID の中で重複不可 |
| `sections[].items[].title` | 文字列 | 必須 | 空白だけは不可。80 文字以内 |
| `sections[].items[].body` | 文字列 | 必須 | 空白だけは不可。2000 文字以内 |
| `sections[].items[].links` | 配列 | 任意 | `sections[].links` と同じ |

- 本文の箇条書きのうち、「ラベル: 説明」の形(句読点を含まない 20 文字までのラベルと、コロン)の項目は、ラベルを太くして表示します。
- `updatedAt` と `items` は任意です。書いていないデータも、そのまま読めます。

リンク先(`href`)は、次のどちらかです。

- アプリ内のパス(`/` で始まる)。画面ができているページ(ナビゲーションに並んでいるもの)か、公開中の資格のページ(`/exams/<資格コード>`)だけを指せます。ないページへのリンクは、検査で失敗します。
- `https://` で始まる URL。外部サイトは、新しいタブで開きます。`http://` や `javascript:` は使えません。

## 11. カリキュラムのデータ `curriculum.<コード>.json`

学習モードで読む単元と、単元ごとに解く問題です。`<コード>` は資格コードの英小文字です。
スキーマの正本は `packages/data-schema/src/curriculum-data/schema.ts` で、`npm run validate:data` が検査します。

```json
{
  "examCode": "EX-SMP-XX",
  "domains": [{ "code": "domain1", "summary": "分野の説明(分野の一覧に出す短い文章)" }],
  "units": [
    {
      "id": "basics",
      "title": "基礎の用語",
      "domain": "domain1",
      "order": 1,
      "summary": ["要点の 1 つ目", "要点の 2 つ目"],
      "sections": [
        { "id": "intro", "title": "はじめに", "body": "本文(「6. 文字の書き方」の記法が使えます)" }
      ],
      "questionIds": ["SAMPLE-0001", "SAMPLE-0002"],
      "stages": [
        { "order": 1, "questionIds": ["SAMPLE-0001"] },
        { "order": 2, "questionIds": ["SAMPLE-0002"] }
      ]
    }
  ]
}
```

| 項目 | 型 | 必須 | 規則 |
| --- | --- | --- | --- |
| `examCode` | 文字列 | 必須 | ファイル名のコードと一致する、公開中の資格のコード |
| `domains` | 配列 | 必須 | 1〜20 件。学習モードの分野の一覧に出す、分野の説明。単元が属する分野を、すべて書く。表示の順は、資格マスタの分野の並び |
| `domains[].code` | 文字列 | 必須 | 資格マスタ(`exams.json`)の分野のコード。ファイルの中で重複不可 |
| `domains[].summary` | 文字列 | 必須 | 空白だけは不可。200 文字以内。分野の名前は、資格マスタの `name` を使う(ここでは持たない) |
| `units` | 配列 | 必須 | 1〜100 件。表示は `order` の小さい順 |
| `units[].id` | 文字列 | 必須 | 英小文字・数字・ハイフンで、英字から始まる 32 文字以内。ファイルの中で重複不可。画面の URL(`/exams/<資格コード>/study/<id>`)になる。`domains` は分野の画面の経路に使うため、使えない |
| `units[].title` | 文字列 | 必須 | 空白だけは不可。80 文字以内 |
| `units[].domain` | 文字列 | 必須 | 単元が属する分野のコード。資格マスタの分野にあり、ファイルの `domains` にもあるコード。`domains` に書いた分野には、単元が 1 つ以上必要 |
| `units[].order` | 整数 | 必須 | 1 以上。ファイルの中で重複不可 |
| `units[].summary` | 配列 | 任意 | 単元の要約。1〜10 件の文字列で、1 件が箇条書きの 1 項目。各項目は空白だけは不可で、200 文字以内。単元の画面の先頭に、この順で出す。記法は 1 行の中の書式(太字、コードなど)だけ |
| `units[].sections` | 配列 | 必須 | 1〜50 件。表示は、この順 |
| `units[].sections[].id` | 文字列 | 必須 | `units[].id` と同じ形。単元の中で重複不可 |
| `units[].sections[].title` | 文字列 | 必須 | 空白だけは不可。80 文字以内 |
| `units[].sections[].body` | 文字列 | 必須 | 空白だけは不可。10000 文字以内 |
| `units[].sections[].diagram` | オブジェクト | 任意 | 節の図解。本文のあとに描く。形は下の「図解」 |
| `units[].sections[].references` | 配列 | 任意 | 節の出典。本文(と図解)のあとにリンクとして出す。形と規則は問題の `references` と同じ(「3.1 出典」) |
| `units[].questionIds` | 配列 | 必須 | 1〜500 件。「この単元の問題を解く」で、この順に出題する。単元の中で重複不可 |
| `units[].stages` | 配列 | 任意 | 段階学習の段階。1〜20 件。`order` の小さい順に進む |
| `units[].stages[].order` | 整数 | 必須 | 1〜100。単元の中で重複不可 |
| `units[].stages[].questionIds` | 配列 | 必須 | 段階の確認問題。1〜100 件。この順に出題する。段階の中で重複不可 |

- `questionIds` と `stages[].questionIds` の各 ID は、同じ資格の問題データ(`questions.<コード>.json`)にある問題です。ない問題や、別の資格の問題を指すと、検査が失敗します。
- 段階の確認問題は、単元の `questionIds` に含まれていなくてもかまいません。1 つの問題を、複数の段階に関連づけてもかまいません。
- 段階は、最初の段階から挑戦でき、確認問題の正答率が 80% 以上で合格すると、次の段階へ進めます。到達の状態は、利用者の端末に保存します。
- 1 つの問題を、複数の単元に関連づけてかまいません。
- 項目の名前の綴りを誤ると(未知の項目)、検査が失敗します。
- 近日公開の資格や、資格マスタにない資格のカリキュラムは置けません。
- 単元・節・図の題、節の本文、要約、図の箱と矢印の文字に、URL は書けません(「4. 機械検査する規則」の 20)。

### 図解 `diagram`

節に 1 つ置ける図です。`type` で 3 種類に分かれます。座標は書きません。画面が、箱の大きさと位置を決めます。

| `type` | 図 | 使いどころ |
| --- | --- | --- |
| `flow` | 箱と矢印の流れ | 手順、段階、因果 |
| `compare` | 左右の比較 | 2 つのものの違い、使い分け |
| `hierarchy` | 入れ子の階層 | 包含関係、分類 |

`type` のない図は、`flow` として読みます(`type` は省略できます)。
どの図も、`title` は必須(空白だけは不可、80 文字以内)で、図の下に出し、読み上げでは図の名前になります。
箱の文字は、題(`label`、20 文字以内)と、題の下に添える短い説明(`note`、任意、40 文字以内)です。
長い文字は、画面が折り返し、それでも収まらなければ文字を小さくします(最小の大きさでも収まらない長さは、`npm test` の検査が失敗にします)。

#### 流れの図 `flow`

箱(ノード)と矢印(辺)の図です。画面が、矢印の向きに沿って箱を上から下へ段に並べ、
矢印のラベルを、ほかのラベルや箱と重ならない位置に置きます。

```json
{
  "type": "flow",
  "title": "物事を進める流れ",
  "nodes": [
    { "id": "goal", "label": "目的を決める", "note": "何のためにやるか" },
    { "id": "do", "label": "進める" }
  ],
  "edges": [{ "from": "goal", "to": "do", "label": "次に" }]
}
```

| 項目 | 型 | 必須 | 規則 |
| --- | --- | --- | --- |
| `nodes` | 配列 | 必須 | 2〜20 件。同じ段の中では、おおむねこの順に左から並べる |
| `nodes[].id` | 文字列 | 必須 | `units[].id` と同じ形。図の中で重複不可 |
| `nodes[].label` | 文字列 | 必須 | 空白だけは不可。20 文字以内。箱の題 |
| `nodes[].note` | 文字列 | 任意 | 空白だけは不可。40 文字以内。題の下の説明 |
| `edges` | 配列 | 必須 | 1〜40 件。`from` の箱から `to` の箱への矢印 |
| `edges[].from` / `edges[].to` | 文字列 | 必須 | `nodes[].id` のどれか。同じ箱どうしは不可 |
| `edges[].label` | 文字列 | 任意 | 空白だけは不可。12 文字以内。矢印に添える文字 |

- 同じ向きの矢印(`from` と `to` の組)は、図の中で重複できません。逆向きの矢印を足すと、一周して戻る形になるため置けません。
- 矢印をたどって元の箱に戻れる形(閉路)は、段に並べられないため、検査が失敗します。
- 読み上げでは、図の名前に続けて、矢印ごとに「「元の箱」から「先の箱」へ(ラベル)」を読みます。
- 段を 2 つ以上飛ばす矢印は、間の段の箱の上を通ることがあります。図が込み入るときは、図を分けます。
- 1 つの段に並べる箱は、多くても 4 つ程度にします(横が広がると、狭い画面で文字が小さくなります)。

#### 比較の図 `compare`

左右に、見出しの箱と、項目の箱を並べます。左右の項目は、同じ行どうしを対応させて並べます(行の高さは、高いほうに合わせる)。

```json
{
  "type": "compare",
  "title": "ルールベースと AI の使い分け",
  "left": { "heading": "ルールベース", "items": [{ "label": "条件が明文化されている", "note": "規程で書き下せる" }] },
  "right": { "heading": "AI・機械学習", "items": [{ "label": "基準を明文化できない" }] }
}
```

| 項目 | 型 | 必須 | 規則 |
| --- | --- | --- | --- |
| `left` / `right` | オブジェクト | 必須 | 左と右の側 |
| `left.heading` / `right.heading` | 文字列 | 必須 | 空白だけは不可。20 文字以内。側の見出し |
| `left.items` / `right.items` | 配列 | 必須 | 1〜6 件。上から順に並べる |
| `items[].label` | 文字列 | 必須 | 空白だけは不可。20 文字以内 |
| `items[].note` | 文字列 | 任意 | 空白だけは不可。40 文字以内 |

- 読み上げでは、「左「見出し」: 項目、項目。右「見出し」: …」の順に読みます。

#### 階層の図 `hierarchy`

根の箱の中に、子の箱を入れ子にして描きます。子は、上から順に並べます。

```json
{
  "type": "hierarchy",
  "title": "AI と機械学習の関係",
  "root": {
    "label": "AI",
    "note": "技術全体",
    "children": [{ "label": "機械学習", "children": [{ "label": "深層学習" }] }]
  }
}
```

| 項目 | 型 | 必須 | 規則 |
| --- | --- | --- | --- |
| `root` | オブジェクト | 必須 | 根の箱 |
| `root.label` ほか、箱の `label` | 文字列 | 必須 | 空白だけは不可。20 文字以内 |
| 箱の `note` | 文字列 | 任意 | 空白だけは不可。40 文字以内 |
| 箱の `children` | 配列 | 任意 | 1〜8 件。子の箱。入れ子は、根を 1 として 4 段まで。図全体の箱は 25 件まで |

- 読み上げでは、「「親」の中に「子」、「子」。」を、親ごとに読みます。

## 12. 要約カードのデータ `summary.<コード>.json`

直前チェックで、1 枚ずつ見返すためのデータです。`<コード>` は資格コードの英小文字です。
問題 1 問につき、カードを 1 枚持ちます。分野・難易度・選択肢の本文は、問題から引くので、ここでは持ちません(重複して持たない)。
スキーマの正本は `packages/data-schema/src/summary-data/schema.ts` で、`npm run validate:data` が検査します。

```json
{
  "examCode": "EX-SMP-XX",
  "cards": [
    {
      "questionId": "SAMPLE-0001",
      "question": "信号機の青(緑)は、何を表すか。",
      "answers": ["B"],
      "point": "青(緑)は、進んでよいことを表す。"
    }
  ]
}
```

| 項目 | 型 | 必須 | 規則 |
| --- | --- | --- | --- |
| `examCode` | 文字列 | 必須 | ファイル名のコードと一致する、公開中の資格のコード |
| `cards` | 配列 | 必須 | 1〜500 件。表示は、この順 |
| `cards[].questionId` | 文字列 | 必須 | 同じ資格の問題データにある、択一・複数選択の問題の ID。ファイルの中で重複不可 |
| `cards[].question` | 文字列 | 必須 | 空白だけは不可。120 文字以内。問いの要約(1〜2 文)。カードの表に出す |
| `cards[].answers` | 配列 | 必須 | 正解の選択肢のキー(`A`〜`Z`)。1 件以上で、重複不可。順序は問わない |
| `cards[].point` | 文字列 | 必須 | 空白だけは不可。200 文字以内。決め手(答えを選ぶ理由。1〜2 文)。答えを開いたときに出す |

- `answers` は、問題の `correctAnswers` と一致しなければなりません(過不足があると、検査が失敗します)。
- `questionId` が問題データにない、別の資格の問題を指す、自由記述の問題を指す、のいずれも、検査が失敗します。
- `question` と `point` に、URL は書けません(「4. 機械検査する規則」の 20)。出典は、問題の `references` にあります。
- 項目の名前の綴りを誤ると(未知の項目)、検査が失敗します。
- 近日公開の資格や、資格マスタにない資格の要約カードは置けません。
- 要約カードのない資格には、モード選択に要約カードの入口を出しません。

## 13. 非公開の問題 `unpublished.<コード>.json`

基準を満たさない問題を、公開から外し、削除せずに残しておく場所です。アプリは読まず、配信に含まれません。公開に戻すときは、`question` をそのまま公開のファイルへ移します(ID は変わりません)。
削除(+ 退役)とは別の状態です。退役した ID は復帰しません。非公開の ID は復帰できます(ADR 0022)。

```jsonc
{
  "examCode": "EX-SMP-XX",
  "entries": [
    {
      "verdict": "rewritable",            // "rewritable"(書き直して戻せる)| "unpublish"(同じ内容では直らない)
      "reasons": ["judge:choices-weak"],  // 非公開にした理由。`<段階>:<コード>` の形。1 件以上
      "question": { /* 公開の問題と同じ形(「3. 問題」)。そのまま戻せる */ }
    }
  ]
}
```

| 項目 | 型 | 必須 | 規則 |
| --- | --- | --- | --- |
| `examCode` | 文字列 | 必須 | 資格コード。ファイル名のコードと一致する |
| `entries` | 配列 | 必須 | 1 件以上。`question.questionId` の昇順に並べる(`unpublish` コマンドが並べる) |
| `entries[].verdict` | 文字列 | 必須 | `rewritable` か `unpublish`(判定の意味は、[書き方の指針](./exam-style/README.md)の「判定の基準」) |
| `entries[].reasons` | 配列 | 必須 | 1〜10 件。形は `^[a-z]+:[a-z]+(-[a-z]+)*$`(小文字の語を `:` でつなぎ、後半は `-` でつなげる。判定の段階の理由コード `judge:*` など) |
| `entries[].question` | 問題 | 必須 | 公開の問題と同じスキーマ(択一・複数選択・自由記述)。本文を変えずに持つ |

- ファイル名は `unpublished.<資格コードの英小文字>.json`。`questions.` で始めません。アプリの読み込み(`questions.<コード>.json`)と、問題データの検査が `questions.*.json` を対象にするためで、名前の形で配信から外れることを守ります。
- 移す作業は、作問パイプラインの `unpublish` コマンドです(判定の結果から移す。公開の選択式が本番モードの出題数を下回る移し方は、止める)。公開に戻す作業は、書き直した問題を `draft --rewrite` で作り、検証・人の確認・判定を通したあとの `restore` コマンドです([ADR 0023](./app/adr/0023-rewrite-unpublished-questions.md))。戻すときは、非公開のファイルから外し(空になれば、ファイルごと消します)、公開のファイルへ問題 ID の順で足します。
- 公開の問題からの参照: カリキュラムの単元(`units[].questionIds`)と段階の確認問題(`units[].stages[].questionIds`)、要約カード(`cards[].questionId`)が参照する問題は、非公開に移しません(参照が切れるため)。先に、単元・段階・要約カードを直します。
- 履歴・復習・ブックマークは、問題の ID だけを持ちます。非公開にした問題は、いまのデータにない問題(退役した ID と同じ)として扱い、一覧にも、数にも、ID にも出しません。非公開から公開に戻すと、同じ ID で再び出ます(記録はそのまま使えます)。
  ただし、結果の数(解いた数・正答率)は、いまの公開の問題だけで数え直すので、非公開の期間は、その問題の分が数に入りません。
- ビルド成果物に非公開の問題が含まれないことは、CI の `npm run check:unpublished-bundle` が確かめます(設問文と ID を、`.next` から探す。設問文が 12 文字未満の問題は、設問文を探さず、ID だけを探す(偶然の一致を避けるため))。
