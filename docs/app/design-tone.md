# デザイン方針

画面ごとの見た目と文言をぶらさないための方針です。色の値やサイズの正は、実装(`packages/app/src/app/globals.css`)です。
ここでは、決め方の考え方と、変数・共通クラス・部品の決まりを書きます。

## 全体のトーン

- 落ち着いていて、読みやすいこと。学習の邪魔をしないことを、最優先にします。
- 結果や達成は、励ます言い方にします。間違いは、責めずに、復習につなげる言い方にします。

## 画面スタイル(リッチ / シンプル)

利用者が、好みに合わせて選べます。どちらも、機能は同じです。

| スタイル | 見た目 | 演出 |
| --- | --- | --- |
| リッチ | やわらかく、装飾のある見た目 | 紙吹雪、ゲージ表示など、達成を感じられる演出を使う |
| シンプル | すっきりした、見やすさ優先の見た目 | 動きは最小限。最終値をそのまま表示する |

- 演出は、端末の「動きを減らす」設定が有効なときは、スタイルにかかわらず抑えます。
- 演出は、情報を伝える手段にしません。演出がなくても、結果の意味が伝わるようにします。

## 配色

- 色は、役割で決めます(主要な操作、正解、不正解、警告、補助)。画面ごとに、色を個別に決めません。
- 正解と不正解は、色だけで区別せず、文言や記号も添えます。
- 本文と背景のコントラスト比は、WCAG の AA(通常の文字で 4.5:1 以上)を満たします。
- 分野ごとの色は、分野の見分けに使います。同じ分野には、すべての画面で、同じ色を使います。

## 余白とレイアウト

- 余白は、段階的な数列(例: 4、8、12、16、24、32)から選びます。数値を、その場で決めません。
- スマートフォンの幅で、横にスクロールしないこと。左右の余白は、16px 以上を確保します。
- 1 画面で、主要な操作は 1 つにします。

## 文言

- 丁寧で簡潔な「です・ます」調にします。
- ボタンは、結果が分かる動詞で書きます(例: 「採点する」「次の問題へ」)。
- エラーは、起きたことと、次にすることを書きます。内部の識別子や、技術的な詳細は出しません。

## ライト / ダーク

- 端末の設定に従うことを初期値にし、手動で切り替えられるようにします。選択は保存します。
- 色は、ライトとダークの両方で、同じ役割の組(背景、文字、境界、強調)を持ちます。
- どちらのテーマでも、コントラスト比の基準を満たします。
- 画面スタイル(リッチ / シンプル)とは、別の設定です。組み合わせは、すべて有効です。

## 骨組み

画面の幅で、ナビゲーションの形を変えます(`components/site-nav.tsx`。項目は `lib/nav.ts`)。出し分けは CSS(`lg`、1024px)で行い、どちらも同じ項目を並べます。

| 幅 | 形 |
| --- | --- |
| 広い(`lg` 以上) | 左にカード状のサイドバー。ロゴ、学習の主要な項目(ホーム、資格、実績、復習、ブックマーク)、案内の項目(リリースノート、使い方)、アカウント、管理、テーマ、画面スタイル、ログアウトの順。選択中の背景が、項目の間を滑って動く |
| 狭い(`lg` 未満) | 上に固定のバー(すりガラス、ロゴ、資格の中の画面では「資格の一覧へ」)と、下に浮くドック(6 等分)。ドックの最後の「メニュー」は、ほかの項目を並べたシートを開く |

- 項目は、画面ができているものだけを置きます。まだない画面は「近日公開」として並べず、画面ができた版で足します。
- 管理の項目は、管理者にだけ出します(開けるかどうかは、サーバーが決めます)。
- ドックの項目の名前は、狭い幅でも 1 行に収めます(折り返さない)。長い名前は、ドックでだけ短い名前にします(「ブックマーク」は「ブクマ」。読み上げは、元の名前)。
  収まらない数の項目は、メニューのシートに置きます。
- 出題中(`/exams/<コード>/play`)は、ドックを隠して、問題に集中できるようにします。
- メニューのシートは、Esc、背景のタップ、「閉じる」で閉じます。開いている間は、Tab の移動をシートの中に留め、閉じたら、開いたボタンにフォーカスを戻します。
- スキップリンク(「本文へ移動」)と、移動先の `main#main` は、どの幅でも残します。
- ロゴのマスコットは、名前の文字を添えるので、代替テキストを空にします。トップの横長のロゴは、文字を含む画像なので、代替テキストに名前を書きます。
  横長のロゴは文字が濃い色なので、テーマにかかわらず明るい面(`.brand-plate`)に載せます。
- リリースノートに、利用者向けの新しい版があり、まだ開いていないときは、ナビの「リリースノート」と「メニュー」に点の目印(`.unread-dot`)を付けます。
  点は飾りにして、読み上げ用の文字(「新しい更新があります」)を添えます。開発者向けの項目だけの版では、目印を付けません。
- リリースノートの種類のラベルは、種類ごとの色の `.chip` にします(機能は `tone-primary`、修正は `tone-orange`、文書は `tone-violet`、開発は `tone-muted`)。種類は、ラベルの文字でも分かります。

### 画面の幅の段階

本文の最大の幅を、画面の用途で 4 段階にします(`lib/nav.ts` の `pageWidth`)。

| 段階 | 最大の幅 | 画面 |
| --- | --- | --- |
| 読む | `max-w-2xl`(42rem) | 使い方、リリースノート、アカウント、ログイン、管理など、文章とフォームの画面 |
| 学ぶ | `max-w-3xl`(48rem) | 学習モード、直前チェック |
| 解く | `max-w-5xl`(64rem)。画面幅が xl(80rem)以上では `max-w-6xl`(72rem) | 出題の画面。問題の列と問題一覧が並ぶため、広い画面でゆとりを取る。xl 以上では、問題文と選択肢の文字と余白、問題一覧の幅も 1 段大きくする。狭い画面は変えない |
| 広い | `max-w-5xl`(64rem) | ホーム、資格の一覧、モード選択、学習の状況、実績、結果、体系ノート(左に目次を置くため。管理者のプレビューも同じ) |

### ブラウザのバーの色

- ブラウザのバーの色(`themeColor`)は、ページの背景の色にして、端末のライトとダークの設定で出し分けます(`lib/pwa.ts`。ライトはホワイト、ダークはリッチのダークの背景)。値は、`lib/palette.test.ts` が `--bg` と一致することを確かめます。
- ホーム画面に追加したときのアイコンは、淡い背景にマスコットを、余白を取って置きます(丸などに切り抜かれても欠けない)。

## 出題画面

- 問題の上に、分野(分野の色)・難易度(やさしい=緑、ふつう=橙、むずかしい=赤)・問題の種類のチップを出します(`QuestionChips`)。色だけでなく、文字で伝えます。難易度のない問題では、難易度のチップを出しません。
- 選択肢の記号は、丸いチップ(`.choice-chip`)で表します。記号は、並べた順に上から A, B, C, … と振ります。
  回答後は、正解を緑、自分の誤答を赤で示し、「正解」「あなたの回答」のタグを付けます(`ChoiceReview`。結果の画面と直前チェックでも使う)。
- 解答の表示は「まとめて最後に」(既定)と「1 問ごと」から選びます。1 問ごとのときは、「回答する」で正誤のバナーへフォーカスを移し、選択肢ごとの説明と、折りたたんだ解説を出します。回答したあとは、選択を変えられません。
  自由記述の問題は、結果の画面と同じ部品(`FreeTextScore`)で、観点ごとの判定と点数、得点と合格点を出します。
- 学習の状況の「見直す問題」には、復習プールとブックマークの数に加えて、自信なしの印(うち正解)と見直しの印を付けた問題の数を出します。
  数えるのは、読み込んだ結果の範囲で印を付けた問題の数です(同じ問題は 1 回)。
- 自信なし・見直しの印は、押した状態(`aria-pressed`)と文字で示します。問題一覧(`QuestionGrid`)は、回答済みを塗り、見直しを点、今の問題を枠で示し、読み上げでは状態を文字で添えます。
  幅の広い画面では右のパネル、狭い画面では開閉するボタンにします。
- 本番モードの残り時間は、ピル(`.timer-pill`)で示します。残り 5 分以下では赤にし、「残りわずか」と文字でも示します。
- ブックマークは、付いている間「ブックマーク中」と出します。この画面で付けたときだけ、★ が回ります(`.motion-star`)。
- 解説は、見出しごとの種類で、色(`tone-*`)とアイコン(飾り。`aria-hidden`)のカード(`.exp-card`)にします。見出しの決まりは、`docs/data-spec.md` の「解説の見出し」です。
  補足は「さらに詳しく」の折りたたみにします。シンプル表示では、カードの面と枠をやめ、左の線と見出しだけにします。

## 履歴とモードの画面

- 出題中の「直近5回」は、古い順に並べ、右端を最新にします。正解は ○、不正解は ✕、まだ解いていない回は `-` です。色だけでなく記号で示し、読み上げでは「正解、不正解、未受験」の文字で伝えます。
- モード選択の難易度は、押した状態(`aria-pressed`)と ✓ の印で示すチップにします(難易度の色は、出題画面のチップと同じ)。
- モード選択は、モードごとのカードの格子にします(狭い幅で 1 列、広がるにつれて 2 列、3 列)。カードは、色のタイルと絵文字(飾り。`aria-hidden`)、名前、説明、数などの文字を持ちます。
  カード全体を押せるようにし、フォーカスは名前のボタン(リンク)に付けて、カード全体を枠で示します。
  通常出題、復習、自由記述は、選ぶと押した状態(`aria-pressed`)と ✓ で示し、その下に出題の設定を出します。直前チェック、学習モード、セクションは別の画面へ、本番モードはそのまま出題を始めます。
  選べないカードは、点線の枠にして、理由を文字で添えます。
- モード選択の見出しは、資格コード、合格ライン、問題数をチップで示し、使い方へのリンクを置きます。問題が本番の出題数に届かない資格では、注意の色で注記を出します。
- 復習の待ちがあるときは、モード選択の「復習」のカードを、注意の色(`--warn` と `--warn-bg`)にし、「復習の待ちがあります」の文字を添えます。
- セクションの状態は、満点(★、ゆっくり光る)、合格(✓)、未達(✗)、未挑戦(-)のチップで示します。記号と文字の両方で伝えます。
- 過去の結果を開いたときは、題の下に「(過去の結果)」と出し、「最新の結果へ」の導線を置きます。紙吹雪は、最新の結果でだけ出します。

## 結果と合格予測の画面

- 結果の画面は、広い画面(`lg` 以上)で 2 列にします。右に、得点のカード・分野ごとの正答数・操作を固定し(`sticky`)、左に問題ごとの結果を並べます。狭い画面では、得点と操作を先に、問題ごとの結果をあとに、1 列で並べます。
- 得点のカードは、合格ラインに達していれば正解の色の面、達していなければ注意の色の面にし、「合格ライン到達」「合格ライン未達」と文字でも示します(色だけで伝えない)。
- 分野ごとの正答数は、リッチでは分野の色のバー、シンプルでは表にします(`DomainBars`)。バーは飾りにして、数値は文字で添えます。バーの伸びる動きは、動きを減らす設定とシンプルで止めます(`.motion-bar`)。
- 問題ごとの結果は、正誤の色の左の線(`border-l-correct` / `border-l-incorrect`)を付けます。
- 回答時間のない古い結果では、平均回答時間を出さず、ほかの表示だけで成り立つようにします。
- 合格予測は、円のゲージ(シンプルでは数字)と、合格ラインまでの差(「あと n ポイント」)を示します。優先して復習したい分野は上位 3 件をバーで示し、合格ラインより下の分野は橙のバーと「合格ラインより下」の文字にします。
  出題のない分野は、全体の正答率で代わりにしたと文字で示します。
- 実績の画面は、連続学習の日数、学習カレンダー(緑の濃淡と、色と問題数の凡例)、資格ごとの受験回数・最高点・直近の点と合格予測のカードを並べます。トップには、受験した資格の合格予測の小さなカードを出し、受験歴がないときは案内の文だけを出します。

## 学習モードの画面

- 学習モードは、分野の一覧(`/exams/<コード>/study`)、単元の一覧(`.../study/domains/<分野>`)、教科書(`.../study/<単元>`)、その場で解く問題の順にたどります。
  分野のカードは、分野の色の左の線、説明、単元と問題の数を持ちます。単元が 1 つだけの分野は、単元の一覧を飛ばします(`lib/study-nav.ts`)。
- 教科書は、パートごとのカード(`StudyCard`)にします。色の左の線と、見出しの文字(アイコンは飾り)で、パートを見分けます。
  順に、「この単元で学ぶこと」(青)、本文(灰)、図(紫)、「この単元の要点」(緑、✓ の印)、「ここがポイント」(橙)、出典(灰)です。
  本文のどの部分がどのパートかは、書き方の決まりで見分けます(`docs/data-spec.md` の「11. カリキュラムのデータ」、`lib/study-body.ts`)。
- 強調の記法 `==語==` は、橙の太い下線(`.mark-emphasis`)にします。太字とは別で、下線の形でも見分けられます(色だけに頼らない)。
- 図は、流れ、左右の比較、入れ子の階層の 3 種類です(`components/diagram.tsx`、`lib/diagram-layout.ts`)。色は、テーマの役割の色だけを使い、ライトとダーク、リッチとシンプルで同じ組になります。
  - 比較は、左を紫、右を橙の見出しにし、項目は面の色の箱にします。階層は、入れ子の深さごとに、面と枠の色を変えます。
  - 箱の文字は、折り返し、それでも収まらなければ小さくします(下限は 10px)。実データのすべての図が収まることは、`lib/diagram-fit.test.ts` が確かめます。
  - 読み上げでは、図の名前(`title`)に続けて、種類ごとの説明(流れは矢印ごと、比較は左右の項目、階層は親ごとの子)を読みます。
- その場で解く問題(`UnitPractice`)は、回答するとすぐに、正誤のバナーと解説を出します(1 問ごとの解答の表示と同じ部品)。
  正解は弾む動き(`.motion-correct`)、不正解は揺れる動き(`.motion-wrong`)で、動きを減らす設定とシンプルでは止まります。続けて正解したら、「n 連続正解」を文字で出します(2 回から)。
  回答したあとは、選択を変えられず、フォーカスは正誤のバナーへ移ります。完了の画面は、得点、次の単元(なければ次の分野)、分野の一覧、もう一度、結果の詳細を並べます。

## 要約カードの画面

- 直前チェックには、要約カード(`/exams/<コード>/cards`)と、ブックマーク(`/bookmarks`)の 2 つがあります。モード選択のカードと画面の見出しは、「直前チェック(要約カード)」「直前チェック(ブックマーク)」と、括弧で付け分けます。
- 要約カードは、1 枚ずつ表示します。広い画面(`lg` 以上)は、左に「問い」、右に「答えと決め手」を並べ、狭い画面は縦に並べます。
  問いは青の左の線、答えは、閉じているとき灰、開いたとき緑の左の線にします。決め手は橙の左の線で示します。色だけでなく、見出しと「正解」のタグの文字でも伝えます。
- 「答えを見る」は、押した状態(`aria-expanded`)を持つボタンにします。答えの欄は、開閉を読み上げ(`aria-live`)で伝えます。
- 前へ・次へで巡回します。最後のカードでは、「次へ」を「最初のカードへ戻る」に変えます。進み具合は、バーと「n / 全部 枚目」の文字で示します。
- キー操作は、出題の画面と前後(N・P)をそろえ、矢印キーと、A・Enter(答えの開閉)を足します(`lib/summary-keys.ts`)。
- カードを切り替える動きは、動きを減らす設定とシンプルで止めます(`.motion-slide-*`)。

## 体系ノートの画面

- 体系ノートは、表紙(`/exams/<コード>/notebook`)と、中分類のページ(`.../notebook/<中分類>`)の 2 種類です(仕様は [体系ノートの仕様](./specs/notebook.md))。
- 目次は、分野 → 中分類の 2 段です(`components/notebook-shell.tsx`)。広い画面(`md` 以上)は、本文の左に固定し、目次だけを縦にスクロールできます。
  狭い画面は、本文の上の「☰ 目次」で、左から出します。開くと先頭から表示し、フォーカスを「閉じる」に移します。項目を選ぶ、外側を押す、Esc、「閉じる」で閉じ、閉じたら「☰ 目次」にフォーカスを戻します。開いている間は、Tab の移動を目次の中に留めます(メニューのシートと同じ)。
  - 中分類ごとに、見出しの数を出します。見出しのない中分類は、補助の色(`text-muted`)で薄く出します(コントラストの基準は保つ)。いまの中分類は、主要な操作の色の面(`bg-soft`)と `aria-current` で示します。
- 表紙の分野のタイルは、学習モードの分野のカードと同じ形(分野の色の左の線)に、配点、見出しの数、記載のある中分類の割合(文字とバー)を並べます。
- 中分類のページは、パンくず → 題 → 導入 → 図 → 見出しごとのブロック → 比較の表 → 前後の中分類の順です(`components/notebook-view.tsx`)。見出しのない中分類は、空状態(「まだ見出しがありません」)を出します。
  - 一言は、主要な操作の色のやわらかい面(`bg-soft`)の太字にし、要点(`keyPhrase`)に、注意の色を薄く混ぜたマーカー(`.notebook-marker`)を引きます。文字は本文の色のままです。
  - 「こう聞かれる」は、注意の色の左の線と面(`border-warn`、`bg-warn-bg`)の囲みにします。
  - 確認の問いは、折りたたみ(`details`)にし、開くと「答え:」「理由:」を出します。結果は保存しません。
  - 検証の状態は、ラベル(`.chip`)で示します。検証済みは「✓ 検証済み」(正解の色)、未検証は「! 未検証」(注意の色)です。利用者の画面には、検証済みの見出しだけを出すので、未検証のラベルは管理者のプレビューにだけ出ます。
  - 比較の表は、列の幅を固定し(`table-fixed`)、文字を折り返します。取り違えやすい観点の行(`highlight`)は、注意の色の面にし、「要注意」のラベルを添えます(色だけに頼らない)。
  - 解説のコードと、表の中のコードは、狭い画面で折り返します(`.notebook-prose`)。横にスクロールさせません。
- 図の比較(`compare`)の項目の状態は、消える項目に不正解の色の斜線、残る項目に正解の色の面と太い枠で表します。読み上げの説明にも「【消える】」「【残る】」を添えます。
  狭い画面(`sm` 未満)では、比較の図を、左の側を上に、右の側を下に積んで描きます(左右に並べた図と、積んだ図を描き分け、幅で片方だけを出す)。カリキュラムの図は変えません。
- 動きは、要点のマーカーが引かれる(`.motion-marker`)、図の斜線が引かれる(`.motion-strike`)、ページの切り替え(中分類ごとに `.motion-page`)を、1 回ずつ短く出します。狭い画面の目次が左から出る動き(`.drawer-panel`)も含め、シンプルと動きを減らす設定では止め、最終の状態(マーカーと斜線が引かれた状態)を出します。
- 管理者のプレビュー(`/admin/preview/<コード>/notebook`)は、利用者の画面と同じ構成に、プレビューであることの注記(注意の色の囲み)を足し、未検証の見出しも出します。

## 資格の一覧と情報ページ

- 資格の一覧は、ベンダーごとの見出しで分け、その中を、レベルの順(`Foundational`、`Associate`、`Professional`、`Expert`、`Specialty`。レベルを持たない資格は最後)に並べます(`lib/exam-list.ts`)。広い画面(`lg` 以上)は 2 列にします。
- 各資格は、ベンダーの色のタイル(略称)、正式名、資格コード(と版)、レベルのチップで示します。ベンダーの色は、分野の色と同じ段階(`tone-domain-*`)を、ベンダーの現れた順に割り当てます。
  タイルの略称は、名前や資格コードでも読めるので、読み上げません(`aria-hidden`)。
- 近日公開の資格は、点線の枠と半透明の面(`bg-surface/60`)にし、「近日公開」のバッジ(注意の色のチップ)を付けます。半透明にするのは面だけで、文字のコントラストは落としません。
  リンクにはしません。公開中の資格の分野のメニュー(`DomainMenu`)は、そのまま残します。
- 前回の続きのカードは、グラデーションの面(`.bg-accent-gradient`)に、進み具合のバーと「続きから解く」のボタンを置きます。面の上の文字・バー・ボタンは、`--on-primary` の色にそろえます。
- 情報ページ(`/exams/<コード>/info`)は、試験の概要(合格点、問題数、試験時間、公式の情報があれば出題形式・言語・受験料・有効期間・レベル)、分野と配点(バー。シンプルでは表)、この問題集の内容、公式の試験ガイドへのリンクを並べます。
  持たない項目は出さず、空欄にしません。公式の情報には、確認した日を添えます。外部リンクは、新しいタブで開き、参照元の情報を渡しません(`rel="noopener noreferrer"`)。

## 管理者の画面

- 全問のプレビューは、問題ごとのカードに、正解(選択肢の正誤のタグ)、解説(見出しごとのカード)、出典を最初から並べます。自由記述は、観点・キーワード・配点を示します。絞り込みは、押した状態(`aria-pressed`)と ✓ で示すチップと、語の入力です。件数は `role="status"` で読み上げます。20 問ずつのページに分けます。

## 表示の設定の保存

- テーマ・画面スタイル・選択肢のシャッフルは、アカウントに保存し、端末をまたいで保ちます(`docs/app/data.md` の「表示の設定の変更の検査と、設定の Cookie」)。
- 切り替えの部品(`ThemeToggle`、`StyleToggle`)の選択は、`<html>` の属性を正とします。サーバーが最初の描画から反映した値と、同期で変わった値のどちらも、表示の選択に追従します。
- 反映のしかたによらず、見た目の切り替わり(ちらつき)を起こさないことを守ります。サーバーが反映できないとき(未ログイン、別のアカウントの Cookie)は、初回描画の前のスクリプトが、端末の設定を反映します。

## 色の変数

役割ごとの変数を、`globals.css` に置きます。画面では、値を直接書かず、変数かユーティリティ(`text-correct`、`bg-incorrect-bg`、`border-line` など)を使います。
4 通り(リッチ / シンプル × ライト / ダーク)の、どれでも同じ名前の変数がそろっています。

| 変数 | 役割 | リッチ・ライト | リッチ・ダーク | シンプル・ライト | シンプル・ダーク |
| --- | --- | --- | --- | --- | --- |
| `--bg` | ページの背景(ライトはホワイト) | `#ffffff` | `#12151a` | `#ffffff` | `#111418` |
| `--surface` | カードなどの面 | `#ffffff` | `#1b2027` | `#ffffff` | `#181c22` |
| `--text` | 本文 | `#1f2933` | `#e5e9ee` | `#1d2430` | `#e3e7ec` |
| `--muted` | 補足の文字 | `#52606d` | `#aab4bf` | `#55606d` | `#a3adb9` |
| `--border` | 縁と区切り。ライトでは、カードと背景を区別する | `#c4ccd6` | `#3a4350` | `#c4ccd6` | `#353c47` |
| `--primary` | 主要な操作 | `#1d4ed8` | `#93b4ff` | `#2a5599` | `#8fb0e0` |
| `--on-primary` | 主要な操作の上の文字 | `#ffffff` | `#0b1220` | `#ffffff` | `#0f1318` |

| `--shadow-card` / `--shadow-float` | カードの影 / 浮いたときの影 | あり(縁と合わせて、ホワイトの背景から浮かせる) | あり(濃いめ) | なし(縁で区別する) | なし |
| `--glass` / `--glass-blur` | すりガラスの面とぼかし | 半透明の面、10px | 半透明の面、10px | 面の色、0 | 面の色、0 |

- 分野の色(`--domain-1`〜`--domain-6`)は、ライトとダークで値が変わり、スタイルでは変わりません。分野の見分けを、どの表示でもそろえるためです。
- 文字に使う色(`--text`、`--muted`、`--primary`、正誤・注意、補助色、分野の色)は、`--bg` と `--surface` の両方に対して 4.5:1 以上にします。
  `*-bg` と `--soft` などの面は、`--text` と同じ組の色(`--correct-bg` には `--correct`)の両方に対して 4.5:1 以上にします。
  `--on-primary` は、`--primary` とグラデーションの両端に対して 4.5:1 以上にします。値を変えたときは、4 通りのすべてで比を確かめます。
- 角丸のユーティリティ(`rounded-sm`〜`rounded-xl`)は、角丸の段階の変数を参照します。シンプル表示に切り替えると、角丸が小さくなります。
- **ライトの背景はホワイト**です(`--bg` と `--surface` が同じ色)。カードと背景は、縁(`--border`。ホワイトに対して 1.5:1 以上)と、リッチでは影(`--shadow-card`)で区別します。
  シンプルは影がないので、縁だけで区別します。ダークは、背景と面の色が違います。
- 正誤・注意・補助色の面(`*-bg`、`--soft`、`--violet-soft`、`--orange-soft`)は、ホワイトの背景から浮いて見えるよう、背景と違う色にし、面の上の文字の比(上の基準)を保ちます。
- ラベル(`.chip`)は、色の段階(`--tone`)の色を、面の色に 16% 混ぜた面にし、文字は段階の色に本文の色を 20% 混ぜた色にします。どの段階でも、面と文字は 4.5:1 以上です。絵文字のタイル(`.tile`)は、18% を混ぜます。
  色は役割で決め、画面ごとに個別の色を足しません。正誤は、色だけでなく、文言や記号も添えます。
- 端末の設定に従うブロック(`prefers-color-scheme`)と、手動の選択(`data-theme`)の値は、同じにします。4 通りの比と、このブロックの一致は、`lib/palette.test.ts` が、`globals.css` の値から確かめます。

## リッチとシンプルの出し分け

- 見た目の違いは、CSS で出し分けます。リッチだけで出す要素には `.rich-only`、シンプルだけで出す要素には `.simple-only` を付けます
  (例: 正答率は、リッチでは円のゲージ、シンプルでは数字で見せる)。
- 部品の側(`useVisualStyle` など)で判定するのは、JavaScript で動かす演出(カウントアップ、紙吹雪)を出すかどうかだけです。
- 配色・影・角丸・グラデーション・すりガラスは、変数の値で切り替えます。部品の側で、スタイルごとにクラスを書き分けません。

## 共通クラス

部品のクラスは、`@layer components` に置きます。余白や枠の色は、ユーティリティで上書きできます。

| クラス | 使い方 |
| --- | --- |
| `.card` | 面、薄い縁、やわらかい影。余白は `p-4` などを足す。強調するときは `border-primary` を足す。リンク(`a.card`)は、触ると浮き、押すと縮む |
| `.card-dashed` | 点線の枠の面。準備中の項目や、空の状態に使う |
| `.chip` | 色付きの小さなラベル。`tone-*` と組み合わせる |
| `.tile` | 絵文字を載せる色付きのタイル。`tone-*` と組み合わせる。絵文字には `aria-hidden` を付ける |
| `tone-*` | 色の段階の元になる色(`tone-primary`、`tone-correct`、`tone-incorrect`、`tone-warn`、`tone-violet`、`tone-orange`、`tone-muted`、`tone-domain-1`〜`6`)。`.chip` と `.tile` が、`color-mix` で面と文字の色を作る |
| `.glass` | すりガラスの面(シンプル表示では、ただの面) |
| `.bg-accent-gradient` | アクセントのグラデーションの面。上の文字は `--on-primary` |
| `.h1` / `.h2` / `.h3` | ページの題 / 区切りの題 / カードの中の題 |

## 部品の決まり

- 空状態(`EmptyState`): 点線の枠に、アイコン(絵文字)、題、説明、次にすることのボタンを並べます。
  画面の全体が空状態のときは、題を `h1` にします(`headingLevel={1}`)。
- 通知(`Notice`): 種類は、エラー(`error`)、完了(`success`)、お知らせ(`info`)の 3 つです。
  色だけでなく、記号(!、✓、i)と、読み上げ用の種類の名前で、種類を伝えます。エラーはすぐに読み上げ(`role="alert"`)、ほかは控えめに読み上げます(`role="status"`)。
  文字は本文の色にします。フォームのエラー(`FormError`)も、この部品を使います。
  通知として読むもの(保存の結果、接続できないときの案内、時間切れなど)は、`role` を直接書かず、この部品を使います。
  例外は、操作(ボタンやリンク)を含む結果の画面のカードと、通知ではない読み上げの領域(絞り込みの件数、読み込み中のバッジ)です。
- 自由記述の採点基準(`RubricView`): 結果の画面(観点ごとの判定と得た点)、ブックマークの見直し(観点と配点)、
  全問のプレビュー(観点と配点とキーワード)で、同じ部品を使います。
- 読み込み中:
  - ページを移るときは、画面の上端に遷移のバーを出します。少し時間がかかったとき(0.5 秒)だけ、「読み込み中…」のバッジを出し、6 秒で消します。
    バッジは、読み上げの領域(`role="status"`)に出し入れして、スクリーンリーダーに伝えます。
  - 画面の読み込みの間は、画面の形に合わせたスケルトン(`components/page-skeletons.tsx`)と、文言付きのスピナーを出します。スケルトンは読み上げません。
  - スピナーは二重のリングです。動きを減らす設定では回らないので、文言を必ず添えます(画面に出さないときも、読み上げは残します)。

## 動き

- 動きは、CSS だけで作ります(`globals.css` の `motion-*` などのクラス)。JavaScript で動かすのは、カウントアップ(`lib/count-up.ts`)と、紙吹雪の片の配置(`lib/confetti.ts`)だけです。
- 動かすのは、`transform` と `opacity` を基本にし、レイアウトを揺らしません。

| クラス | 動き |
| --- | --- |
| `.motion-page` | ページを開いたときのフェード(`app/template.tsx`) |
| `.motion-stagger` | 一覧の子を、順に出す |
| `.motion-slide-next` / `.motion-slide-prev` | 問題カードのスライド(次へは右から、前へは左から) |
| `.motion-select` / `.motion-correct` / `.motion-wrong` | 選択肢を選んだとき / 正解 / 不正解 |
| `.motion-bar` | 進み具合のバーが伸びる |
| `.skeleton` | スケルトンの光 |
| `.motion-stamp` / `.motion-shine` / `.motion-float` | 正解のスタンプ / 満点の光 / 空状態のアイコンが漂う |
| `.confetti-piece` | 紙吹雪(合格ラインに届いたとき。満点は量を増やす) |
| `.nav-progress-fill` / `.loading-badge` / `.spinner` | 遷移のバー / 読み込み中のバッジ / スピナー |
| `.nav-indicator` / `.sheet-panel` | サイドバーの選択中の背景が滑る / メニューのシートが下から出る |
| `.motion-star` | ブックマークを付けたときに ★ が回る |
| `.motion-marker` / `.motion-strike` / `.drawer-panel` | 体系ノートの要点のマーカーが引かれる / 図の消える項目の斜線が引かれる / 狭い画面の目次が左から出る |
| `.section-perfect` | セクションの満点の印が、ゆっくり光る |

- 止める一覧を、`globals.css` の末尾に 2 つ持ちます。動きを足したときは、両方の一覧に名前を足します。
  - 動きを減らす設定(`prefers-reduced-motion: reduce`): 上の動きをすべて止め、終わりの状態だけを見せます。
  - シンプル表示: 飾りの動きを止めます。遷移のバーとスピナーは、待っていることを伝えるので動かします(バーの光は流しません)。
- すべての `transition` と `animation` をまとめて止めるやり方は、使いません。フォーカスの見た目などまで消えてしまうためです。
  フォーカスの枠は、スタイルと動きの設定にかかわらず出します。

## 絵文字

- 絵文字は飾りとして使い、`aria-hidden="true"` を付けて読み上げません。意味は、題や説明の文字で伝えます。
- 絵文字だけで、状態や種類を伝えません(正誤や通知の種類は、文字と記号で添えます)。
- 文字は、端末に入っているフォントで表示します(欧文、和文、絵文字の順)。ビルド時にも表示時にも、外部へフォントを取りに行きません。

## 新しい画面を足すとき

新しいモードや画面は、実装の前に、短い仕様を書いて承認を得ます。書き方は[画面の仕様のひな形](../ui-spec-template.md)にあります。
仕様は、この文書の方針(トーン、画面スタイル、配色、余白、ライト / ダーク)を再利用する前提で書きます。
