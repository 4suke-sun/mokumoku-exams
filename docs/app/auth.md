# 認証の仕組み(ログイン・再設定・セッション)

招待された人だけが使える、Cognito UserPool による認証です。セルフサインアップはできません。
ログインを必須にする(保護された画面と API での拒否)のは、別の段階で行います。この版は、ログインに必要な画面と仕組みまでです。

## 構成

- 画面(`/login`、`/forgot-password`、`/account`)は、アプリのサーバー(`/api/auth/*`)を呼びます。ブラウザは Cognito を直接呼びません。
- サーバーは、Cognito の認証 API(認証情報のいらない操作)を `fetch` で呼びます(`packages/app/src/lib/auth/cognito.ts`)。
  クライアントはシークレットを持たず、これらの操作は IAM の署名が要らないため、Lambda に追加の権限はありません。
- 認証の実装は、`AuthProvider`(`lib/auth/types.ts`)の境界で差し替えられます。本番は Cognito、手元の開発とテストは代替です。

## トークンの扱い

| Cookie | 中身 | 有効期間 |
| --- | --- | --- |
| `mokumoku_id` | ID トークン | Cognito の指定(1 時間) |
| `mokumoku_access` | アクセストークン | 同上 |
| `mokumoku_refresh` | リフレッシュトークン | 30 日 |

- すべて `HttpOnly`(JavaScript から読めない)、`SameSite=Lax`、本番は `Secure` です。トークンは、画面にも API の応答の本文にも出しません。
- ブラウザは、ログイン状態を `GET /api/auth/session` で確かめます。期限の 5 分前に `POST /api/auth/refresh` で更新します。
  更新できなければ(リフレッシュトークンの期限切れ、無効化)、Cookie を破棄してログイン画面へ戻します。通信の失敗では戻しません(次の機会に再試行します)。
- ログアウトは、リフレッシュトークンを Cognito 側で無効にし、3 つの Cookie を破棄します。無効にできなくても、Cookie は破棄します。
- 状態を変える `POST` は、JSON だけを受け付け、ブラウザが「別サイトから」と示したもの(`Sec-Fetch-Site`)を断ります。
- この版のサーバーは、トークンの署名を検証しません(画面の表示と更新の時刻の判断にだけ、本文を読みます)。署名の検証と認可は、ログイン必須化の段階で行います。

## 画面

| 画面 | 内容 |
| --- | --- |
| `/login` | メールアドレスとパスワードでログイン。招待直後は、仮パスワードでログインすると、新しいパスワードを決める入力に切り替わる |
| `/forgot-password` | メールアドレスを入れると確認コードを送る。コードと新しいパスワードを入れて再設定する。登録の有無は、画面では分からない |
| `/account` | ログイン中のメールアドレス、パスワードの変更、表示テーマと選択肢のシャッフルの設定 |

パスワードの規則は、12 文字以上で、英大文字・英小文字・数字を含むことです(`packages/infra` の UserPool の設定と同じです)。

## 手元での確認(AWS に接続しない)

```sh
AUTH_FAKE=1 npm run dev
```

`AUTH_FAKE=1` のとき(`NODE_ENV` が `production` でない場合だけ)、メモリ上の代替の認証が使われます。サーバーを再起動すると、状態は戻ります。

| 用途 | 値 |
| --- | --- |
| ログインできるユーザー | `learner@example.com` / 接頭辞・`Example`・数字を `-` でつないだ文字列(値は `lib/auth/fake.ts` の `FAKE_USER_PHRASE`) |
| 初回ログイン(新しいパスワードを決める)のユーザー | `invited@example.com` / 同じ形の文字列(`FAKE_INVITED_PHRASE`) |
| パスワード再設定の確認コード | `FAKE_RESET_CODE`(`lib/auth/fake.ts`) |

これらは、手元の動作確認のための架空の値です。実在の認証情報ではなく、本番(`NODE_ENV=production`)では代替の認証が無効になります。

## 招待とパスワード再設定のメール

- 招待メールは、管理者が Cognito でユーザーを作ると送られます。件名・本文・仮パスワードの有効期限(7 日)は `packages/infra/lib/auth-stack.ts` で定めています。
  本文にサイトの URL は入れません(配信のドメインが環境ごとに違うため)。管理者が、招待と一緒にサイトの URL を伝えます。
- パスワード再設定は、確認コード方式です。コードの有効期間は Cognito の固定(1 時間)です。
- メールの送信元は、Cognito の既定のもの(1 日あたりの送信数に上限があります)。独自の送信元は、独自ドメインの段階で扱います。

## 環境変数

| 変数 | 設定する場所 | 内容 |
| --- | --- | --- |
| `COGNITO_CLIENT_ID` | Lambda(スタックが自動で設定) | 認証で使う UserPool クライアントの ID |
| `AWS_REGION` | Lambda(実行環境が設定) | 認証 API を呼ぶリージョン |
| `AUTH_FAKE` | 手元の開発だけ | `1` で代替の認証を使う |
