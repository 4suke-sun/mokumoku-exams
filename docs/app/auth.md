# 認証の仕組み(ログイン・再設定・セッション)

招待された人だけが使える、Cognito UserPool による認証です。セルフサインアップはできません。
ログインしていない人は、ログイン画面と再設定の画面以外を開けません(「ログイン必須化」の節)。

## 構成

- 画面(`/login`、`/forgot-password`、`/account`)は、アプリのサーバー(`/api/auth/*`)を呼びます。ブラウザは Cognito を直接呼びません。
- サーバーは、Cognito の認証 API(認証情報のいらない操作)を `fetch` で呼びます(`packages/app/src/lib/auth/cognito.ts`)。
  クライアントはシークレットを持たず、これらの操作は IAM の署名が要らないため、Lambda に追加の権限はありません。
- 管理者の画面の、利用者の一覧・招待・無効化だけは、Cognito の管理 API(IAM の署名が要る操作)を SDK で呼びます(`lib/auth/user-admin.ts`)。
  Lambda には、この 3 つの操作だけを、その UserPool に限って許しています([インフラ](./infra.md))。
- 認証の実装は、`AuthProvider`(`lib/auth/types.ts`)の境界で差し替えられます。本番は Cognito、手元の開発とテストは代替です。

## トークンの扱い

| Cookie | 中身 | 有効期間 |
| --- | --- | --- |
| `mokumoku_id` | ID トークン | Cognito の指定(1 時間) |
| `mokumoku_access` | アクセストークン | 同上 |
| `mokumoku_refresh` | リフレッシュトークン | 30 日 |

- すべて `HttpOnly`(JavaScript から読めない)、`SameSite=Lax`、本番は `Secure` です。トークンは、画面にも API の応答の本文にも出しません。
- ブラウザは、ログイン状態を `GET /api/auth/session` で確かめます。期限の 5 分前に `POST /api/auth/refresh` で更新します。
  更新できなければ(リフレッシュトークンの期限切れ、無効化)、Cookie を破棄してログイン画面へ戻します。通信の失敗では戻しません(次の機会に再試行します)。
- ログアウトは、リフレッシュトークンを Cognito 側で無効にし、3 つの Cookie を破棄します。無効にできなくても、Cookie は破棄します。
  端末(localStorage)の学習の記録は消しません(下の「持ち主の印」のとおり、アカウントごとにキーが分かれるので、次のアカウントには混ざりません)。
- 状態を変える `POST` は、JSON だけを受け付け、ブラウザが「別サイトから」と示したもの(`Sec-Fetch-Site`)を断ります。
- 画面の表示と更新の時刻の判断のために、ブラウザ側と `/api/auth/session` は ID トークンの本文を読みます(署名は確かめません)。
  **認可の判断には使いません。** 認可は、次の「ログイン必須化」の、サーバー側の検証だけで行います。
- **持ち主の印**: ログイン中の `GET /api/auth/session` の応答は、`signedIn`・`email`・`expiresAt`・`isAdmin` に加えて、`owner`(持ち主の印)を返します。
  印は、ID トークンの `sub` の SHA-256 の先頭 16 文字です(`lib/owner-tag.ts`。設定の Cookie の持ち主の照合と同じ作り)。印から `sub` には戻せず、`sub` そのものは応答に入れません。
  画面は、印を端末の学習の記録のキーに入れ、ログインしているアカウントの記録だけを読み書きします(規則は [データの設計](./data.md) の「端末の結果(localStorage)との関係」)。
  印は端末には保存せず、ページを開くたびに、この応答から受け取ります。印は端末の記録を分けるためだけに使い、認可の判断には使いません。

## ログイン必須化(サーバー側の ID トークンの検証)

`proxy.ts` が、すべてのリクエストの入り口で ID トークンをサーバー側で検証します(`lib/auth/guard.ts` の `authenticate`)。

- **ログインなしで開ける経路**: `/login`、`/forgot-password`、`/_next/*`、認証の API のうち列挙した 7 つ(`login`・`new-password`・`forgot-password`・`reset-password`・`refresh`・`logout`・`session`)と、
  ブラウザや検索エンジンが Cookie なしで取りに来るファイル(`/manifest.webmanifest`、`/robots.txt`、`/sitemap.xml`、`/sw.js`、`/icons/` の列挙した 3 つ)と、ログインの画面にも出すロゴ(`/brand/` の 2 つ)だけです。どのファイルも、秘密の情報を含みません。
  ほかは、すべて検証が通らないと開けません(`/api/auth/change-password` や、資格の一覧・ヘルプも同じです)。列挙は完全一致で、大文字小文字、末尾のスラッシュ、`..`・`%`・`\` を含むものでは広げられません。新しい認証の API とファイルは、列挙に足さない限り保護されます。
  画面・API・ファイルの経路の一覧は `packages/app/src/authorization.test.ts` に固定してあり、新しい画面や API、`public/` のファイルを足すと、一覧に足すまでテストが落ちます(公開するか、保護するかを、意識して決めるためです)。
- **`public/` のファイルの配信**: 本番では、`public/` のファイル(`/brand/*`・`/icons/*`・`/sw.js`)は、CloudFront が S3 から配り、入口を通りません(「インフラの構築とデプロイ」)。
  このため、この 3 つの経路に置いたファイルは、上の列挙によらず、ログインなしで取れます。公開してよいものだけを置きます。
  `public/` のほかの場所に置いたファイルは、本番では配られません(CloudFront の振り分けを足すまで、Lambda へ渡って見つからない)。
- **未ログインのとき**: 画面は `/login?next=<元の場所>` へ移します。API は `401` を返します。`next` は、このサイト内の画面だけを受け付けます(`lib/auth/redirect.ts`)。
- **検証の内容**(`lib/auth/verify.ts`): 署名(RS256、Cognito の公開鍵)、発行元(`iss`)、クライアント(`aud`)、用途(`token_use=id`)、有効期限(`exp`)、`sub` の形、`cognito:groups` の形(文字列の配列)。
  どれか 1 つでも合わなければ拒否します。公開鍵は Cognito の JWKS から取り、メモリに 1 時間保ちます。取得できないときも、拒否します(通す側には倒しません)。
  依存は足さず、Node の `crypto` を使います。
- **更新**: ID トークンの Cookie が期限で消えていても、リフレッシュトークンが有効なら、その場で更新して通します(新しい Cookie を応答に付けます)。
- **設定の不備**(Cognito の設定がない、など): `503` で断ります。通す側には倒しません。
- 環境変数: `COGNITO_USER_POOL_ID` と `COGNITO_CLIENT_ID`(どちらも CDK が Lambda に渡します)。

認可の主体は、検証で得た `sub` だけです。履歴の API を含め、リクエストの本文や問い合わせから利用者の識別子を受け取りません(`docs/app/data.md`)。

## 管理者の画面

`/admin` 以下の画面と `/api/admin` 以下の API は、管理者だけが開けます。

- **管理者の判定**: 検証した ID トークンの `cognito:groups` に、管理者のグループ(`admins`)があることです(`lib/auth/admin.ts`)。
  グループ名は `packages/infra` の UserPool のグループと同じ値で、両方のテストで固定しています。
  問い合わせ・ヘッダー・Cookie などで管理者だと申告されても、使いません。
- **2 か所で確かめます**: 守りの本体は入口(`proxy.ts`)で、すべてのリクエストで確かめます。管理者の画面の共通のレイアウト(`app/admin/layout.tsx`)は、入口を通らなかったときの補助です
  (レイアウトは、画面の中の移動では、もう一度は動かないことがあるため、レイアウトだけには頼りません)。
  管理者の API を足すときは、API の本体でも `authenticateAdmin` で確かめます。
  `/api/admin` の外にある管理者だけの操作(テスト通知の `POST /api/push/test`)は、入口では通常のログインだけを確かめ、API の本体の `authenticateAdmin` で管理者かを確かめます
  (管理者でなければ `403`、未ログインは `401`。[データの設計](./data.md) の「通知の購読」)。
- **管理者でないとき**: 画面はホームへ移します。API は `403`(`{ "error": "forbidden" }`)を返します。未ログインのときは、ほかの画面と同じくログイン画面へ移します(API は `401`)。
- 経路の判定は、符号化(`%61` など)・大文字小文字・重なったスラッシュをならしてから行います。ならせない経路は、管理者の経路として扱います。
- **ナビゲーション**: 「管理」の項目は、管理者にだけ出します。表示の判断には `GET /api/auth/session` の `isAdmin` を使います。
  これは表示のためだけの値で(ID トークンの本文を、署名を確かめずに読んだもの)、開けるかどうかは、上の 2 か所の検証で決まります。
- 利用者を管理者のグループに入れる操作は、Cognito のコンソールなどで行います。

### 利用者の管理(一覧・招待・無効化)

`/admin` の画面で、次の操作ができます。

- **一覧**: メールアドレス、状態(有効、招待中、無効など)、作成日を、作成日の新しい順に出します。
- **招待**: メールアドレスを入れて招待します。Cognito が招待メール(仮のパスワードつき)を送り、招待された人は、仮のパスワードでログインすると、新しいパスワードを決める入力に進みます(「招待とパスワード再設定のメール」の節)。
- **無効化**: 「無効にする…」を押すと確認が出て、もう一度「無効にする」を押したときだけ実行します。無効にした利用者は、以降ログインもトークンの更新もできません。ただし、すでに持っている ID トークンは、有効期限(1 時間)まではサーバー側の検証を通るため、ログインしたままの画面は最長 1 時間で使えなくなります。
  自分自身は無効にできません(画面に操作を出さず、API も `400` で断ります)。無効化を元に戻す操作は、画面にはありません(Cognito のコンソールなどで行います)。
- **管理者を増やす**: アプリからは、管理者を作れません(昇格の操作と、管理者のグループへの追加の権限は、持ちません)。Cognito は、グループ名を IAM の条件で絞れないため、アプリの Lambda に、グループへの追加を許すと、侵害されたときに、任意のユーザーを管理者にできるからです。管理者を増やすのは、アカウントの持ち主が、Cognito のコンソールか AWS CLI で、自分の権限で行います。
  - 対象のユーザーを、UserPool のグループ `admins` に加えます(CLI の例: `aws cognito-idp admin-add-user-to-group --user-pool-id <UserPool の ID> --username <ユーザー名> --group-name admins`)。
  - 加えたユーザーは、次にログインしたときから(新しい ID トークンに、グループが入ってから)管理者の画面を開けます。
- **全問のプレビュー**: 管理者の画面から、資格ごとの全問の正解・解説・出典を一覧できます(`/admin/preview`)。分野・難易度・問題の種類・語で絞り込めます。`/admin` 以下なので、入口(proxy)とレイアウトの両方で管理者を確かめます。
- **操作の記録**: 無効化のあとに、DynamoDB に記録を残します(`PK=ADMIN`、`SK=AUDIT#{時刻}#{対象}`。[データの設計](./data.md))。
  記録には、操作した管理者の `sub`(検証した ID トークンの値)、対象の Cognito のユーザー名、操作の種類、時刻だけを入れ、メールアドレスは入れません。
- **メールアドレスの扱い**: 画面にだけ出します。サーバーのログ、操作の記録、エラー応答には出しません。

| メソッドと経路 | 内容 |
| --- | --- |
| `GET /api/admin/users` | 利用者の一覧(`{ "users": [{ "username", "email", "status", "enabled", "createdAt", "self" }] }`)。問い合わせのパラメーターは受け付けない |
| `POST /api/admin/users` | 招待する(本文は `{ "email" }`)。結果の利用者を返す |
| `POST /api/admin/users/disable` | 無効にする(本文は `{ "username" }`。ユーザー名は、この UserPool では `sub` と同じ値)。操作の記録を残す |

- どれも、入口(`proxy.ts`)と API の本体(`authenticateAdmin`)の両方で、管理者かを確かめます。API の本体は、管理者でないときも未ログインのときも `403` を返します。
- 操作した管理者は、検証した ID トークンの `sub` だけで決めます。本文に未知の項目(`sub`、`actor` など)があれば `400` です。
- `POST` は、JSON だけを受け付け、別サイトからの送信を断ります。本文は 1KB までです。
- エラー応答は `{ "error": "<種類>" }` だけです: `bad-request` 400、`self-disable` 400、`forbidden` 403、`not-found` 404、`already-exists` 409、`too-large` 413、`limit-exceeded` 429、`unavailable` 503。
  無効化のあとに記録を残せなかったときも `503` です(無効化そのものは済んでいることがあるので、一覧を読み直して状態を確かめます)。

## 画面

| 画面 | 内容 |
| --- | --- |
| `/login` | メールアドレスとパスワードでログイン。招待直後は、仮パスワードでログインすると、新しいパスワードを決める入力に切り替わる |
| `/forgot-password` | メールアドレスを入れると確認コードを送る。コードと新しいパスワードを入れて再設定する。登録の有無は、画面では分からない |
| `/account` | ログイン中のメールアドレス、パスワードの変更、表示テーマと選択肢のシャッフルの設定、通知の購読([データの設計](./data.md) の「通知の購読」) |
| `/admin` | 管理者だけが開ける画面。利用者の一覧・招待・無効化(「管理者の画面」の節) |
| `/admin/preview` | 管理者だけが開ける画面。全問のプレビュー |

パスワードの規則は、12 文字以上で、英大文字・英小文字・数字を含むことです(`packages/infra` の UserPool の設定と同じです)。

## 手元での確認(AWS に接続しない)

```sh
AUTH_FAKE=1 npm run dev
```

`AUTH_FAKE=1` のとき(`NODE_ENV` が `production` でない場合だけ)、メモリ上の代替の認証が使われます。サーバーを再起動すると、状態は戻ります。
管理者の画面の招待・無効化と操作の記録も、メモリ上の代替で動き、ログインに反映されます。代替で招待した利用者の仮のパスワードは、`FAKE_INVITED_PHRASE` です。

| 用途 | 値 |
| --- | --- |
| ログインできるユーザー | `learner@example.com` / 接頭辞・`Example`・数字を `-` でつないだ文字列(値は `lib/auth/fake.ts` の `FAKE_USER_PHRASE`) |
| 初回ログイン(新しいパスワードを決める)のユーザー | `invited@example.com` / 同じ形の文字列(`FAKE_INVITED_PHRASE`) |
| 管理者のグループに入っているユーザー | `admin@example.com` / 同じ形の文字列(`FAKE_ADMIN_PHRASE`) |
| パスワード再設定の確認コード | `FAKE_RESET_CODE`(`lib/auth/fake.ts`) |

これらは、手元の動作確認のための架空の値です。実在の認証情報ではなく、本番(`NODE_ENV=production`)では代替の認証が無効になります。

## 招待とパスワード再設定のメール

- 招待メールは、管理者が管理者の画面で招待する(Cognito でユーザーを作る)と送られます。件名・本文・仮パスワードの有効期限(7 日)は `packages/infra/lib/auth-stack.ts` で定めています。
  本文にサイトの URL は入れません(配信のドメインが環境ごとに違うため)。管理者が、招待と一緒にサイトの URL を伝えます。
- パスワード再設定は、確認コード方式です。コードの有効期間は Cognito の固定(1 時間)です。
- メールの送信元は、Cognito の既定のもの(1 日あたりの送信数に上限があります)。独自の送信元は、独自ドメインの段階で扱います。

## 環境変数

| 変数 | 設定する場所 | 内容 |
| --- | --- | --- |
| `COGNITO_CLIENT_ID` | Lambda(スタックが自動で設定) | 認証で使う UserPool クライアントの ID |
| `COGNITO_USER_POOL_ID` | Lambda(スタックが自動で設定) | ID トークンの検証と、管理者の画面の管理 API で使う UserPool の ID |
| `AWS_REGION` | Lambda(実行環境が設定) | 認証 API を呼ぶリージョン |
| `AUTH_FAKE` | 手元の開発だけ | `1` で代替の認証を使う |
