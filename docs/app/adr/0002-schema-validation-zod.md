# 0002. データの検証に Zod を使う

- 状態: 採用
- 日付: 2026-10-08

## 背景

資格マスタと問題データ(JSON)の形と整合を、機械的に検査する必要があります。同じスキーマの型を、検査スクリプトと、アプリ側で共有したい、という要件があります。

## 決定

スキーマの定義と検査に **Zod** を使います。スキーマの正本は `packages/data-schema/src/exam-data/schema.ts` で、型はスキーマから導きます。
ファイルをまたぐ検査(分野がマスタにあるか、ファイルの有無など)は、通常のコードで書きます。

## 理由

- スキーマから TypeScript の型を作れるので、検査と型が食い違いません。アプリ側(`packages/app`)で同じ型を使えます。
- 1 つの問題の中の整合(正解が選択肢にあるか、種類と正解の数が一致するか)を、スキーマの中に書けます。
- 検査の結果に、入力の値は含まれません(場所と種類だけ)。「値を引用せず、場所と種類で報告する」方針に合います。
- JSON Schema への変換が組み込まれているので、エディタの補完用のスキーマが必要になったときに出力できます。

## 採用しなかった選択肢

- 手書きの検証: 依存は増えませんが、型と検証を二重に管理することになり、スキーマが増えると保守が重くなります。リリースノートの検証は、構造が小さいため、手書きのままにしています。
- JSON Schema とその検証ライブラリ: 言語に依存しない仕様にできますが、型を別に作る必要があります。1 つの問題の中の整合も、書きにくくなります。

## 影響

- 開発用の依存が 1 つ増えます。
- ファイルをまたぐ検査は、Zod の機能ではなく、通常のコードで書きます。
- アプリ側で型を共有するときは、スキーマを共有のパッケージに移す必要があります(実装する版で判断します)。
