# 0020. 書き出しは、出典の URL と公式ページの題を公開データに載せる

- 状態: 採用
- 日付: 2026-10-26
- 置き換える ADR: 0014

## 背景

問題の出典(`references`)は `{ title, url }` の形で、題は任意です。画面は、題があれば題を、なければ URL のホスト名を出します。
書き出し(`export`)が URL だけを入れると、パイプラインで足した問題の出典は、ホスト名で表示されます。画面の出典を、できるだけ公式ページの題で出すために、題を入れる方法を決める必要があります。

## 決定

- 問題ごとに、根拠の事実カードと出典(台帳の項目)を結ぶ**来歴**を持ちます。来歴は pipeline の側に置き、下書きの ID を鍵にします。
  書き出したときに、採番した問題の ID を、その項目に書き戻します。書き出し済みの下書きは、再び書き出しません。
- 公開データ(`data/`)に載せるのは、出典の URL と、公式ページの題です。事実カード、言い換え、作業の記録は載せません。
- 題は、**台帳の出典に持たせます**。収集(`collect`)が出典を取得するとき、取得した本文の `<title>` から取ります(数値の実体参照と、`&amp;` `&lt;` `&gt;` `&quot;` `&apos;` `&nbsp;` の 6 種の名前付きの実体参照(名前の大文字小文字は区別しない)を戻し、空白をそろえる。ほかの名前付きの実体参照は、そのまま残る)。
  台帳は本文を持たない決まりなので、題は短い文字列として持ち、データの契約の出典の題と同じ規則(空白だけは不可、URL を含めない、200 文字以内)で絞ります。規則に合わない題は持ちません。
- 既存の台帳の出典に題を足すには、`collect <資格コード> --titles` を使います。題のない出典だけを取得し、題以外の項目(本文のハッシュ、取得日、状態、検査の記録)は変えません。
- 書き出しは、来歴の出典の URL ごとに、台帳の題を付けます。台帳の題は、収集が取得するたびに、取れた題で更新されます。書き出しは、そのときの台帳の題を付けます(すでに公開した問題の題は、書き出しも `export --titles` も変えません)。同じ題にそろえるのは、題のない出典を足すときで、データにすでにある同じ URL の題を先に使います。台帳に題がない出典は、**題なしで書き出し**、`題が取れない出典` として報告します(書き出しは止めません)。
- すでに公開している問題の、題のない出典には、`export <資格コード> --titles` で題を足します。書いたあとにデータの検査を通し、失敗したら元に戻します。題が取れない出典が残ると、`collect --titles` と `export --titles` は終了コード 1 で終わります(`--dry-run` は取得も書き込みもしないので 0)(書き出しは、題が取れなくても止めません)。題は、データにすでにある同じ URL の題を先に使い、なければ台帳の題を使います。どちらもなければ足さず、報告します。
- 公開した問題の**正は `data/`** です。書き出し(`export`)は、人が承認し、来歴の検査を通った下書きを、作業ツリーの
  `data/questions.<コード>.json` に追加します。ほかの問題は変えません。書いたあとにデータの検査を通し、失敗したら書き出し前に戻します。
  「差分として出力する」は、この作業ツリーの差分を指します。人が差分と差分レポートを確かめ、通常の PR で取り込みます。
- 問題の識別子は、変えません。削除した問題の ID は、資格マスタの `retiredQuestionIds` に足し、再び使いません。採番は、今の問題・退役した ID・書き出し済みの来歴の ID を含めた最大の番号の次から行います。

## 理由

- 台帳はコミットされ、取得した本文のキャッシュ(保持の期間と容量に上限がある作業用の置き場)に依らずに、題を取り出せます。
- 公式ページの `<title>` は、ページの題という事実で、本文の写しではありません。長さと形を絞れば、台帳に本文が入りません。
- 題を取れない出典があっても、書き出しを止めずに報告すれば、問題の追加が題の取得に妨げられず、あとから足せます。
- 作業ツリーに書けば、PR の差分の確認・整形の検査・データの検査が、手で問題を足すときと同じ流れで動きます。

## 採用しなかった選択肢

- 取得済みの本文のキャッシュ(`pipeline-work/`)の `<title>` を、書き出しのときに読む: キャッシュは保持の期間と容量に上限があり、本文がなければ題が取れないため、書き出しの結果がキャッシュの状態で変わります。
- 題が取れない出典があるとき、書き出しを止める: 題は表示のための情報で、問題の正しさと関係がないため、止めません。
- `title` をデータの契約で必須にする: カリキュラムの節の出典(`docs/data-spec.md` の「11. カリキュラムのデータ」)にも同じ形が使われ、影響が広がります。題の有無は、報告で数えます。
- パッチのファイルとして出す: 人が当てる手間が増え、当てたあとの検査の流れが、手で足すときと分かれます。

## 影響

- ADR 0014 は「置き換え済み」になります。
- 台帳のスキーマに、任意の `title` が加わります。古い記録は、そのまま読めます。
- データの検査(`npm run validate:data`)は、退役した ID を問題が使うと失敗にします。CI の `npm run check:retired-ids` は、main から削除した問題の ID が `retiredQuestionIds` にないと失敗にします。
