# 0014. 書き出しは作業ツリーの `data/` に書き、人が PR の差分で確かめる

- 状態: 置き換え済み(置き換えた ADR: 0020)
- 日付: 2026-10-16
- 置き換える ADR: 0008

## 背景

ADR 0008 は、来歴を問題ごとに持ち、pipeline は `data/` を直接は書き換えず、追加・更新を差分として出力する、としていました。
来歴の項目は、下書きの ID が鍵で、問題の ID は書き出しのときに採番します。書き出しの方式と、来歴に問題の ID を書き戻す時点を決める必要があります。

## 決定

- 問題ごとに、根拠の事実カードと出典(台帳の項目)を結ぶ**来歴**を持ちます。来歴は pipeline の側に置き、下書きの ID を鍵にします。
  書き出したときに、採番した問題の ID を、その項目に書き戻します。書き出し済みの下書きは、再び書き出しません。
- 公開データ(`data/`)に載せるのは、出典の URL だけです。事実カード、言い換え、作業の記録は載せません。
- 公開した問題の**正は `data/`** です。書き出し(`export`)は、人が承認し、来歴の検査を通った下書きを、作業ツリーの
  `data/questions.<コード>.json` に追加します。ほかの問題は変えません。書いたあとにデータの検査を通し、失敗したら書き出し前に戻します。
  「差分として出力する」は、この作業ツリーの差分を指します。人が差分と差分レポートを確かめ、通常の PR で取り込みます。
- 問題の識別子は、変えません。削除した問題の ID は、資格マスタの `retiredQuestionIds` に足し、再び使いません。採番は、今の問題・退役した ID・書き出し済みの来歴の ID を含めた最大の番号の次から行います。

## 理由

- 作業ツリーに書けば、PR の差分の確認・整形の検査・データの検査が、手で問題を足すときと同じ流れで動きます。パッチのファイルを別に扱う手間がいりません。
- 書いたあとにデータの検査を通し、失敗したら戻すので、検査に落ちる `data/` が作業ツリーに残りません。
- 来歴を下書きの ID で持つと、書き出しの前から根拠をたどれます。書き出しのあとは、問題の ID でもたどれます。
- 退役した ID を資格マスタに残すと、最大の番号の問題を削除したあとでも、同じ番号を採番しません。

## 採用しなかった選択肢

- パッチのファイルとして出す: 人が当てる手間が増え、当てたあとの検査の流れが、手で足すときと分かれます。
- 退役した ID を main の ID の集合との比較だけで知る: 同じ変更の中の削除と再追加しか見つけられず、削除が main に入ったあとの再追加を見つけられません。

## 影響

- ADR 0008 は「置き換え済み」になります。
- データの検査(`npm run validate:data`)は、退役した ID を問題が使うと失敗にします。CI の `npm run check:retired-ids` は、main から削除した問題の ID が `retiredQuestionIds` にないと失敗にします。
