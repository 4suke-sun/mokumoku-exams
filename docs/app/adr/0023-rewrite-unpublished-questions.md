# 0023. 非公開の問題の書き直しは、パイプラインが扱い、元の ID のまま公開へ戻す

- 状態: 採用
- 日付: 2026-10-27
- 補う ADR: 0012、0019、0022

## 背景

質を上げる機構では、判定役(ADR 0021)が公開の問題を「公開 / 書き直しで復帰できる / 非公開」に判定し、基準を満たさない問題は、非公開のファイルへ移す(ADR 0022)。
判定が「書き直しで復帰できる」の問題は、論点は成り立つが書き方が基準を満たさない。書き直して、同じ ID で公開へ戻したい。ID は受験履歴・ブックマーク・復習が参照するので、変えない。

既存の決まりとは、次の点で合わない。

- ADR 0012 は、パイプラインは公開済みの問題に足すだけで、直す・取り下げるのはパイプラインの外の通常の変更とする。非公開の問題の書き直しは、1 問ずつ人が直す作業ではなく、数が多くなる前提(LLM が判定し、LLM が書き直し、人は一覧と抜き取りで確かめる)で作る。
- ADR 0019 の直しは、保留の下書きを直し、設問文か根拠を変えると、新しい下書きの ID(`revisionOf`)になる。元の下書きへの人の判断は引き継がない。書き直しは、公開の ID を持つ非公開の問題が元で、ID を引き継ぐ。
- 書き出し(`export`)は、承認した下書きに ID を採番して公開に足す。書き直した問題は、採番せず、元の ID のまま、非公開のファイルから公開のファイルへ移す。

## 決定

- **書き直しはパイプラインが扱う**(ADR 0012 の「直す・取り下げるのはパイプラインの外」への補い)。ただし、対象は非公開のファイルの問題だけで、公開の問題は、これまでどおり変えない(公開の問題を変えるのは、公開から非公開へ移してから)。
- **ADR 0019 の直しとは別の種類にする**(下書きの直しの決まりは変えない)。書き直しの下書きは、`revisionOf` ではなく `rewriteOf`(元の問題の ID)を持つ。
  - 取り込みは、下書きと同じ検査(形、スタイル規則、誤答、根拠、写し、重複)を通る。計画の項目を持たないので、問題の ID から決めた項目の ID を使う。
  - 検証(`verify`)・人の確認・判断の記録は、下書きと同じ。ただし、抜き取りの対象にしない(次の「公開へ戻す条件」)。
  - 書き直しの下書きを、さらに直す(`draft --revise`)と、直した下書きも `rewriteOf` を引き継ぎ、同じ内容かの比較を受ける。
  - 書き出し(`export`)は、書き直しの下書きを対象にしない(採番しない)。
- **書き直す対象**は、非公開のファイルで判定が `rewritable` の、選択式の問題だけ。`unpublish` の判定、自由記述は対象にしない。理由コードごとの絞り込みはしない(理由コードは、書き直しの依頼に、直す方向として載せる)。
- **書き直しの入力**(`draft --rewrite` の依頼の `rewrite`): 現行の本文、判定の理由コード、元の根拠の事実カードの ID、根拠の節の場所。`facts` には、元の根拠の事実カードを先頭に、周辺の事実カードを載せる(下書きの直しと同じ選び方)。役は `question-reviser` を使い、定義に書き直しの依頼を足す(役とモデルの表は変えない。表の置き場は ADR 0021)。
  - 元の根拠は、来歴(`provenance/`)の、その問題の ID を持つ項目から引く。来歴のない問題(パイプラインで作っていない問題)は、材料がそろわないので書き直さない(報告する)。現行の作り方で作り直すのは、別の作業(資格ごとの更新)で行う。
- **同じ内容であることの確かめ**は、機械で比べる。次の 3 つがすべて同じ。違うものは、取り込みで不採用(理由コード `rewrite:domain-changed`・`rewrite:references-changed`・`rewrite:topic-changed`)にする。公開へ戻すときにも、もう一度比べる。
  - 分野。
  - 出典の URL の集合(書き直しの根拠の事実カードの出典と、元の問題の `references`)。
  - 論点。問題データには論点の項目がないので、根拠の事実カードの、分野と出題範囲の項目の組の集合で比べる(元の根拠は来歴から引く)。
- **公開へ戻す条件**(`restore` コマンド)。次のすべてを満たす書き直しの下書きだけを戻す。満たさないものは、理由を報告して戻さない。
  1. 元の問題が非公開のファイルにあり、判定が `rewritable` である。
  2. 人が承認した。この版では、書き直した問題は、抜き取りにせず全件を人が確かめる(抜き取りで確認しないものに入れない)。効果が確かめられてから、抜き取りにするかを、別に決める。
  3. 検証役の検証を通った(保留は、人の承認があるときだけ通す)。
  4. 来歴の検査と、再検証の検査を通った。
  5. 同じ内容であること(上)。
  6. 判定役が、書き直した内容で「公開」と判定した。判定の結果の、問題の ID・本文のハッシュ・判定の基準のハッシュ・判定役の定義のハッシュが、いまのものと一致すること。判定(`judge`)は、検証を通った書き直しの下書きを、元の問題の ID で、公開の問題と一緒に判定する。
  - 戻すときは、`unpublish` と同じく、書く前に、戻したあとのデータ全体の検査(`validate:data` のデータの契約の検査と同じ関数。退役した ID と重ならないことを含む。出典のホストとベンダーの対応は、`validate:data` で別に確かめる)を通し、失敗したら何も書かない。書き込みが途中で失敗したときは、2 つのファイルを元に戻す。非公開のファイルが空になるときは、ファイルを消す。
  - 戻した問題は、公開のファイルの、問題 ID の順の位置に入る。タグなど、書き直しで作らない項目は、元の問題のものを引き継ぐ。
  - 来歴は、いまの問題の根拠を指す。書き直した下書きの項目に問題の ID を書き、元の問題の古い項目は外す。
- **履歴・ブックマーク・復習**は、問題の ID だけを持つ(ADR 0022)。同じ ID で公開へ戻れば、保存した記録は、そのまま使える。戻った期間の数え方は、ADR 0022 のとおり(いまの公開の問題だけで数え直す)。

## 理由

- 書き直しの作業は、問いを保ちながら、判定の指摘を解消する作業で、保留の下書きを直す作業と同じ種類の判断が要る。役・取り込みの検査・検証は、下書きの直しと共通にし、元が違う点(元の ID を引き継ぐ)だけを `rewriteOf` で分ける。
- 下書きの直しの決まり(`revisionOf`: 新しい下書きの ID、元の判断を引き継がない)に例外を足すと、決まりが 1 つの文で読めなくなる。元が違う別の種類として分けるほうが、それぞれの決まりを短く保てる。
- 同じ内容かを機械で比べるのは、書き直しの結果を人が全件読む前に、論点・出典がずれた書き直しを落とすため。論点の持ち方は、データの契約に項目を足さず、すでに持っている根拠の事実カードの出題範囲の項目を使う。
- 判定役と書き直す役は別のモデルで、書き直した内容を、判定役が改めて判定する。判定のハッシュを一致させるのは、判定のあとに本文や基準が変わった問題を、判定済みとして戻さないため。
- この版では人が全件を確かめる。判定・書き直し・戻すを LLM で回す前提でも、最初は書き直しの質を人が確かめ、効果が分かってから抜き取りにするほうが、公開の質を下げにくい(非公開へ移す作業 `unpublish` は、個別の承認を置かず、PR の差分で確かめる(ADR 0022)。戻す前の確認は、これとは別に扱う)。

## 採用しなかった選択肢

- 書き直しを、下書きの直しの例外にする(`revisionOf` で、元を非公開の問題にする): 決まりは 1 つになるが、「下書きが元」「問題が元」「ID が変わる」「ID を引き継ぐ」の条件が同じ決まりの中に入り、読み解きにくい。
- 書き直した問題を、通常の書き出し(`export`)で公開し、元の問題を削除する: 新しい ID になり、利用者の記録が宙に浮く(ADR 0012 の理由)。
- 同じ内容かを、人が確かめる(機械で比べない): 論点・出典のずれが、人が全件を読むまで残る。人の確認は、機械で落とせないものに使う。
- 判定の結果を確かめずに戻す(検証だけで戻す): 書き直しで、別の基準違反が出ていても戻る。判定役が改めて公開と判定することを、条件にする。
- 判定が `unpublish` の問題も書き直す: 設問が成り立たない、または範囲外で、同じ内容の書き直しでは直らない(ADR 0021)。

## 影響

- ADR 0021 の役の表は変えない。`question-reviser` の行(保留の選択式の下書き 1 件を直す役)は、書き直し(非公開の問題 1 問を直す)にも使う役として読む。
- `question-reviser` の定義に、書き直しの依頼の節を足す(定義のハッシュが変わるので、取り込み前の直しの依頼は出し直される)。
- 下書きの記録に `rewriteOf` が増える(作業用の置き場。コミットしない)。`pipeline.config.json` に設定は足さない。
- `judge` の対象に、検証を通った書き直しの下書きが入る。判定の結果は、その問題の ID の項目として持つ(非公開の問題の判定の項目は、これまでどおり判定のたびに外れる)。
- 手順は [問題を作る手順書](../../question-production.md) の「7.7 書き直して公開へ戻す」、下書きの段階の決まりは [出題計画と下書きの手順](../../drafting.md) の「書き直し(非公開の問題)」。
