# 0008. 問題の来歴を台帳で結び、公開データの正は `data/` に置く

- 状態: 置き換え済み(置き換えた ADR: 0014)
- 日付: 2026-10-13

## 背景

問題の正しさは、根拠をたどれて初めて確かめられます。一方、公開するデータには、作業の内部の情報を載せたくありません。

## 決定

- 問題ごとに、根拠の事実カードと出典(台帳の項目)を結ぶ**来歴**を持ちます。来歴は pipeline の側に置きます。
- 公開データ(`data/`)に載せるのは、出典の URL だけです。事実カード、言い換え、作業の記録は載せません。
- 公開した問題の**正は `data/`** です。pipeline は `data/` を読み取り専用で参照し、追加・更新を**差分として出力**します。
  `data/` を直接は書き換えません。差分は、人が確かめて、通常の PR で取り込みます。
- 問題の識別子は、変えません。

## 理由

- 来歴があれば、出典が変わったときに、影響を受ける問題を特定できます。
- 正が 1 つなら、アプリと pipeline の間で、データが食い違いません。
- 差分として出すと、人が、変更の中身を確かめてから取り込めます。

## 採用しなかった選択肢

- pipeline が `data/` を直接書き換える: 確認を経ずに公開データが変わります。
- 公開データに来歴をすべて載せる: データが大きくなり、作業の内部の情報が公開されます。

## 影響

- 書き出しの段階は、`data/` の仕様(`docs/data-spec.md`)に従う差分を作ります。
- 公開データの検査(`npm run validate:data`)は、これまでどおり関門として残ります。
