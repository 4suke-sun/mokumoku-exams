# 0017. 事実カードの台帳には、アンカーの引用を残さない

- 状態: 採用
- 日付: 2026-10-21

## 背景

事実カードの台帳(`packages/pipeline/facts/<コード>.json`)と、問題の来歴(`packages/pipeline/provenance/<コード>.json`)は、リポジトリにコミットして、ほかの環境でも来歴を検査できるようにしたい。

- 事実カードは、本文の位置を確かめるアンカーとして、見出しのほかに、30 文字以内(英語は 10 語以内)の引用を持てる形が考えられる。
- 出典と権利の方針(`docs/source-policy.md` の 2 節)は、直接の引用を 1 つの出典あたり合計 100 文字以内にする。1 つの出典から多くのカードができるので、引用の合計はこの上限を超えうる。
- 来歴は事実カードの ID を指すので、台帳なしで来歴だけをコミットすると、ほかの環境で `draft --check` が事実カードを見つけられない。

## 決定

- 出典と権利の方針は変えない。
- 台帳のアンカーは、節の見出し(`heading`)だけにする。引用(`quote`)は、台帳に残さない。
- 引用は、抽出のときの出力にだけ書く。CLI は、取り込むときに、引用が節にあるかを照合してから捨てる。
- 抽出の出力は、作業用の置き場(gitignore 済み)にだけ置き、取り込みが終わると消す。この間の引用は、出典あたり合計の上限の対象にしない。コミットにも公開にも残らないため。
- 引用を持つ台帳は、スキーマの検査(`FactsFileSchema`)が止める。
- 台帳と来歴は、コミットできる。

## 理由

- 引用に別の上限を設ける案は、上限の数字を決めること自体が権利の判断になる。出典から多くのカードができると、引用の合計は上限を大きく超えうるので、別の上限でも説明が難しい。
- 引用は、取り込むときの照合に役立つが、取り込んだ後の検証(`verify`)は、見出しで本文の節を切り出して行うので、引用を使わない。
- 失うのは、取り込み後に、引用で本文と照らし直す力だけ。見出し・数値・固有名詞・引用の照合は、取り込むときに行う。やり直すには、抽出をやり直す。

## 採用しなかった選択肢

- アンカーの引用に、表記を示す引用とは別の上限を設ける。権利の判断が要り、上限の根拠を示しにくい。必要になったら、この ADR を置き換えて進める。
- 台帳と来歴を手元だけに置き、コミットしない。ほかの環境で、来歴の検査も作問の再現もできない。
