# 0027. リリースノートの読み手を項目の種類で分け、開発の項目は画面に出さない

- 状態: 採用
- 日付: 2026-11-21

## 背景

`data/release-notes.json` の項目は、アプリのリリースノートの画面と、GitHub の Release の本文の両方に出る。読み手は、アプリの利用者と、リポジトリを読む人の 2 つある。
項目の種類は `feat`・`fix`・`docs`・`dev` の 4 つで、開発の仕組み(検査、スクリプト、作問パイプラインの内部など)の変更は `dev` に書く。

読み手を決めずに `dev` を書くと、次の 2 つの間を行き来する。

- 平易に言い換えると、条件や例外が落ちて、実装とずれる。
- 正確に書くと、利用者に意味のない内部の語(ファイル名、検査の名前、理由コード)が画面に増える。

## 決定

- **`dev` の項目は、アプリの画面に出さない。** 画面は `feat`・`fix`・`docs` の項目だけを出す。`dev` の項目は、ファイルに残し、GitHub の Release の本文には、これまでどおり、すべての種類を出す。
- **`dev` だけの版も、画面に版・日付・タイトルを出す。** 項目の代わりに、開発者向けのアップデートであることと、その版の GitHub の Release のページへのリンクを出す(詳細は Release の本文で読める)。リンクの URL は、`packages/app/src/lib/site.ts` の `releaseUrl` で、リポジトリの URL から組み立てる。版の並びに欠けを作らない。未読の目印は、これまでどおり、`dev` だけの版では付けない。
- **読み手は種類で決める。** `feat`・`fix`・`docs` は利用者、`dev` はリポジトリを読む人。`docs` は利用者が読む文書(利用規約とプライバシーポリシー、使い方)の変更にし、開発の文書の変更は `dev` にする。
- **書き方の基準は `CONTRIBUTING.md` の「リリースノートの書き方」に置く。** `/dev-version` の Step 3 は、その要点と参照を持つ。
- **機械で守れるものは `npm run check:release-notes` で守る。** 版のタイトルと項目の文字数の上限と、利用者向けの項目の内部の語の形(コードの書式、ファイル名・パス、コマンド、検査・スクリプトの名前、Issue・PR の番号)。種類の選び方、平易さ、要旨と実装の一致は、機械で守れないので、書く人と検査役が確かめる。
- **既存のエントリは書き直さない。** 書き方の検査は、`WRITING_STYLE_SINCE`(`scripts/lib/release-notes-check.ts`)の版より新しいエントリだけを対象にする。既存の `dev` の項目は、画面に出さなくなることで、利用者向けの扱いに合う。

## 理由

- 利用者への影響: 利用者に影響する変更は、`feat`・`fix`・`docs` に書くので、画面から落ちない。`dev` は利用者の操作と表示を変えないので、画面から外しても、利用者が知るべきことは減らない。
- 実装との一致: `dev` の読み手をリポジトリを読む人に絞るので、内部の語で正確に書ける。利用者向けに言い換える必要がなく、言い換えによるずれが起きない。
- 機械検査: 利用者向けの項目に内部の語がないことは、語の形で検査できる。`dev` の項目は内部の語を許すので、誤検知で止まらない。
- 既存のエントリ: 種類で表示を分けるので、既存の `dev` の項目(全体の半分ほど)を書き直さずに、画面が利用者向けになる。
- 未読の目印は、すでに `dev` だけの版を利用者向けの更新として扱っていない。画面の表示も、同じ線で分かれる。

## 採用しなかった選択肢

- `dev` を、利用者向けの短い一文にする: 開発の変更の記録が Release の本文からも消え、リポジトリを読む人が版ごとの変更を追えない。言い換えで実装とずれる問題も残る。既存の `dev` の項目をすべて書き直すことになる。
- 開発向けの記録を別のファイル(または変更履歴)に持つ: ファイルが 2 つになり、版とタグの 1 対 1 の対応、版の締めの手順、検査を、両方に持つことになる。読み手を種類で分ければ、1 つのファイルで足りる。
- `dev` だけの版を画面から外す: 版の並びに欠けができ、お問い合わせで送るアプリの版(リリースノートの先頭の版)が、画面にない版になりうる。
- 既存のエントリも書き方の検査の対象にする: 既存のエントリを書き換えることになり、過去の版の Release の本文と食い違う。

## 影響

- 画面は、`dev` の項目を出さず(`packages/app/src/lib/release-notes.ts` の `userItems`)、`dev` だけの版では、項目の代わりに、開発者向けのアップデートであることと、その版の Release へのリンクを出す。
- 新しいエントリは、利用者向けの項目に内部の語があると、`npm run check:release-notes` で止まる(CI と、タグを切るときの Release の作成でも)。
- 既存の `docs` の項目には、開発の文書の変更を書いたものがあり、画面に残る。書き直さない。
- 種類を足す・表示を変えるときは、この ADR を置き換える。
