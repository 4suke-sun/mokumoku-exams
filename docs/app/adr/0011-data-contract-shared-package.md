# 0011. データの契約を共有パッケージ(`packages/data-schema`)に置く

- 状態: 採用
- 日付: 2026-10-13
- 置き換える ADR: 0004

## 背景

資格マスタ・問題・カリキュラム・要約・ヘルプのスキーマと検査は、`scripts/lib` にありました。アプリは相対パスで型だけを参照していました(ADR 0004)。
作問パイプライン(ADR 0005)も、同じスキーマと、出典に許すドメインの一覧を使います。ADR 0004 は、アプリ以外がスキーマを使うようになったら
再検討するとしていました。

## 決定

- スキーマと検査(4 種類のデータの `schema` と `validate`)、出典に許すドメインの一覧(`ALLOWED_REFERENCE_HOSTS`)を、
  `packages/data-schema` に移します。定義は 1 か所です。
- 外から使えるのは、`package.json` の `exports` に並べたものだけです。`@mokumoku-exams/data-schema/<データ種別>/<schema|validate>` の形で import します。
- アプリ、`scripts/`、pipeline は、データの契約を、このパッケージから import します。契約のファイルを、相対パスで指しません。
- 実行時の依存は `zod` だけです。他のワークスペースを import しません。
- アプリは TypeScript のまま読むので、ビルドの設定(`transpilePackages`)に指定します。

## 理由

- 3 か所が同じ定義を使え、データの仕様を変えると、すべての型検査が食い違いを示します。
- `exports` で公開の範囲を決めると、内部のファイルへの依存が広がりません。
- 相対パスでワークスペースをまたぐ参照は、境界(ADR 0005)を機械で検査しにくくします。パッケージ名の import なら、検査が単純です。

## 採用しなかった選択肢

- 相対パスの import のまま、pipeline も `scripts/lib` を読む: pipeline が `scripts/` の内部に依存し、境界の検査が複雑になります。
- アプリにも検査の実行時を含めない前提(ADR 0004 の型だけの参照)を維持する: パッケージから import する形では、型だけに限る意味が薄くなります。
  型の参照は消え、値(`EXAM_LEVELS` など)の参照は、これまでどおり実行時に含まれます。

## 影響

- ADR 0004 は「置き換え済み」になります。ADR 0002 のスキーマの場所は、`packages/data-schema/src/exam-data/schema.ts` に読み替えます。
- データの検査(`npm run validate:data`)とテストの結果は、移す前と同じです。
- スキーマを足すときは、`exports` にも足します。
