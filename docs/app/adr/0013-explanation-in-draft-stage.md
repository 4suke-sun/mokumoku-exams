# 0013. 解説は下書きの段階で書き、別の段階を持たない

- 状態: 採用
- 日付: 2026-10-16
- 置き換える ADR: 0007

## 背景

ADR 0007 は、作業を段階に分け、そのうちの 1 つを「解説・出典」としていました。
解説は、設問と同じ根拠(事実カードの主張)から書くもので、設問・選択肢・誤答の設計と一緒に書くほうが、食い違いが出ません。
出典(`references`)は、来歴の出典の URL から決まり、書き出しで付けられます。

## 決定

- 作業を次の段階に分けます。収集、事実カード、出題計画、下書き(解説を含む)、検証、書き出し。人の確認は、下書きのあと、書き出しの前に行います。
- 解説(総合解説と、選択肢ごとの解説)は、下書きの役が設問と一緒に書きます。誤答の設計の理由が、その選択肢の解説になります。解説の形の規則は、下書きのスタイル規則で検査します。
- 出典(`references`)は、書き出しの段階で、来歴の出典の URL から付けます。
- 段階ごとに、入力と出力の形(スキーマ)と、**関門**(次へ進める条件)を定めます。関門を通らないものは、先へ進めません。
- 安い機械検査(スキーマ、重複、出典の有無、長さ)を先に、高いモデルによる検証をあとに置きます。
- **作る役と検証する役を分けます**。同じエージェントに、書かせて確かめさせません。
- 各段階の成果物は、作業用の置き場(gitignore 済み)にファイルで残し、段階の間はファイルで受け渡します。
- 公開するデータに入るのは、書き出しの段階を通ったものだけです。

## 理由

- 解説を別の段階で書くと、設問を書いたときの根拠と、解説の根拠が離れ、食い違いの検査が要ります。下書きで一緒に書けば、同じ根拠の検査で足ります。
- 出典は、来歴から機械で決まるので、モデルの段階を要しません。
- 段階ごとに確かめれば、誤りを早く見つけ、直す範囲が小さくなります。機械検査で先に落とすと、高いモデルを呼ぶ回数が減ります。
- 作る役と確かめる役を分けると、同じ思い込みを通してしまうことを防げます。

## 採用しなかった選択肢

- 解説・出典の段階を残す: 解説の役と下書きの役の間で、根拠の受け渡しと食い違いの検査が要り、費用が増えます。
- 一括で生成して、最後に人が確かめる: 誤りの発見が遅く、人の負担が大きくなります。

## 影響

- ADR 0007 は「置き換え済み」になります。
- コマンドの一覧から `explain` を外します。
- 関門の基準は、段階ごとの Issue で決め、検査の失敗は理由コードで報告します(本文は引用しません)。段階を足すときは、入力・出力・関門を定義してから実装します。
