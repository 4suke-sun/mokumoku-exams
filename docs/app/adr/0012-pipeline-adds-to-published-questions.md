# 0012. パイプラインで作る問題は、公開済みの問題に足す

- 状態: 採用
- 日付: 2026-10-16
- 補った ADR: 0023(非公開の問題の書き直し)

## 背景

作問パイプライン(ADR 0005、0007)は、出題計画で、目標の問題数と、公開済みの問題(`data/questions.<コード>.json`)の数の差を不足として出し、
不足の分だけ下書きを作ります。下書きの重複の検出は、公開済みの問題も比べる相手にします。

パイプラインで作る問題が、公開済みの問題を置き換えるのか、足すのかが決まっていませんでした。置き換える前提で使うと、置き換える分が計画の不足に出ず、
置き換え対象と同じ論点の新しい問題は、重複として落ちるか、保留になります。方針がないと、計画と下書きの結果が、どちらの方針の結果なのかを判断できません。

## 決定

- パイプラインで作る問題は、公開済みの問題に**足します**。公開済みの問題は変えず、目標に足りない分だけを作ります。
- 出題計画は、公開済みの問題のうち資格の分野に属するものを、既存の数に入れます(データの検査が、問題の分野が資格マスタにあることを確かめるので、実際にはすべてです。区分は分野・難易度・種別。難易度のない問題は `medium` として数えます)。
- 下書きの重複の検出は、公開済みの問題をすべて比べる相手にします(`duplicate:similar-existing`、`review:similar-existing`)。
- 公開済みの問題を直したり、取り下げたりするのは、パイプラインの外で、問題データの通常の変更として行います(ID の扱いは `docs/data-spec.md` の「7. ID の運用」)。
  ただし、非公開のファイルへ移した問題の書き直しは、パイプラインが扱います([0023](./0023-rewrite-unpublished-questions.md))。公開の問題は、これまでどおり変えません。

## 理由

- `questionId` は永続で、削除しても再利用しません(`docs/data-spec.md`)。受験履歴・ブックマーク・復習がこの ID を参照するので、
  置き換えで ID が消えると、利用者の記録が宙に浮きます。足す方針なら、既存の ID と利用者の記録は変わりません。
- 今の出題計画と重複の検出は、足す方針のとおりに動いています。方針を文書とテストで固定すれば、実装を変えずに済みます。
- 公開済みの問題の質を上げる作業(直す、取り下げる)は、1 問ずつ人が判断するもので、パイプラインの不足の計算と混ぜないほうが、結果を読み解きやすくなります。

## 採用しなかった選択肢

- 置き換える(新しい問題で、公開済みの問題を資格ごとに置き換える): 公開済みの問題の ID がまとめて消え、利用者の記録が参照先を失います。
  置き換え対象を、計画の数と重複の比較から外す仕組みも要ります。
- 一部だけ置き換える(人が選んだ問題 ID だけ): 置き換え対象の指定の置き場と、計画・重複の検出での除外が要ります。
  必要になったら、置き換え対象を問題 ID で指定する形で、改めて決めます。

## 影響

- `docs/drafting.md` の「2. 出題計画」と「4. 判定と理由コード」に、足す方針を書きます。
- 公開済みの問題がある場合とない場合で、計画の不足と、重複の判定がこの方針のとおりになることを、テストで固定します。
