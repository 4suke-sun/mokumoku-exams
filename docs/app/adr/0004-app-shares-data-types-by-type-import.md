# 0004. アプリは問題データの型を、スキーマから型だけ参照する

- 状態: 採用
- 日付: 2026-10-09

## 背景

資格マスタと問題データの型は、検査スクリプトの Zod スキーマ(`scripts/lib/exam-data/schema.ts`)が正本です(ADR 0002)。アプリ(`packages/app`)も同じ型で、データを表示・採点します。ADR 0002 は、アプリで型を共有するときの方法を、アプリを実装する版で判断するとしていました。

## 決定

アプリは、スキーマのファイルから**型だけ**を `import type` で参照します。スキーマの実行時の処理(Zod による検査)は、アプリのバンドルに含めません。データの形の検査は、`npm run validate:data` が CI で行います。

## 理由

- 型の定義を 1 か所に保てます。データの仕様を変えると、アプリの型検査が食い違いを示します。
- 型の参照は実行時に消えるので、アプリの配信物が大きくなりません。
- 共有のパッケージを新しく作るより、変更が小さく済みます。

## 採用しなかった選択肢

- 共有のパッケージにスキーマを移す: 構成がきれいになりますが、この段階では変更の範囲が広すぎます。アプリ以外(インフラなど)がスキーマを使うようになったら、再検討します。
- アプリ側に型を手書きする: 依存はなくなりますが、スキーマと食い違うおそれがあります。

## 影響

- アプリの型検査は、`scripts/` のスキーマのファイルを読みます。
- ビルド時には、JSON の形を検査しません。公開前に `validate:data` が通っていることが前提です。
- アプリの実行時にデータを検査する必要が出たら(外部から取り込むデータなど)、この ADR を置き換えます。
