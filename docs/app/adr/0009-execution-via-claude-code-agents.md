# 0009. モデルを使う段階は、Claude Code のエージェントで実行する

- 状態: 採用
- 日付: 2026-10-13

## 背景

作問には、モデルを使う段階(事実カード、下書き、検証、解説)があります。呼び出しの方式は、
Anthropic API を pipeline の CLI から直接呼ぶ方式と、Claude Code のエージェントから呼ぶ方式があります。

## 決定

- モデルを使う段階は、Claude Code のエージェント(`.claude/agents/` の定義)で実行します。役ごとにモデルを固定します(ADR 0003)。
- pipeline の CLI は、**モデルを呼ばない決定的な処理**を受け持ちます。入力の用意、出力のスキーマ検査、台帳の読み書き、重複の検出、
  関門の判定、書き出しです。
- CLI とエージェントの間は、作業用の置き場のファイルで受け渡します。エージェントは決められた場所にだけ書き、
  CLI が、書かれたものを検査してから次へ進めます。
- API キーを扱いません。pipeline の設定に、認証情報は持ちません。
- 費用は、実行前の見積もり(件数 × 役ごとのモデル)、1 回の実行の件数の上限、結果のキャッシュ(入力のハッシュ)で管理します。
  実行の記録には、段階、件数、モデルの ID を残します。

## 理由

- 鍵の管理と、通信の設定が要りません。公開リポジトリで扱う秘密が増えません。
- 既存の役割分担(作る役と検査する役、ADR 0003)と、検査・承認の流れにそのまま乗ります。
- 決定的な処理を CLI に分けるので、モデルを呼ばない部分は、通信なしでテストできます。

## 採用しなかった選択肢

- API を CLI から直接呼ぶ: トークン数の計測、予算の強制、再実行の制御は正確にできます。しかし、鍵の管理と、
  別の実行基盤が要ります。計測や上限の精度が必要になったら、この ADR を置き換えます。
- 両方に対応する: 検査と保守の対象が倍になります。

## 影響

- トークン数の厳密な計測と予算の強制は、API 直接の方式より弱くなります。件数の上限と、実行前の見積もりで補います。
- 出力の再現性は、入力のハッシュ、エージェントの定義、モデルの ID を記録して担保します。同じ入力でも、出力は変わりえます。
  変わっても困らないように、出力は関門で検査します。
- 品質の評価(誤りを仕込んだデータでの検出率)は、この方式で行える形にします。
