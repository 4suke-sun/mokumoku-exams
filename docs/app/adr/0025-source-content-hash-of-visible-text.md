# 0025. 出典の変更の検出を、見える本文のハッシュで行う

- 状態: 採用
- 日付: 2026-10-27
- 補う ADR: 0006

## 背景

出典の本文のハッシュは、出典の変更の検出と、取得した本文のキャッシュの鍵に使う(ADR 0006)。出典のハッシュが変わると、それを根拠にした事実カードに再検証の印が付く。
このハッシュを、取得した HTML の生のバイト列の sha256 にすると、ページの飾り(更新時刻のメタ、ナビゲーションの設定、イベントのお知らせのバナーなど)の更新でも、取得のたびに変わる。
本文が変わっていないのに、再検証の印が付く誤検知になり、収集を流すたびに、事実カードが一斉に再検証になる。

## 決定

- **ハッシュは、HTML は見える本文の sha256、HTML でないものは生のバイト列の sha256** にする(`packages/pipeline/src/collect/content-hash.ts`)。
- **見える本文**は、`<main>` があれば最初の `<main>` から最後の `</main>` までの中、なければ `<head>` を除いた全体。どちらも、コメント・`script`・`style`・`noscript`・`template` を除き、タグを外し、文字参照を戻し、NFKC にして、空白を 1 つにそろえる。
  ナビゲーション、お知らせのバナー、フッターは、`<main>` の外にあるので入らない。
- **HTML かどうかは、本文の先頭 4 KB の目印(doctype、`html`、`head`、`body`)で決める。** 取得時の Content-Type に依らず、キャッシュの本文だけから、同じ値が出る。
- **キャッシュは、このハッシュを鍵にする。** 見える本文が同じ 2 つの HTML は、同じ鍵になり、あとから書いた本文が残る。旧い定義(生のバイト列の sha256)の名前のファイルも読める(保持期間で消える)。
- **定義を変えたときの移行は、`rehash` で行う。** キャッシュの本文から新しい定義のハッシュを計算し直し、台帳・事実カード・来歴・判断の記録を、再検証の印を付けずに書き換える。何度流しても同じ結果になる。
  - 本文がキャッシュにない、台帳の現在のハッシュは、`--refetch` で取り直して、新しい定義のハッシュを採用する。旧い定義のハッシュとは比べられないので、前回の取得から本文が変わっていても、検出しない。
  - 台帳の現在のハッシュと違う、古い根拠のハッシュで、本文がないものは、今の本文のハッシュに寄せず、据え置く(古い本文を根拠にしている事実を、隠さないため)。
  - 見える本文の規則を変えるときも、同じ `rehash` で移す。
- 廃止の兆候の検査は、これまでどおり、取得した本文の全体を見る。`<main>` の外の廃止のお知らせは、ハッシュに依らず、取得のたびに検出する。

## 却下した案

- サイトごとに、お知らせのバナーを外す規則を置く: ホストごとの保守が要る。バナーは `<main>` の外にあるので、`<main>` を取れば足りる。
- 生のバイト列のハッシュのまま、再検証の印を人が確かめて外す: 取得のたびに全件を人が見ることになり、検出が使えない。
- 本文の変更を、差分の大きさで判断する: しきい値の調整が要り、数値の変更のような小さな本当の変更を見逃す。
- 生のハッシュと見える本文のハッシュを、両方持つ: 台帳と記録の形が増え、どちらで判断するかの規則も要る。

## 結果

- 飾りだけの更新では、ハッシュも再検証の印も変わらない。見える本文が変わると、従来どおり検出する。
- `<main>` を持たないページは、`<head>` を除いた全体を見るので、本文の外の変更で、誤検知しうる。出たら、そのページの取り方を見直す。
- 見える本文が同じ 2 つの HTML は、同じ鍵のキャッシュを共有し、あとから取得した HTML が残る。
- 保存済みのハッシュは、定義の変更のたびに、`rehash` で移す必要がある。
