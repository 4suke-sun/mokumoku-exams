# 0016. 作問パイプラインの役のモデルの表に、出典の候補を挙げる役を足す

- 状態: 置き換え済み(置き換えた ADR: 0019)
- 日付: 2026-10-17
- 置き換える ADR: 0015

## 背景

出典の候補を挙げる役(`source-scout`)を足すため、ADR 0015 の表を置き換える。ADR 0015 の決定(役のモデルを表で固定する、検証役は下書きの役と別のモデルにする)は、そのまま引き継ぐ。

作問パイプラインのモデルを使う段階は、Claude Code のエージェントで実行します(ADR 0009)。役ごとの定義は `.claude/agents/` にあり、`model:` に完全な ID を書きます。
ADR 0003 は、コミット・push・PR の作成役と検査役のモデルを決めていますが、パイプラインの役は含みません。

検証役は、下書きの正解と解説を、根拠の節だけから確かめる役です。下書きを書いた役と同じモデルだと、同じ思い込みを通しやすくなります。
検証の取りこぼしは、誤った問題の公開につながるので、検証役は、通す側に倒れにくいモデルにします。

## 決定

パイプラインの役と、モデルを次の表で固定します。表のモデルの表記(`Sonnet 5.5` など)は、定義の完全な ID(`claude-sonnet-5-5` など)に対応します。

| 役 | エージェント | モデル | 使う場面 |
| --- | --- | --- | --- |
| 試験ガイドの抽出役 | `guide-extractor` | Haiku 5.5 | 収集の段階で、試験ガイドの分野・配点・出題範囲を抽出する |
| 事実カードの抽出役 | `fact-extractor` | Haiku 5.5 | 事実カードの段階で、出典の本文 1 件から事実カードの候補を抽出する |
| 下書きの作成役 | `question-drafter` | Sonnet 5.5 | 下書きの段階で、事実カードだけを根拠に、問題の下書きを書く |
| 検証役 | `question-verifier` | Opus 5.5 | 検証の段階で、根拠の節だけから、選択肢ごとの正誤の再導出と、解説の確認を行う |
| 出典の候補を挙げる役 | `source-scout` | Sonnet 5.5 | 収集の段階で、試験ガイドの出題範囲の項目ごとに、公式の文書を出典の候補として挙げる |

- 表のモデルと、`.claude/agents/` の定義の `model:` が一致することを、テストで確かめます。
- 検証役のモデルは、下書きの作成役のモデルと異なるものにします。異なることも、テストで確かめます。
- モデルを変えるときは、新しい ADR で表を置き換えます。定義のハッシュが変わるので、依頼の鍵が変わり、取り込み済みの依頼も出し直されます。

## 理由

- 出典の候補を挙げる役は、自分の知識で文書の URL を挙げる。サービスや機能の名前から、公式の文書を選ぶ知識が要るので、抽出役より高いモデルにする。挙げた候補は提案で、CLI の検査(形、許可したホスト、計画との重複)と、足したあとの収集の検査(公式か、対象か、廃止の兆候、日付、リンク)が後ろにあるので、検証役ほど高いモデルは要らない。
- 抽出は、本文から決まった形に写す作業で、検査(本文との照合、写しの検出)が後ろにあります。軽いモデルで足ります。
- 下書きは、複数の事実を組み合わせ、誤答を設計する作業です。抽出より高いモデルにします。
- 検証は、独立に導き直す作業で、後ろに機械の関門がありません。下書きの役より高いモデルにし、別のモデルにすることで、同じ思い込みを避けます。

## 採用しなかった選択肢

- 検証役を下書きの役と同じモデルにする: 同じ誤りを通しやすい。
- 検証役を軽いモデルにする: 費用は下がるが、検証の取りこぼしが公開に直結する。
- 表を ADR 0003 に足す: 元の ADR を書き換えない運用に反する(`docs/app/adr/README.md`)。

## 影響

- 検証は、下書き 1 件につき、再導出と解説の確認の 2 回、検証役を呼びます。費用は、下書きの数に比例します。
- 出典の候補を挙げる役は、資格 1 つにつき、依頼 1 件(エージェントの起動 1 回)です。試験ガイドの出題範囲の項目をまとめて 1 件の依頼に載せるので、費用は項目の数ではなく、依頼の数で決まります。
