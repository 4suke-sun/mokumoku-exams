# データの設計(学習の履歴)

学習の履歴は、DynamoDB の**単一テーブル**に置きます(`<接頭辞>-data` スタック、`packages/infra/lib/data-stack.ts`)。
利用者ごとの分だけを操作でき、他人の履歴は読み書きできません。

## テーブル

| 項目 | 内容 |
| --- | --- |
| パーティションキー `PK` | `USER#{sub}`(`sub` は、サーバー側で検証した ID トークンの値) |
| ソートキー `SK` | 種別ごとの接頭辞で分ける。結果は `RESULT#{資格コード}#{完了時刻}`、ブックマークは `BOOKMARK#{資格コード}#{問題 ID}`、復習プールは `REVIEW#{資格コード}#{問題 ID}`、日ごとの学習量は `DAY#{資格コード}#{YYYY-MM-DD}`、目標日は `GOAL#{資格コード}`、通知の購読は `PUSH#{endpoint のハッシュ}` |
| 管理者の操作の記録 | 利用者の区画とは別の `PK=ADMIN` に、`SK=AUDIT#{時刻}#{対象のユーザー名}` で置く(「アクセスパターン」。画面は [認証の仕組み](./auth.md) の「管理者の画面」)。`sub` は `ADMIN` にならない(`USER#` が付く)ため、利用者の区画と混ざらない |
| 課金 | オンデマンド(使った分だけ。使わなければ、ほぼ無料) |
| 暗号化 | 既定(AWS 所有のキー。追加の費用なし) |
| 削除 | スタックを消しても、テーブルは残る(`RETAIN`)。削除保護も有効(「データの保護」) |
| 復旧 | 時点復旧が有効(過去 35 日の任意の時点に戻せる)。「データの保護」 |

`sub` は英数字と `.` `_` `-` だけ、資格コードは `[A-Z][A-Z0-9]{1,15}`、完了時刻はミリ秒つきの ISO 8601(`toISOString()` の形)だけを受け付けます。
キーの区切りの `#` を含められないため、ほかの利用者や資格のキーに入り込めません。

## アクセスパターン

| 操作 | DynamoDB の操作 | 条件 |
| --- | --- | --- |
| 結果を保存する | `PutItem` | `PK=USER#{sub}`、`SK=RESULT#{資格}#{完了時刻}`。同じキーは上書き(繰り返しても重複しない) |
| 資格の結果を新しい順に取る | `Query`(`ScanIndexForward=false`、`Limit=10`) | `PK=USER#{sub}` かつ `begins_with(SK, "RESULT#{資格}#")` |
| 古い結果を切り詰める | `Query`(`SK` だけ)→ `DeleteItem` | 保存のあと、1 資格あたり 10 件を超えた分を古い順に消す |
| ブックマークを付ける・外す | `PutItem` / `DeleteItem` | `SK=BOOKMARK#{資格}#{問題 ID}`。繰り返しても結果は変わらない |
| 資格のブックマークを取る | `Query`(`SK` だけ) | `PK=USER#{sub}` かつ `begins_with(SK, "BOOKMARK#{資格}#")` |
| 復習プールを更新する | `PutItem` / `DeleteItem` | 結果の保存のあと。間違えた問題を `SK=REVIEW#{資格}#{問題 ID}` で入れ、正解した問題を消す。同時に送るのは 10 件まで |
| 資格の復習プールを取る | `Query`(`SK` だけ) | `PK=USER#{sub}` かつ `begins_with(SK, "REVIEW#{資格}#")` |
| 日ごとの学習量に足す | `PutItem`(`ReturnValues=ALL_OLD`)→ `UpdateItem`(`ADD`) | 結果の保存で、結果の項目が新しく作られたとき(上書きした項目が返らないとき)だけ、`SK=DAY#{資格}#{日付}` の `answered` と `correct` に足す。項目がなければ 0 から足す |
| 資格の日ごとの学習量を取る | `Query` | `PK=USER#{sub}` かつ `begins_with(SK, "DAY#{資格}#")`。日付の順 |
| 目標日を決める・消す・取る | `PutItem` / `DeleteItem` / `GetItem` | `SK=GOAL#{資格}`。資格ごとに 1 項目 |
| 管理者の操作を記録する | `PutItem` | `PK=ADMIN`、`SK=AUDIT#{時刻}#{対象のユーザー名}`。無効化のあとに 1 件。項目は `at`(時刻)・`actor`(操作した管理者の `sub`)・`target`(対象の Cognito のユーザー名)・`action`(`disable-user`)だけで、メールアドレスは入れない |
| 通知を購読する・やめる | `PutItem` / `DeleteItem` | `SK=PUSH#{endpoint の SHA-256}`。同じ端末(endpoint)は上書き |
| 自分の購読を取る | `Query` | `PK=USER#{sub}` かつ `begins_with(SK, "PUSH#")`。購読の上限の確認と、テスト通知に使う |
| 毎日の通知の送り先を集める | `Scan`(`SK` が `PUSH#` のものに絞る) | 送信の Lambda だけが使う(「通知の購読」) |
| 無効になった購読を消す | `DeleteItem`(`begins_with(SK, "PUSH#")` を条件にする) | プッシュサービスが 404 か 410 を返した購読 |

アプリ(画面と API)は、スキャンを使いません。インデックス(GSI)もありません。1 資格あたりの結果は 10 件までです(端末に保存していたときと同じです)。
ブックマークと復習プールは、資格の問題の数より多くはなりません(問題 ID ごとに 1 項目)。
日ごとの学習量は、学習した日ごとに 1 項目です(1 年で高々 365 項目)。

## 日ごとの学習量

- 結果を保存するとき、サーバーが**いまの問題データで採点し直して**、解いた問題の数(`answered`)と、そのうちの正解の数(`correct`)を、完了時刻の日に足します。日付は日本時間(UTC+9)で、`finishedAt` から決めます。
- 未回答は、解いた問題として数え、不正解とします。問題データにない問題は数えません。数える問題がない結果と、公開中でない資格の結果は、足しません。
- 同じ結果(同じ資格・同じ完了時刻)を送り直しても、二重に数えません。結果の項目が新しく作られたときだけ足すためです。
- 古い結果を切り詰めても、日ごとの学習量は減りません。
- この仕組みより前に保存した結果は、日ごとの学習量に入りません。
- 画面では、直近 12 週のヒートマップと、連続日数(今日か昨日まで続いている日数)を出します。1 問以上解いた日を、学習した日とみなします。

## 復習プール

- 結果を保存するとき、サーバーが**いまの問題データで採点し直して**、プールを更新します。端末から送られた正誤は使いません。
  自由記述の問題は、画面の採点と同じ判定(採点基準のキーワード、`docs/data-spec.md` の「8. 自由記述」)で正誤を決めます。
- 間違えた問題と、未回答の問題を入れます。正解した問題は外します。問題データにない問題(データの更新で消えた問題など)は、どちらにもしません。
- 同じ結果を送り直しても、同じ更新になります。
- 更新は、届いた順に反映します。「アカウントに移す」で古い結果をあとから送ると、その結果で間違えた問題がプールに入ります(そのあとに正解していても入ります)。

## API

| メソッドと経路 | 内容 |
| --- | --- |
| `GET /api/history/results?examCode=...` | 自分の結果を、新しい順に返す |
| `POST /api/history/results` | 自分の結果を 1 件保存する。あわせて、復習プールを更新する |
| `GET /api/history/bookmarks?examCode=...` | 自分のブックマークの問題 ID を返す(`{ "questionIds": [...] }`) |
| `PUT /api/history/bookmarks` | ブックマークを付ける・外す(本文は `{ "examCode", "questionId", "bookmarked" }`) |
| `GET /api/history/review?examCode=...` | 自分の復習プールの問題 ID を返す(`{ "questionIds": [...] }`) |
| `GET /api/history/days?examCode=...` | 自分の日ごとの学習量を、日付の順に返す(`{ "days": [{ "date", "answered", "correct" }] }`) |
| `GET /api/history/goal?examCode=...` | 自分の目標日を返す(`{ "date": "YYYY-MM-DD" }`。決めていなければ `null`) |
| `PUT /api/history/goal` | 目標日を決める・消す(本文は `{ "examCode", "date" }`。`date` が `null` なら消す) |
| `PUT /api/push/subscription` | この端末の通知の購読を保存する(本文は `{ "endpoint", "keys": { "p256dh", "auth" } }`) |
| `DELETE /api/push/subscription` | この端末の通知の購読を消す(本文は `{ "endpoint" }`) |
| `POST /api/push/test` | 管理者だけ。自分の購読(すべての端末)に、テスト通知を送る(本文は `{}`)。送れた数を返す(`{ "sent": 1 }`)。管理者でなければ `403` |

管理者の API(`/api/admin/*`。利用者の一覧・招待・無効化)は、[認証の仕組み](./auth.md) の「管理者の画面」に書きます。

- どれも、`proxy.ts` と各ハンドラーの両方で、ID トークンを検証します。未ログインは `401` です。
- **利用者の識別子は、リクエストから受け取りません。** 本文に `sub` などの未知の項目があれば `400`、問い合わせに資格コード以外があれば `400` です。
- 状態を変える `POST`・`PUT`・`DELETE` は、JSON だけを受け付け、別サイトからの送信を断ります(認証 API と同じです)。

### 保存する結果の検査

`POST` の本文は、次をすべて満たすときだけ保存します。1 つでも外れると、何も保存せず `400` です。

| 項目 | 条件 |
| --- | --- |
| 本文全体 | JSON のオブジェクト。未知の項目は不可。100KB まで |
| `examCode` | `[A-Z][A-Z0-9]{1,15}`(キーの区切りの `#` を含められない) |
| `finishedAt` | ミリ秒つきの ISO 8601(`toISOString()` の形)。2020-01-01 以降で、サーバーの時刻から 24 時間先まで(端末の時計のずれを許す) |
| `questionIds` | 1〜500 件。それぞれ `<資格コード>-<4 桁>` の形で、この資格のもの。重複不可 |
| `answers` | キーは `questionIds` の中の問題。値は選択肢のキー(`A`〜`J`)の配列で、10 個まで、重複不可。未回答の問題は、キーがなくてよい |
| `textAnswers`(任意) | 自由記述の回答。キーは `questionIds` の中の問題。値は 1000 文字までの文字列 |
| `choiceOrder`(任意) | キーは `questionIds` の中の問題。値は選択肢のキー(`A`〜`J`)の配列で、重複不可 |

`GET` の問い合わせは、`examCode` だけです。同じ名前が 2 回以上あるものも断ります。

### ブックマークの変更の検査

`PUT` の本文は、次をすべて満たすときだけ保存します。外れると、何も保存せず `400` です。

| 項目 | 条件 |
| --- | --- |
| 本文全体 | JSON のオブジェクト。未知の項目は不可。1KB まで |
| `examCode` | `[A-Z][A-Z0-9]{1,15}`。公開中の資格 |
| `questionId` | `<資格コード>-<4 桁>` の形で、この資格のもの。いまの問題データにある問題 |
| `bookmarked` | 真偽値。`true` で付け、`false` で外す |

### 目標日の変更の検査

`PUT` の本文は、次をすべて満たすときだけ保存します。外れると、何も保存せず `400` です。

| 項目 | 条件 |
| --- | --- |
| 本文全体 | JSON のオブジェクト。未知の項目は不可。1KB まで |
| `examCode` | `[A-Z][A-Z0-9]{1,15}`。公開中の資格 |
| `date` | 実在する日付の `YYYY-MM-DD`(2020-01-01 から 2099-12-31 まで)か、`null`(消す)。項目そのものは省けない |

### エラー応答

応答の本文は、種類だけを持つ `{ "error": "<種類>" }` です。原因・内部の情報・入力の値は返しません(検査に外れた場所も返しません)。

| ステータス | 種類 | 起きる場面 |
| --- | --- | --- |
| `400` | `bad-request` | 本文が JSON でない、検査に外れた、問い合わせが正しくない |
| `401` | `unauthorized` | 未ログイン、トークンが正しくない |
| `403` | `forbidden` | 別のサイトからの送信。管理者でない利用者のテスト通知 |
| `413` | `too-large` | 本文が上限(結果は 100KB、ブックマークと目標日は 1KB、通知は 4KB)を超える(申告された大きさで、読み込む前にも断る) |
| `415` | `bad-request` | `Content-Type` が JSON でない |
| `503` | `unavailable` | 保存先の失敗。通知の鍵が設定されていない、または秘密鍵を読めない(テスト通知)。原因は返さない |

保存は、同じ資格・同じ完了時刻なら上書きです。失敗したあとに同じ内容を送り直しても、重複しません。

## 通知の購読

学習のリマインドを、ブラウザのプッシュ通知(Web Push)で送ります。購読は、利用者の区画(`PK=USER#{sub}`)に、端末(ブラウザ)ごとに 1 項目で置きます。

| 属性 | 内容 |
| --- | --- |
| `SK` | `PUSH#{endpoint の SHA-256(16 進)}`。endpoint は長く、端末ごとの識別子を含むため、キーにはハッシュを使う |
| `endpoint` | ブラウザのプッシュサービスの URL(送信先) |
| `p256dh`・`auth` | 通知の本文を暗号化するための、ブラウザの公開鍵と認証の値 |
| `createdAt` | 保存した時刻 |

### 扱い

- 購読の情報は、その端末に通知を届けるためだけに使います。画面にも、API の応答にも、ログにも出しません(送信の Lambda のログは、送れた数・失敗の数・消した数だけです)。
- 読み書きできるのは、本人の区画だけです。API は、サーバー側で検証した `sub` の区画だけを操作し、本文に利用者の識別子があれば `400` で断ります。
  ほかの人と同じ endpoint を送っても、自分の区画の項目だけが変わります。
- 「通知を止める」で、ブラウザの購読を取り消し、項目を消します。プッシュサービスが、購読が無効になった(404 か 410)と返したときも、送信のときに消します。
- テスト通知(`POST /api/push/test`)は、管理者だけが、自分の購読にだけ送れます。API の本体で、サーバー側で検証した ID トークンのグループを
  `authenticateAdmin`(`lib/auth/admin.ts`)で確かめ、管理者でなければ、本文を読む前に `403`(`{ "error": "forbidden" }`)で断ります。未ログインは `401` です。
  送り先は、検証した `sub` の購読だけで、本文で指定することはできません。アカウントの画面の「テスト通知を送る」も、管理者にだけ出します
  (表示には `GET /api/auth/session` の `isAdmin` を使いますが、これは表示のためだけの値で、送れるかどうかは API が決めます)。
- 1 人が購読できる端末は、10 台までです(送信の量を抑えるため)。上限のあとの新しい端末は `400` です。
- 送信先は、主なブラウザのプッシュサービス(`fcm.googleapis.com`、`*.push.services.mozilla.com`、`*.push.apple.com`、`*.notify.windows.com`)の https の URL だけを受け付けます。
  サーバーが endpoint へリクエストを送るため、内部のアドレスなど、ほかの URL へは送りません(送信の Lambda も、送る前に確かめます)。

### 購読の検査

`PUT` の本文は、次をすべて満たすときだけ保存します。外れると、何も保存せず `400` です。`DELETE` の本文は `{ "endpoint" }` だけで、同じ endpoint の検査をします。

| 項目 | 条件 |
| --- | --- |
| 本文全体 | JSON のオブジェクト。未知の項目は不可。4KB まで |
| `endpoint` | 2048 文字まで。上の、主なブラウザのプッシュサービスの https の URL |
| `keys.p256dh` | base64url。80〜100 文字(65 バイトの公開鍵) |
| `keys.auth` | base64url。16〜32 文字(16 バイトの値) |

### 毎日の送信

- 送信は、毎日 11:00(UTC。日本時間の 20:00)に動く Lambda が行います(`packages/infra/lib/push-stack.ts`)。
- 送り先は、利用者をまたいで集める必要があるため、送信の Lambda だけが、テーブルをスキャンします(`SK` が `PUSH#` の項目に絞ります)。
  スキャンは、テーブル全体を読む分の読み取りの料金がかかりますが、1 日に 1 回で、個人で使う規模(数 MB 以下)では、月に 1 円に満たない金額です。
  利用者や項目が増えたら、購読だけを集めた区画やインデックスへの切り替えを検討します。
- 送信の Lambda に許すのは、テーブルのスキャンと削除だけです。削除は、`SK` が `PUSH#` の項目に限る条件を付けて送ります。
- VAPID の公開鍵は `.env` から渡し、秘密鍵は SSM Parameter Store の SecureString から、Lambda が実行時に読みます。どちらもリポジトリには書きません([インフラの構築とデプロイ](./infra.md) の「VAPID の秘密鍵」)。

## 端末の結果(localStorage)との関係

ログインしている間は、**サーバーに保存した結果を正**とします。

- 採点したとき、まずサーバーに保存します。保存できたら、端末には残しません。
  保存できなかったとき(通信の失敗など)は、端末に残します。
- 結果の画面は、サーバーの結果を表示します。サーバーに接続できないときは、端末の結果を表示し、その旨を伝えます。
- 端末にだけ残っている結果(サーバーに同じ完了時刻のものがない)があるときは、画面で件数を伝え、「アカウントに移す」で移せます。
  すべて移せたときだけ、端末の結果を消します。1 件でも移せなければ、端末の結果は残し、やり直せます。
- 出題の途中の状態(続きから再開するための情報)と、表示の設定は、これまでどおり端末だけに保存します。
- 学習モードの段階の到達の状態(合格した段階と、直近の段階の確認の合否)も、端末だけに保存します。サーバーには送りません。
- ブックマークと復習プールは、アカウントにだけ保存します。サーバーに接続できないときは、出題の対象に選べず、ブックマークも切り替えられません。
- 日ごとの学習量と目標日も、アカウントにだけ保存します。サーバーに接続できないときは、表示も設定もできません。
  端末にだけ残っている結果は、「アカウントに移す」で移したときに、日ごとの学習量に入ります。

## データの保護

履歴を失わないために、テーブルに次の設定を入れています(`packages/infra/lib/data-stack.ts`)。

| 設定 | 内容 |
| --- | --- |
| スタックを消しても残す(`RETAIN`) | スタックを削除しても、テーブルは削除されません |
| 削除保護 | テーブルを削除する操作(コンソールや CLI)を、設定を外すまで断ります |
| 時点復旧 | 過去 35 日(DynamoDB の最大)の任意の時点の状態を、別のテーブルとして復元できます |

- **`RETAIN` と削除保護の関係**: `RETAIN` は「スタックを消す操作ではテーブルを消さない」設定、削除保護は「テーブルを直接消す操作を断る」設定です。両方あると、スタックの削除でも、テーブルの直接の削除でも、テーブルは消えません。テーブルを消したいときは、先に削除保護を外すデプロイが必要です。
- **時点復旧の使い方**: 誤って消した・上書きしたときに、時点を指定して復元します。復元したテーブルは別の名前で作られ、元のテーブルは置き換わりません。アプリの接続先を切り替える手順は、復元が必要になったときに、対象と手順を示して決めます。
- **保持の方針**: 復元できる期間は 35 日です。それより古い状態には戻せません。35 日のうちは、保存量に応じた料金が、期間によらず同じです(期間を短くしても安くならないため、最大にしています)。
- 時点復旧は、自動のバックアップ(スナップショット)の代わりではなく、操作の取り消しに向いた仕組みです。長期の保管が必要になったら、別途オンデマンドのバックアップを検討します。

## 費用の目安

個人で使う規模(1 日に数十回の保存・取得)では、DynamoDB の課金は、月に数円以下です(オンデマンドの料金は、書き込みが 100 万回あたり 1 ドル台前半、読み取りが 100 万回あたり 0.3 ドル前後です。リージョンで少し異なります)。
時点復旧の料金は、保存量(1GB あたり、月に 0.2 ドル台。リージョンで少し異なります)に比例します。
履歴は 1 件あたり数 KB なので、個人で使う規模(数 MB 以下)では、月に 1 円に満たない金額です。削除保護に料金はかかりません。
使わなければ、常時かかる費用は、ほぼありません。ストレージは、25GB までは無料枠の範囲です(時点復旧の分は、無料枠の対象外です)。
