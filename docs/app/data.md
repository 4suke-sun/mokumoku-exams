# データの設計(学習の履歴)

学習の履歴は、DynamoDB の**単一テーブル**に置きます(`<接頭辞>-data` スタック、`packages/infra/lib/data-stack.ts`)。
利用者ごとの分だけを操作でき、他人の履歴は読み書きできません。

## テーブル

| 項目 | 内容 |
| --- | --- |
| パーティションキー `PK` | `USER#{sub}`(`sub` は、サーバー側で検証した ID トークンの値) |
| ソートキー `SK` | 種別ごとの接頭辞で分ける。いまは `RESULT#{資格コード}#{完了時刻}` |
| 課金 | オンデマンド(使った分だけ。使わなければ、ほぼ無料) |
| 暗号化 | 既定(AWS 所有のキー。追加の費用なし) |
| 削除 | スタックを消しても、テーブルは残る(`RETAIN`)。削除保護も有効(「データの保護」) |
| 復旧 | 時点復旧が有効(過去 35 日の任意の時点に戻せる)。「データの保護」 |

`sub` は英数字と `.` `_` `-` だけ、資格コードは `[A-Z][A-Z0-9]{1,15}`、完了時刻はミリ秒つきの ISO 8601(`toISOString()` の形)だけを受け付けます。
キーの区切りの `#` を含められないため、ほかの利用者や資格のキーに入り込めません。

## アクセスパターン

| 操作 | DynamoDB の操作 | 条件 |
| --- | --- | --- |
| 結果を保存する | `PutItem` | `PK=USER#{sub}`、`SK=RESULT#{資格}#{完了時刻}`。同じキーは上書き(繰り返しても重複しない) |
| 資格の結果を新しい順に取る | `Query`(`ScanIndexForward=false`、`Limit=10`) | `PK=USER#{sub}` かつ `begins_with(SK, "RESULT#{資格}#")` |
| 古い結果を切り詰める | `Query`(`SK` だけ)→ `DeleteItem` | 保存のあと、1 資格あたり 10 件を超えた分を古い順に消す |

スキャンは使いません。インデックス(GSI)もありません。1 資格あたりの結果は 10 件までです(端末に保存していたときと同じです)。

## API

| メソッドと経路 | 内容 |
| --- | --- |
| `GET /api/history/results?examCode=...` | 自分の結果を、新しい順に返す |
| `POST /api/history/results` | 自分の結果を 1 件保存する |

- どちらも、`proxy.ts` と各ハンドラーの両方で、ID トークンを検証します。未ログインは `401` です。
- **利用者の識別子は、リクエストから受け取りません。** 本文に `sub` などの未知の項目があれば `400`、問い合わせに資格コード以外があれば `400` です。
- 状態を変える `POST` は、JSON だけを受け付け、別サイトからの送信を断ります(認証 API と同じです)。

### 保存する結果の検査

`POST` の本文は、次をすべて満たすときだけ保存します。1 つでも外れると、何も保存せず `400` です。

| 項目 | 条件 |
| --- | --- |
| 本文全体 | JSON のオブジェクト。未知の項目は不可。100KB まで |
| `examCode` | `[A-Z][A-Z0-9]{1,15}`(キーの区切りの `#` を含められない) |
| `finishedAt` | ミリ秒つきの ISO 8601(`toISOString()` の形)。2020-01-01 以降で、サーバーの時刻から 24 時間先まで(端末の時計のずれを許す) |
| `questionIds` | 1〜500 件。それぞれ `<資格コード>-<4 桁>` の形で、この資格のもの。重複不可 |
| `answers` | キーは `questionIds` の中の問題。値は選択肢のキー(`A`〜`J`)の配列で、10 個まで、重複不可。未回答の問題は、キーがなくてよい |
| `choiceOrder`(任意) | キーは `questionIds` の中の問題。値は選択肢のキー(`A`〜`J`)の配列で、重複不可 |

`GET` の問い合わせは、`examCode` だけです。同じ名前が 2 回以上あるものも断ります。

### エラー応答

応答の本文は、種類だけを持つ `{ "error": "<種類>" }` です。原因・内部の情報・入力の値は返しません(検査に外れた場所も返しません)。

| ステータス | 種類 | 起きる場面 |
| --- | --- | --- |
| `400` | `bad-request` | 本文が JSON でない、検査に外れた、問い合わせが正しくない |
| `401` | `unauthorized` | 未ログイン、トークンが正しくない |
| `403` | `forbidden` | 別のサイトからの送信 |
| `413` | `too-large` | 本文が 100KB を超える(申告された大きさで、読み込む前にも断る) |
| `415` | `bad-request` | `Content-Type` が JSON でない |
| `503` | `unavailable` | 保存先の失敗。原因は返さない |

保存は、同じ資格・同じ完了時刻なら上書きです。失敗したあとに同じ内容を送り直しても、重複しません。

## 端末の結果(localStorage)との関係

ログインしている間は、**サーバーに保存した結果を正**とします。

- 採点したとき、まずサーバーに保存します。保存できたら、端末には残しません。
  保存できなかったとき(通信の失敗など)は、端末に残します。
- 結果の画面は、サーバーの結果を表示します。サーバーに接続できないときは、端末の結果を表示し、その旨を伝えます。
- 端末にだけ残っている結果(サーバーに同じ完了時刻のものがない)があるときは、画面で件数を伝え、「アカウントに移す」で移せます。
  すべて移せたときだけ、端末の結果を消します。1 件でも移せなければ、端末の結果は残し、やり直せます。
- 出題の途中の状態(続きから再開するための情報)と、表示の設定は、これまでどおり端末だけに保存します。

## データの保護

履歴を失わないために、テーブルに次の設定を入れています(`packages/infra/lib/data-stack.ts`)。

| 設定 | 内容 |
| --- | --- |
| スタックを消しても残す(`RETAIN`) | スタックを削除しても、テーブルは削除されません |
| 削除保護 | テーブルを削除する操作(コンソールや CLI)を、設定を外すまで断ります |
| 時点復旧 | 過去 35 日(DynamoDB の最大)の任意の時点の状態を、別のテーブルとして復元できます |

- **`RETAIN` と削除保護の関係**: `RETAIN` は「スタックを消す操作ではテーブルを消さない」設定、削除保護は「テーブルを直接消す操作を断る」設定です。両方あると、スタックの削除でも、テーブルの直接の削除でも、テーブルは消えません。テーブルを消したいときは、先に削除保護を外すデプロイが必要です。
- **時点復旧の使い方**: 誤って消した・上書きしたときに、時点を指定して復元します。復元したテーブルは別の名前で作られ、元のテーブルは置き換わりません。アプリの接続先を切り替える手順は、復元が必要になったときに、対象と手順を示して決めます。
- **保持の方針**: 復元できる期間は 35 日です。それより古い状態には戻せません。35 日のうちは、保存量に応じた料金が、期間によらず同じです(期間を短くしても安くならないため、最大にしています)。
- 時点復旧は、自動のバックアップ(スナップショット)の代わりではなく、操作の取り消しに向いた仕組みです。長期の保管が必要になったら、別途オンデマンドのバックアップを検討します。

## 費用の目安

個人で使う規模(1 日に数十回の保存・取得)では、DynamoDB の課金は、月に数円以下です(オンデマンドの料金は、書き込みが 100 万回あたり 1 ドル台前半、読み取りが 100 万回あたり 0.3 ドル前後です。リージョンで少し異なります)。
時点復旧の料金は、保存量(1GB あたり、月に 0.2 ドル台。リージョンで少し異なります)に比例します。
履歴は 1 件あたり数 KB なので、個人で使う規模(数 MB 以下)では、月に 1 円に満たない金額です。削除保護に料金はかかりません。
使わなければ、常時かかる費用は、ほぼありません。ストレージは、25GB までは無料枠の範囲です(時点復旧の分は、無料枠の対象外です)。
