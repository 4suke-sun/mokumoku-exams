# 書き込みを取り消す処理は、元がない場合と、後続の失敗の両方をテストで確かめる

## 注意すること

書き込みを取り消す処理(書き出しに失敗したときに、書く前の内容へ戻す処理など)は、次の 2 つを、それぞれテストで確かめる。

- 書く前に元のファイルがなかった場合: 取り消しで、ファイルを消す(空のファイルを残さない)。
- 書いたあとの手順が失敗した場合: データの検査に落ちたときだけでなく、後ろの書き込みや記録が失敗したときも、元に戻る。

## 理由

元がない場合は、「元の内容を書き戻す」処理では、書いた内容(または空の内容)のファイルが残る。後続の手順の失敗は、検査に落ちる場合と別の経路で起き、その経路で取り消しが抜けると、書き込みだけが残る。どちらも、通常の経路のテストでは通ってしまう。

## 対処

取り消しの処理を足す、または変えるときは、元がない状態から始める試験と、後続の手順を失敗させる試験を足す。後続の失敗は、後ろの書き込み先のディレクトリを書けない状態(読み取り専用のディレクトリ)にして起こす。書き込みが、一時ファイルを作ってから置き換える実装のときは、ファイルを読み取り専用にしても失敗しない。管理者の権限で実行すると、この方法は効かない。
