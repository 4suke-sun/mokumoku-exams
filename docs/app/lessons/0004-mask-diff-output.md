# デプロイと、デプロイ前の合成・差分の出力は、環境変数の値を伏せてから扱う

## 注意すること

デプロイ(`cdkd deploy`・`cdkd destroy`)と、デプロイ前の合成(`cdkd synth`)・差分の確認(`cdkd diff`)の出力には、環境固有の値が出る。差分は、リソースの設定を新旧そのまま表示し、Lambda の環境変数や CloudFront のオリジンのヘッダーに入れた合言葉の値も、そのまま出る。デプロイの出力にも、リソースの ARN や配信のドメインが出る。出力を、共有・記録・コミットする前に、値を伏せる。

## 理由

差分は、変更のあるプロパティの旧い値と新しい値を両方出す。合言葉やトークンのような機密の値が環境変数にあると、変更のたびに、画面、ログ、会話の記録へ現れる。デプロイの出力のリソースの識別子も、環境固有の値で、履歴に載ると消しにくい。

## 対処

- 出力は、値が出てもよい場所でだけ実行し、そのまま貼らない。
- 読むときは、出力を、標準エラーも合わせて(`2>&1`。エラーの出力にも値が出うる)`npm run -s mask`(`scripts/mask-output.ts`)に通す。伏せる形を、手で書いた正規表現で置き換えない(検査の形と食い違い、取りこぼす)。
  - 伏せるのは、コミット・push・PR の検査と同じ正規表現(認証情報、環境固有の値、個人情報、許可されていないメールアドレス)、数字だけの 12 桁、`.env` の値(4 文字以上で、`<...>` でないもの)、拒否リストの語。伏せたあとも、これらに掛かる行は出さない。
  - これ以外の形(S3 のバケット名、ディストリビューション ID、IP アドレス、キーの名前なしで出るクライアント ID など)と、行をまたぐ値(折り返し、複数行の値)と、`.env` に書いていない値(シェルで設定しただけの環境変数など)は伏せない。伏せた出力も、共有の前に読み直す。伏せきれない形を見つけたら、検査の正規表現に足す(伏せる処理にも同じ形が効く)。
  - `.env` がない作業ツリーでは、`.env` の値を伏せない(標準エラーに知らせる)。作業ツリーの直下に `.env` を写してから使う。
  - パイプにすると、終了コードは `mask` のもの(0)になる。デプロイや差分の失敗を見分けるときは、シェルで `set -o pipefail` を設定してから実行する。
  - 1 行ずつ読むので、改行のない途中の出力(確認の問いなど)は表示されない。確認の問いが出うる実行(デプロイ、削除)は、`mask` を通さず、人が自分の端末で行う。その出力を共有・記録するときは、保存した出力を `npm run -s mask < <ファイル>` に通す。
  - 拒否リストが見つからないときは、標準入力を読み捨てて何も出さずに、終了コード 1 で止まる(伏せきれない出力を出さない)。ただし、環境変数 `CI` があるときは、ほかの検査と同じく、空の拒否リストで続ける(標準エラーに知らせる)。
- 配信のドメインなど、伏せた値そのものが要るとき(`SITE_URL` に写す、確認の URL を開く)は、伏せていない出力を、人が自分の端末でだけ見る。
- 機密の値を環境変数に入れる設計では、値が表示される場面を、手順書に書いておく。
