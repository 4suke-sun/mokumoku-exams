# 判定の単位を変えたら、依存するテストの期待を先に洗い出す

## 注意すること

判定の単位(出力ごと、下書きごと、ファイルごとなど)を変えるときは、実装を変える前に、その単位に依存する既存のテストの期待を洗い出す。

## 理由

判定の単位を変えると、件数、並び、失敗の範囲といった、その単位を前提にしたテストの期待がずれて落ちる。落ちてから 1 件ずつ直すと、期待を実装に合わせて書き換えるだけになり、新しい単位でも守るべき振る舞いを見落とす。

## 対処

変える単位の名前や、その単位で数える値で、テストを検索する(`git grep`)。見つけたテストごとに、新しい単位でも守る振る舞いか、単位の変更に伴って変わる期待かを分けて、変わる期待だけを、実装と同じ差分で直す。
