# 手順に書くコマンドは、zsh と BSD 版の道具でも動く形にする

## 注意すること

手順書やスキルに書くコマンドは、zsh で実行され、macOS の BSD 版の道具で動くことがある。bash や GNU 版の道具と動きが違う、次の 3 つの書き方を避ける。

1. 等号で始まる語を、引用符なしで書かない。zsh は、先頭が `=` の語(`==` や `=cmd`)を、コマンドのパスに展開しようとする。
2. 変数に入れたコマンドを、`$cmd` の形で実行しない。zsh は、引用符のない変数を単語に分けない。
3. BSD 版と GNU 版で、受け付けるオプションや意味が違うものを、片方の形だけで書かない(`sed -i`、`date -d`、`head -0` など)。

## 理由

同じ書き方が、止まる、別の意味になる、何も出さない、のいずれかになる。エラーの文面から原因を読み取りにくい。

- `[ a == b ]` は、zsh では、`=` という名前のコマンドが見つからない誤りで止まる。
- `cmd="git log"` と書いて `$cmd` を実行すると、zsh は、`git log` という 1 つの名前のコマンドを探して失敗する。
- `sed -i 's/x/y/' <ファイル>` は、BSD 版では、次の引数を、バックアップの拡張子として読む。`date -d` は、BSD 版にない。`head -0` と `head -n 0` は、BSD 版では、行数の誤りで止まる。

## 対処

- 比較の記号は、引用符で囲む(`[ a "==" b ]`)か、`=` を使う(`[ a = b ]`)。
- コマンドは、関数にするか、配列に入れて実行する(`cmd=(git log)` と書き、`"${cmd[@]}"` で実行する)。
- どちらの版でも動く形を使う。`sed` の置き換えは、拡張子を続けて書き(`sed -i.bak 's/x/y/' <ファイル>`)、できた控えを消す。日付の計算や、行数の細かい扱いは、`node` のスクリプトで行う。
- 迷う書き方は、使う環境(zsh と、BSD 版の道具)で動かして確かめてから、手順に書く。
