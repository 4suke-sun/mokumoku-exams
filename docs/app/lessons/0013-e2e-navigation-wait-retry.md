# E2E の画面の移動を待つ確認は、押し直しと長めの待ちの形にそろえる

## 注意すること

E2E で、ボタンやリンクを押して別の画面を開き、移るのを待つ確認は、「押す → 移るのを長めに待つ」を、全体の上限の中で押し直す形(`expect(async () => { … }).toPass()`)に、そろえる。1 回の待ちは長めにとり(15 秒など)、全体の上限は、その数倍にする。ログイン、ログアウト、採点のように、サーバーへの送信を伴う操作は、この形の対象にしない(押し直すと送信が重なるため)。

## 理由

開発サーバーは、初めて開く画面を、その場でビルドする。読み込みの直後は、押しても効かないことがある。待ちが短いと、移るのが遅いだけでも落ち、押し直しの間隔が短いと、押し直しを重ねてしまう。手元では通り、負荷のある CI だけで落ちる不安定さにつながる。

## 対処

移動を待つ確認は、`packages/app/e2e/smoke.spec.ts` の `clickUntilUrl` と同じ形で書く(別の試験のファイルへ移すときは、この関数を共有する形に直す)。新しい試験は、`npx playwright test <ファイル> --repeat-each=<回数> --retries=0` で繰り返し、通ることを確かめる。E2E は、代替の認証(`AUTH_FAKE`)が開発サーバーでだけ有効なので、本番のビルドでは回さない。
