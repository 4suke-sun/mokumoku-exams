# 検証役の評価

検証役(`question-verifier`。[ADR 0019](./app/adr/0019-pipeline-reviser-role.md) の表)の見落とし(誤りのある下書きを合格にする)と、誤検出(誤りのない下書きを保留にする)を数字で測り、
検証役の指示やモデルを変えたときの良し悪しを比べるための文書です。コマンドは `eval` です。API は直接呼びません。評価の実行も、依頼 → エージェント → 取り込みの形で、API キーを使いません(ADR 0009)。

## 1. 評価用のデータ

測れるのは、ラベル(誤りの種類と、期待する判定)つきの評価用のデータがあるときだけです。公開済みの問題は、質を人が確かめていないので、誤りのない対照にしません。

- **誤りのない対照**: 人が承認した選択式の下書き(人の判断の記録で `approve` のもの)。合格(`pass`)が期待されます。根拠の節を取り出せない下書きは使いません。
- **誤りのある例**: 承認した下書きに、次の誤りを仕込んだ変種です。保留か不採用(`not-pass`)が期待されます。変種ごとに、元の下書きの ID、誤りの種類、期待する判定を、ラベルとして持ちます。

| 誤りの種類 | 仕込み方 |
| --- | --- |
| `wrong-answer`(誤った正解) | 正解を、誤答だった選択肢に差し替える |
| `unsupported-claim`(根拠のない主張) | 解説に、節にない断定(適用範囲や条件を超えた言い切り)を足す |
| `ambiguous-choice`(曖昧な選択肢) | 誤答の 1 つを、正答と同じ文に差し替える(複数の正解になりうる) |
| `stale-fact`(古い版の記述) | 正答の選択肢と解説の数値を、別の値に差し替える(古い版の値の想定) |

- 誤りのないものと誤りのあるものは、**同じ数**にします。仕込めない組(正解以外の選択肢がない、数値がない、など)は飛ばし、両方の数をそろえます。
- 評価用の問題の ID は `e-<12 桁の 16 進>` です。公開データの問題 ID(大文字の接頭辞と 4 桁の連番)と重なりません。
- 同じ入力と同じ種(設定の `eval.seed`)から、同じデータができます。種と、誤りの種類ごとの件数の目安(設定の `eval.perKind`)を記録します。
- **データの置き場は作業用の置き場だけです**(`pipeline-work/eval/<コード>/dataset.json`)。下書きの本文を持つので、コミットしません。`data/` には書き込みません。
- 検査: ラベルの欠落、未知の誤りの種類、種類と期待する判定の食い違い、ID の重複、対照と変種の数の不一致は、`評価用データの誤り` で落とします。
- **人が却下した下書きは使いません。** 不採用の下書きは本文を持たない(`draft/store.ts`)ので、誤りのある例にできません。本文を残す形は、この版では採りません。

## 2. 手順

```sh
npm run pipeline -- eval <試験コード>            # 評価用のデータを作り(なければ)、検証の依頼を書く
npm run pipeline -- eval <試験コード> --import   # 検証役の出力を期待する判定と照合し、レポートを書く
```

1. `eval` が、再導出の依頼を、ケースごとに書きます(検証と同じ形。正解も解説も載せません)。エージェント `question-verifier` に、依頼のファイルを 1 つずつ渡します。並列の実行は、`pipeline-run` のスキルが行います。
2. `eval --import` で取り込みます。再導出が合格したケースだけが、解説の確認の依頼に進みます。もう一度 `eval` を実行して、解説の確認の依頼を書き、同じように取り込みます。
3. 取り込みのたびに、レポートを書き直します。全ケースが終わる(途中が 0 件になる)まで、目標は「満たした」になりません。
4. 出力の形が違うものは、先へ進めません。設定の `eval.maxAttempts` まで出し直し、超えると**止めたもの**として数えます(別の項目にも件数を出します)。
5. 1 回の件数の上限は、設定の `maxItemsPerRun` です。実行前の見積もりと予算の上限は持ちません。費用(トークン・金額)は CLI が測れないので、指標に入れません。

置き場は `pipeline-work/eval/<コード>/` です(`dataset.json`、`requests/`、`out/`、`results.json`、`state.json`、`report.json`、`report.md`)。

## 3. 指標

| 指標 | 定義 | 計算式 | 測る場所 |
| --- | --- | --- | --- |
| 検出率(種類ごと) | 誤りのある例を、保留か不採用にした割合 | 種類ごとに 保留にした件数 ÷ 評価が済んだ件数 | `eval --import` のレポート |
| 検出率(全体) | 同じ割合を、全種類で | 保留にした誤りのある例 ÷ 評価が済んだ誤りのある例 | 同上 |
| 見落とし率 | 誤りのある例を、合格にした割合 | 1 − 検出率(全体) | 同上 |
| 誤検出率 | 誤りのない対照を、保留か不採用にした割合 | 保留にした対照 ÷ 評価が済んだ対照 | 同上 |
| 不採用率(段階ごと) | その段階に進んだものを、保留か不採用にした割合 | 再導出・解説の確認のそれぞれで 保留にした件数 ÷ その段階に進んだ件数 | 同上 |

- 評価が済んだ = 最終の判定(合格・保留)が出たもの。**止めたもの**(出力の形が違い、上限に達した)と**途中のもの**は、分母に入れず、件数として別に出します。
- 止めたものと途中のものが 1 件でもあると、目標は「満たした」になりません(分母には入れませんが、評価が終わっていないため)。
- 分母が 0 の指標(誤りが 0 件の種類など)は、割合を `null` にします(0 除算にしない)。`null` の項目は「測れなかった」として、目標を満たしたとはしません。
- 件数・ID・種類・割合だけを持ち、問題の本文・選択肢・出典の本文を含めません。
- 検証の段階は、解説の確認の指摘が先にあっても、再導出の保留で止まります。そのため、解説の確認の不採用率は、再導出を通ったものに対する割合です。

## 4. 目標

目標は、設定の `eval.targets` に持ちます(`pipeline.config.json`)。

| 指標 | 目標 |
| --- | --- |
| 検出率(全体) | 90% 以上(`detectionOverall`) |
| 検出率(種類ごと) | どの種類も 80% 以上(`detectionPerKind`) |
| 誤検出率 | 20% 以下(`falsePositiveMax`) |

不採用率は目標を持たず、段階ごとの目安として見ます(極端に高い・低い段階は、原因を調べます)。

- **下回ったとき**: レポートの `belowTarget` に項目が出ます。原因(どの種類を見逃したか、何を誤検出したか)を調べ、検証役の指示かモデルの変更を取り入れません(変更の前の定義とモデルに戻します)。
- **測れなかったとき**: `unmeasured` に項目が出ます。評価用のデータを増やします。
  - 評価用のデータ(`dataset.json`)は、**あれば作り直しません**。承認した下書きを増やしたり、`eval.perKind` や `eval.seed` を変えたりしても、`pipeline-work/eval/<コード>/` の `dataset.json` を消して(`results.json`・`state.json`・`requests/`・`out/` も消す)から `eval` を実行しないと、反映されません。
  - 件数は、承認した下書きの数が上限です(対照と誤りのある例を同数にそろえるため)。`eval.perKind` を上げても、承認した下書きの数を超えては増えません。種類ごとの件数が少ないと、種類ごとの検出率は 0% か 100% になりやすいので、承認した下書きを増やします。
- 目標を満たしたかは、レポートの `meetsTargets` に出ます。人の確認を抜き取りに切り替える条件も、この値を使います([問題を作る手順書](./question-production.md)の「8.1 抜き取りで確認する」)。検証役の定義を変えると、レポートのハッシュが合わなくなり、評価をやり直すまで全件の確認へ戻ります。
- **見直す周期と手順**: 検証役の定義(指示かモデル)を変えるたびに評価を流し、結果を見て目標を見直します。変更がなくても、版ごとの締めで、直近のレポートを見て、目標が厳しすぎる・緩すぎるかを確かめます。目標を変えるときは、設定の `eval.targets` を直す通常の PR で、理由を添えます。

## 5. レポート

`report.json`(機械が読む形)と `report.md`(人が読む要約)に、次を載せます。

- 検証役の役の名前、モデルの ID、定義のハッシュ(どの検証役で測ったか)
- 評価用のデータのハッシュ、種、件数(どのデータで測ったか)
- 実行日
- 件数(対照、誤りのある例、評価が済んだもの、途中、止めたもの)
- 指標と目標、下回った項目、測れなかった項目

本文は含みません。同じデータで、検証役の定義やモデルを変えて測り直し、レポートを比べます(定義のハッシュとモデルの ID が、比べる軸です)。
