# 資格を追加する手順

新しい資格を、問題集に加える手順です。データの形と検査の規則は [問題データの仕様](./data-spec.md) が正本で、この文書は、その順番と置き場所をまとめます。
アプリのコードは変えません(資格マスタと `data/` のファイルだけで、一覧・モード選択・出題・結果の画面ができます)。

## 1. 決めること

| 項目 | 決め方 |
| --- | --- |
| 資格コード(`examCode`) | 英大文字で始まる英大文字と数字(2〜16 文字)。ほかの資格と重ならないもの。ファイル名と URL(`/exams/<資格コード>`)に使います |
| 公開の状態(`status`) | 問題がそろうまでは `coming-soon`(一覧に「近日公開」と出すだけ)。出題できるようになったら `published` |
| 分野(`domains`) | `domain1`〜`domainN` のコードと表示名、公式の配点の重み(合計 1) |
| 本番モードの値 | `officialQuestionCount`(出題数)と `officialTimeMinutes`(制限時間の分)。公式の試験に合わせます |
| レベルと略称(任意) | `level`(`Foundational`・`Associate`・`Professional`・`Expert`・`Specialty`)は、公式にレベルの区分があるときだけ。`abbr` は、一覧のタイルに出す英数字 1〜4 文字 |
| 資格の情報(任意) | 受験料、出題形式、言語、有効期間、公式の試験ガイドの URL を、情報ページに出せます(`info`)。公式の情報だけに基づけ、載っていない項目は持たず、確認した日(`checkedAt`)を書きます |
| 出典のドメイン | 出典(`references`)に使う、その資格のベンダーの公式ドキュメントのホスト名。ほかの学習サイトや講座のサービスなどは使いません |

## 2. ファイルの命名と配置

すべて、リポジトリ直下の `data/` に置きます。`<コード>` は、試験コードを英小文字にしたものです(例: 試験コード `AWS-AIB-C01` なら `aws-aib-c01`)。試験コードの形は、仕様の「試験コード」を見てください。

| ファイル | 内容 | 必要なとき |
| --- | --- | --- |
| `data/exams.json` | 資格マスタ。資格ごとに 1 件を足します | 常に |
| `data/questions.<コード>.json` | 問題 | `published` のとき必須。`coming-soon` のときは置きません |
| `data/curriculum.<コード>.json` | 学習モードの単元と本文 | 任意。ないと、学習モードは「準備中です」になります |

- ファイル名のコードと、ファイルの中の `examCode` は一致させます。
- 問題の ID は `<問題 ID の接頭辞>-<4 桁の連番>`(例: `SAMPLE-0001`)です。接頭辞は、資格マスタの `idPrefix` に書き、資格どうしで重複させません。一度使った番号は、問題を消しても再利用しません。
- ベンダーを新しく足すときは、`data/vendors.json` に、名前と略称を足します。

## 3. 手順

1. **近日公開として載せる**(任意)。`data/exams.json` の `exams` に、`examCode`(`<ベンダー略称>-<試験略称>-<版>`。版がなければ `XX`)・`status: "coming-soon"`・`vendor`・`name`・`shortName`(と任意の `note`)だけの 1 件を足します。
2. **出典のドメインを足す**(出典を付けるとき)。`scripts/lib/exam-data/schema.ts` の `ALLOWED_REFERENCE_HOSTS` に、その資格のベンダーの公式ドキュメントのホスト名(完全一致)を足し、仕様の「3.1 出典」の表にも足します。すでにあれば、足しません。
3. **問題を書く**。`data/questions.<コード>.json` を作り、[問題データの仕様](./data-spec.md) の「3. 問題」の形で書きます。
   選択式(択一・複数選択)の問題数は、本番モードの出題数(`officialQuestionCount`)以上にします(自由記述は数えません)。
   出典の URL は `references` に書き、本文には書きません。
4. **公開にする**。資格マスタの 1 件を `status: "published"` にし、`edition`・`category`・`passingScore`・`totalScore`・
   `officialQuestionCount`・`officialTimeMinutes`・`domains`・`idPrefix` を足します。公式の情報があれば、`level`・`abbr`・`info` も足します
   (`info.guideUrl` のドメインも、手順 2 の許可の一覧に足します)。
5. **カリキュラムを書く**(任意)。`data/curriculum.<コード>.json` を、仕様の「11. カリキュラムのデータ」の形で作ります。
6. **検査する**。次の「4. 検査」を通します。
7. **画面で確かめる**。`npm run dev` で、資格の一覧、モード選択、通常出題と本番モード、結果の画面を開きます。
8. **リリースノートに書く**。`data/release-notes.json` の、その版のエントリに、加えた資格を書きます。

## 4. 検査

```sh
npm run validate:data   # 資格マスタ・問題・カリキュラム・使い方ページの検査
npm run build           # 公開中の資格のページが、ファイルから作れること
npm test
```

`validate:data` は、次のような食い違いを見つけます(規則の一覧は、仕様の「4. 機械検査する規則」)。

- 公開中の資格に問題のファイルがない。資格マスタにない資格の問題やカリキュラムがある
- ファイル名のコードと、中の `examCode` が違う
- 問題の分野のコードが、資格マスタの分野にない
- 選択式の問題数が、本番モードの出題数より少ない
- 問題の ID の重複、接頭辞の誤り、正解のキーの誤り
- 問題・カリキュラム・資格マスタの本文に、URL(`http://`・`https://`・`www.`)がある
- 出典の URL が `https` でない、ユーザー情報やポートを持つ、許すドメインの一覧にない

報告には、ファイル名・項目の位置・問題の ID と規則の種類だけが出ます(本文は出ません)。

## 5. 注意

- 実データの扱いは、加えるときに、そのつど決めます(仕様の「9. サンプルデータ」)。
- 資格マスタの値(合格点、問題数、制限時間、分野の重み)を変えたときも、同じ検査を通します。
